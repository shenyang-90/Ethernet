1. 协议概述

IEEE 802.1AS-2020 定义了 gPTP (generalized Precision Time Protocol)，用于在 IEEE 802 网络中实现亚微秒级的时间同步。它是 IEEE 1588-2019 PTP 的一个 profile，但针对桥接网络做了大量简化和特化。

核心功能：通过 Sync/Follow_Up 消息传播 Grandmaster 时间，通过 Pdelay 消息测量链路延迟，全网达到纳秒级时间同步。

1.1 gPTP vs PTP (IEEE 1588) 的关键差异

特性gPTP (802.1AS)PTP (1588-2019)
传输层仅 L2 (MAC)L2 / L3 / L4
时钟类型PTP End Instance / PTP Relay InstanceOC / BC / E2E-TC / P2P-TC
延迟机制仅 P2P (peer-to-peer)E2E 或 P2P
步进模式默认 Two-Step，可选 One-Step依赖 Profile
syntonization 强制 (NeighborRateRatio)可选
非 PTP 中继不允许允许

2. gPTP Domain 与概念

2.1 Domain

  • 一个 Domain 包含一个或多个 PTP Instance 和链路
  • Domain 编号范围：0 ~ 127
  • 必须支持 domain 0
  • 每个 Domain 独立运行 BMCA 和时间同步
  • sdoId = majorSdoId(4bit=0x1) + minorSdoId(8bit=0x00)

2.2 PTP Instance 类型

类型功能
PTP End Instance端系统，对应 1588 的 Ordinary Clock。可作为 Grandmaster 或 Slave
PTP Relay Instance中继系统，对应 1588 的 Boundary Clock。转发 Sync、执行 BMCA、有 Port State

2.3 关键术语

术语说明
Grandmaster PTP InstanceDomain 中时间源，所有其他节点同步到它
LocalClock本地自由运行时钟 (oscillator)
ClockMaster向其他端口发送 Sync 的实体
ClockSlave接收 Sync 并同步本地时间的实体
SiteSyncPTP Instance 内部协调多个 PortSync 的实体
PortSync每个 PTP Port 对应的同步实体
residence time帧在 Bridge 内部的驻留时间
meanLinkDelay链路平均传播延迟
neighborRateRatio相邻节点 LocalClock 频率比

2.4 Timescale

类型说明
PTP基于 TAI 秒，连续，epoch 为 PTP epoch。domain 0 必须用这个
ARB (Arbitrary)基于域启动时间，可由管理设置，可有不连续

3. BMC (Best Master Clock) 算法

3.1 算法目标

在每个 PTP Instance 上运行，比较各端口收到的 Announce 消息，选出最优的 Grandmaster，并确定每个端口的状态 (MasterPort / SlavePort / PassivePort / DisabledPort)。

3.2 比较优先级 (从高到低)

  1. priority1 (UInteger8)：管理配置，越小越好。非 GM-capable 必须为 255
  2. clockClass：时钟等级，如 6=GM locked to GPS, 7=GM holdover, 52=Slave, 255=not GM-capable
  3. clockAccuracy：时钟精度枚举
  4. offsetScaledLogVariance：时钟稳定性
  5. priority2 (UInteger8)：次优先级，管理配置
  6. clockIdentity：MAC 地址派生的唯一标识，字典序比较

3.3 priority1 默认值

设备类型priority1
网络中心设备 (Bridge/AP/GM-capable 端节点)246
可关闭的端节点 (PC/电视/音箱)248
非 GM-capable 端节点255

3.4 Port State

状态说明
MasterPort向下游发送 Sync
SlavePort从上游接收 Sync
PassivePort不参与同步，备用路径
DisabledPort禁用
gPTP 要求 BMCA 为默认模式，但支持 externalPortConfiguration (外部端口配置)。在 TSN 集中管理网络中，可由控制器直接配置端口状态，跳过 BMCA。

4. PTP 消息类型与格式

4.1 消息类型

消息类型值事件/通用说明
Sync0x0事件时间同步事件消息
Pdelay_Req0x2事件请求测量对端延迟
Pdelay_Resp0x3事件对端延迟响应
Follow_Up0x8通用携带 preciseOriginTimestamp
Pdelay_Resp_Follow_Up0xA通用携带 responseOriginTimestamp
Announce0xB通用BMC 用，携带时钟质量信息
Signaling0xC通用信令消息 (间隔请求等)

4.2 通用消息头 (34 bytes)

字段长度说明
majorSdoId4 bits= 0x1 (gPTP)
messageType4 bits消息类型
minorVersionPTP4 bitsPTP 次版本
versionPTP4 bitsPTP 主版本 = 2
messageLength2 bytes消息总长度
domainNumber1 byte域编号
minorSdoId1 byte= 0x00
flags2 bytes标志位 (twoStepFlag, ptpTimescale...)
correctionField8 bytes修正域 (ns + fraction, 2^16 = 1ns)
messageTypeSpecific4 bytes类型特定
sourcePortIdentity10 bytesclockIdentity(8) + portNumber(2)
sequenceId2 bytes序列号
controlField1 byte保留
logMessageInterval1 byte消息间隔的对数值 (base 2)

4.3 目的 MAC 地址

消息目的 MAC
Sync, Follow_Up, Pdelay_Req, Pdelay_Resp, Pdelay_Resp_Follow_Up01-80-C2-00-00-0E
Announce, Signaling01-80-C2-00-00-0E

EtherType: 0x88F7

4.4 Sync 消息体 (Two-Step)

字段长度说明
originTimestamp (seconds)6 bytes10^9 比例秒
originTimestamp (nanoseconds)4 bytes纳秒部分

注：Two-Step 模式下，Sync 的 originTimestamp 通常不全用，精确时间在 Follow_Up 中传递。

4.5 Follow_Up 消息体 + TLV

字段长度说明
preciseOriginTimestamp10 bytes精确原始时间
Follow_Up information TLV28 bytes包含 rateRatio, gmTimeBaseIndicator, lastGmPhaseChange, lastGmFreqChange

RTL 设计提示：消息解析

  • 硬解析：PTP 消息头 34 bytes 固定格式，可用状态机逐字节解析
  • correctionField：64-bit 有符号定点数，高 48-bit 为 ns，低 16-bit 为 1/65536 ns。需要 96-bit 精度算术
  • sequenceId：Sync 和 Follow_Up 共享 sequenceId，需成对匹配
  • Two-Step vs One-Step：Two-Step 需缓存 Sync 的接收时间戳，等 Follow_Up 到达后一起处理

5. Peer-to-Peer Delay 测量

5.1 Pdelay 消息交互

Initiator (本端)                          Responder (对端)
    |                                          |
    |---- Pdelay_Req (t1) -------------------->|
    |<--- Pdelay_Resp (t2, t3) ---------------|
    |<--- Pdelay_Resp_Follow_Up (t3 precise) --|
    |                                          |

 timestamps:
 t1 = Pdelay_Req 发送时间 (initiator egress)
 t2 = Pdelay_Req 接收时间 (responder ingress)
 t3 = Pdelay_Resp 发送时间 (responder egress)
 t4 = Pdelay_Resp 接收时间 (initiator ingress)

5.2 计算公式

meanLinkDelay = [ r * (t4 - t1) - (t3 - t2) ] / 2

其中:
  r = neighborRateRatio (对端频率 / 本端频率)
  t1 = pdelayReqEventEgressTimestamp
  t2 = requestReceiptTimestamp (from Pdelay_Resp)
  t3 = responseOriginTimestamp (from Pdelay_Resp_Follow_Up)
  t4 = pdelayRespEventIngressTimestamp

5.3 neighborRateRatio 计算

neighborRateRatio = (responder_time_N - responder_time_0) / (initiator_time_N - initiator_time_0)

使用多组 Pdelay 测量结果做线性回归或差分估计
neighborRateRatio 精度要求：误差 < 200 ppm。这意味着频率差检测要达到 0.02% 精度。

5.4 关键阈值

链路类型meanLinkDelayThresh
IEEE 802.3 (1G/10G/100G)800 ns (电口典型 ~400ns)
IEEE 802.11较大 (无线环境)
IEEE 802.3 EPON根据距离计算

6. Sync / Follow_Up 时间同步

6.1 Two-Step 同步流程

Grandmaster                              Relay/Slave
    |                                         |
    |---- Sync (t1_GM) ---------------------->|
    |         (t2_RX = ingress timestamp)     |
    |                                         |
    |---- Follow_Up (t1_precise) ----------->|
    |     + correctionField                   |
    |     + rateRatio                         |
    |                                         |
    // Slave 计算:
    masterTime = t1_precise + correctionField
    slaveTime  = t2_RX - meanLinkDelay / rateRatio
    offset     = masterTime - slaveTime

6.2 correctionField 累积

每经过一个 Relay Instance，correctionField 增加：

correctionField_new = correctionField_old
                    + residence_time * rateRatio
                    + meanLinkDelay * rateRatio
                    + delayAsymmetry

6.3 Sync 超时

  • syncReceiptTimeoutTime = 3 * syncInterval (默认)
  • 若在超时前未收到下一个 Sync，标记 sync receipt timeout，Slave 进入 HOLDover

7. 状态机总览

7.1 时间同步状态机 (Media-Independent)

状态机功能
SiteSyncSync协调各 PortSync 的同步信息，选择最优 Slave 端口
PortSyncSyncReceive处理从 MD 层接收的 MDSyncReceive
ClockMasterSyncSendGM 定期发送 Sync
ClockMasterSyncOffsetGM 计算时间偏移
ClockMasterSyncReceiveGM 接收外部时钟源信息
PortSyncSyncSendMaster 端口发送 MDSyncSend 到 MD 层
ClockSlaveSyncSlave 计算并应用时间偏移

7.2 BMC 状态机

状态机功能
PortAnnounceReceive接收并校验 Announce 消息
PortAnnounceInformation维护端口接收的时钟数据集
PortStateSelection执行数据集比较，选择最优 GM
PortAnnounceTransmit发送 Announce 消息

7.3 MD 层状态机 (Media-Dependent)

状态机功能
MDSyncReceiveSM接收 Sync/Follow_Up，计算 upstreamTxTime
MDSyncSendSM发送 Sync/Follow_Up，打时间戳
MDPdelayReq发送 Pdelay_Req，计算 meanLinkDelay 和 neighborRateRatio
MDPdelayResp响应 Pdelay_Req，发送 Pdelay_Resp/Follow_Up
LinkDelayIntervalSetting控制 Pdelay 消息间隔

RTL 设计提示：状态机实现

  • 并行度：每 domain、每 port 有独立状态机实例。多域系统需大量并行状态机
  • 事件驱动：状态机由消息接收事件 (rcvdSync, rcvdFollowUp) 和定时器事件驱动
  • 全局变量：SiteSync 相关的变量是 per-domain 全局的，需注意多端口访问的原子性
  • 简化：固定 GM + 固定 Slave 的网络可关闭 BMCA，大幅简化逻辑

8. 时间戳与硬件要求

8.1 时间戳点

时间戳测量平面 (timestamp measurement plane) 位于 MAC 与 PHY 之间。实际在 RTL 中：

  • Egress timestamp：帧的最后一个字节离开 MAC 的时刻 (或 SFD 发出时刻)
  • Ingress timestamp：帧的 SFD 到达 MAC 的时刻

8.2 LocalClock 要求

参数要求
频率典型 25MHz / 125MHz / 156.25MHz 参考，需分频/倍频到高精度
分辨率至少 1ns (1GHz 计数器)
精度TDEV < 4ns @ tau=1s (B.1 要求)
频率稳定度< ±100 ppm (通常 < ±50 ppm)

8.3 Timestamp 格式

Timestamp {
  seconds:      48-bit (10^9 比例，即 48-bit 可表示约 8.9 年)
  nanoseconds:  32-bit (0 ~ 999,999,999)
}

UScaledNs {
  seconds:      48-bit
  nanoseconds:  32-bit
  fraction:     16-bit (1/65536 ns)
}
关键 RTL 约束：时间戳必须来自硬件计数器，直接在 MAC 的 SFD 检测点采样。软件读取时间戳会引入不可接受的抖动 (us 级)。

9. CMLDS (Common Mean Link Delay Service)

9.1 概念

CMLDS 是 802.1AS-2020 新增特性，允许多个 domain 共享同一套链路延迟测量结果：

  • 每端口的 MDPdelayReq/Resp 状态机运行一次，与 domain 无关
  • asCapableAcrossDomains 是所有 domain 共享的布尔变量
  • 各 domain 的 MDSyncReceiveSM 使用相同的 meanLinkDelay 和 neighborRateRatio

9.2 CMLDS 与 instance-specific Pdelay 的差异

特性CMLDSInstance-specific
Domain 相关性无关，所有 domain 共享每个 domain 独立
correctionField包含 -delayAsymmetry不包含 delayAsymmetry
适用场景多域 TSN 网络单域或需要独立测量

10. RTL 设计要点

10.1 顶层模块划分

gptp_top
├── local_clock_counter       // 64-bit ns + 16-bit fraction 自由运行计数器
├── timestamp_unit            // 每端口 ingress/egress 时间戳捕获
├── rx_msg_parser             // PTP 消息解析 (0x88F7 DA)
├── tx_msg_builder            // PTP 消息组装
├── bmc_engine                // BMC 数据集比较、端口状态选择
├── sync_sync_engine          // SiteSync / PortSyncSync 状态机
├── clock_slave_sync          // 时间偏移计算 + 时钟调整
├── clock_master_send         // GM Sync/Follow_Up 发送
├── md_sync_receive           // MDSyncReceiveSM (two-step sync rx)
├── md_sync_send              // MDSyncSendSM (two-step sync tx)
├── md_pdelay_req             // MDPdelayReq 状态机
├── md_pdelay_resp            // MDPdelayResp 状态机
├── cmlds_controller          // CMLDS 共享变量管理
├── interval_timers           // Sync/Pdelay/Announce 间隔定时器
└── config_registers          // 数据集、优先级、域配置

10.2 关键计算

计算精度要求硬件实现
meanLinkDelay< 1ns64-bit 有符号整数除法
neighborRateRatio< 200ppm定点除法或线性回归
correctionField1/65536 ns96-bit 定点加法
offsetFromMaster< 1ns64-bit 减法 + 滤波器
rateRatio< 10ppmPI 控制器或锁相环

10.3 定点运算建议

  • 时间：48-bit seconds + 32-bit ns + 16-bit fraction = 96-bit UScaledNs
  • rateRatio：32.32 定点 (1.0 = 0x1_0000_0000)
  • 频率偏移：使用 PI 控制器输出调整本地时钟分频比
  • 除法：meanLinkDelay / 2 可用右移；复杂除法用迭代法或查表

10.4 时钟调整输出

Slave 需要调整本地时钟频率/相位以跟踪 Grandmaster：

方法说明
软件调整 (NTP-like)周期性地 slew 系统时钟，精度 ~ms
硬件 PLL/DPLL用 offset/rateRatio 控制硬件锁相环，精度 ~ns
PTP Hardware Clock (PHC)独立硬件时钟，通过 addend register 微调频率

RTL 设计提示：时钟同步硬核

  • 时间戳捕获：必须在 MAC 层用自由运行计数器打戳，使用格雷码或双缓冲传递给时钟域
  • Sync 处理延迟：Two-Step 模式下，从收到 Sync 到收到 Follow_Up 之间需缓存时间戳。Follow_Up 超时 (如 1s) 需清缓存
  • 多域支持：每个 domain 独立的 Sync 序列、BMC 状态、时钟数据集。domain 0 必须存在
  • Announce 间隔：默认 1s (logInterval=0)，Sync 默认 125ms (logInterval=-3)
  • 面积优化：固定拓扑网络可关闭 BMCA，直接静态配置 Master/Slave 端口

10.5 性能指标

  • 同步精度：端到端 < 1us (通常 < 100ns 在有线网络)
  • 收敛时间：BMCA 收敛 < 5s；频率锁定 < 30s
  • 消息速率：Sync 125ms / Pdelay 125ms / Announce 1s (默认)
  • 带宽开销：极低，< 0.1% 的链路带宽
最小可裁剪实现：单 domain (domain 0) + 固定 GM/Slave 配置 + Two-Step + 有线以太网 Pdelay + 无 CMLDS。关闭 BMCA，直接静态配置端口状态。覆盖大多数车载/工业 TSN 场景。
