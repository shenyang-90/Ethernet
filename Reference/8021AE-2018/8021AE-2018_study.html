1. 协议概述

IEEE 802.1AE-2018 定义了 MAC Security (MACsec)，在 MAC 层提供数据机密性、数据完整性、数据源认证和重放保护。MACsec 在两个直接相连的 peer 之间操作（ hop-by-hop 安全）。

核心功能：对以太网帧进行认证加密 (AEAD)，在帧中插入 SecTAG，接收端验证后解密/递送。

1.1 协议范围

功能说明
Confidentiality加密用户数据，防止窃听
Integrity完整性校验 (ICV)，防止篡改
Data Origin Authenticity源认证 (基于共享密钥)
Replay Protection基于 PN 的防重放机制
Hop-by-hop Security逐跳安全，每跳独立加解密
MACsec 是 hop-by-hop 安全，不是 end-to-end。中间 Bridge 必须解密再重新加密（若该 Bridge 也支持 MACsec）。

2. SecTAG 格式

2.1 SecTAG 结构

字段长度说明
MACsec EtherType2 bytes0x88E5
TCI1 byteTag Control Information (V|E|C|SC|ES|SCB|C)
AN (Association Number)1/2 nibble4-bit SA 编号 (与 SCI 一起标识 SA)
SL (Short Length)1 byteUser Data 长度 (若 < 48 bytes)
PN (Packet Number)4 bytesPN 低 32 位 (扩展 PN 时高 32 位由算法恢复)
SCI (optional)8 bytesSecure Channel Identifier，条件性携带

2.2 TCI 位定义

位名称说明
8V (Version)协议版本，当前 = 0
7ES (End Station)SCI 由 SMAC + 默认 PortID 推导
6SC (SC present)SecTAG 中显式携带 SCI
5SCB (Single Copy Broadcast)EPON SCB 专用
4E (Encryption)E=1 且 C=1：加密+完整性；E=0 且 C=0：仅完整性
3C (Changed Text)C=0：Secure Data = User Data (仅完整性且 ICV=16B)

2.3 SCI 编码规则

条件SC bitES bitSCI 来源
alwaysIncludeSCI=True10显式编码
transmit SCs > 110显式编码
useES=True, 单 SC01SMAC + PortID=0x0001
useSCB=True00SCB 模式，PortID=0x0000
默认单 SC00KaY 配置的默认 SCI

RTL 设计提示：SecTAG 处理

  • 位置：SecTAG 紧跟在 SMAC 之后（若帧无 VLAN tag），或在 VLAN tag 之后
  • 解析顺序：EtherType 0x88E5 → 读取 TCI → 提取 AN/PN → 条件读取 SCI
  • AN 提取：TCI+AN 共 2 bytes，AN 在低 4 bits
  • 长度变化：加密封装后帧长增加 SecTAG(6/14B) + ICV(8/16B)

3. SCI / SA / SC / PN

3.1 关键术语

术语定义
SecYMAC Security Entity，执行加解密的核心实体
CA (Connectivity Association)两个 peer SecY 之间的安全关联
SC (Secure Channel)单向安全通道，每个 CA 有两个 SC (Tx/Rx)
SCI (SC Identifier)64-bit = SMAC(48) + Port Identifier(16)
SA (Secure Association)SC 的时序分量，对应一个 SAK 和一组 PN
AN (Association Number)4-bit，标识 SC 内的不同 SA
PN (Packet Number)32-bit 或 64-bit，每帧递增，用于 IV 和重放保护
SAK (SA Key)用于保护帧的对称密钥

3.2 SC / SA 关系

CA (两个 SecY 之间)
├── Transmit SC (本端发送)
│   ├── SA[AN=0] : SAK_A, PN=0..N
│   ├── SA[AN=1] : SAK_B, PN=0..N  (密钥更新时切换)
│   └── encodingSA : 当前用于发送的 SA
└── Receive SC (对端发送)
    ├── SA[AN=0] : SAK_A
    ├── SA[AN=1] : SAK_B
    └── lowestAcceptablePN : 重放保护窗口下界

3.3 PN 管理

  • 发送：每帧使用 nextPN，发送后 nextPN++
  • nextPN 回绕到 0 (或 2^32/2^64) 时，MAC_Operational → False，停止发送
  • 接收：从 SecTAG 提取 PN，进行重放检查
  • 扩展 PN (64-bit)：SecTAG 只传低 32 位，高 32 位由接收算法恢复

5. Secure Frame Generation (发送)

5.1 发送流程

  1. SA 分配：选择 encodingSA 对应的 SA (当前活动的 transmit SA)
  2. PN 分配：使用 SA 的 nextPN 作为本帧 PN，然后 nextPN++
  3. SecTAG 编码：根据 TCI/AN/PN/SCI 规则生成 SecTAG
  4. 加密保护：调用 Cipher Suite，输入 {SAK, SCI, PN, SecTAG, User Data} → 输出 {Secure Data, ICV}
  5. 组装发送：DA | SA | SecTAG | Secure Data | ICV → Common Port

5.2 Traffic Class Table (可选)

若实现 Traffic Class Table，可根据用户优先级 (0~7) 选择不同的 transmit SC（最多 8 个），实现不同优先级的独立 PN 空间。

若 protectFrames=False，SecY 透传帧，仅递增 OutPktsUntagged 计数器。

6. Secure Frame Verification (接收)

6.1 接收流程

  1. SecTAG 检测：检查用户数据是否以 0x88E5 开头
  2. SecTAG 解码：提取 TCI/AN/PN/SCI
  3. SA 定位：根据 SCI + AN 查找 receive SA
    • 无 SCI 时，使用 KaY 配置的默认 peer SCI
    • 找不到 SA 时：Strict/C-bit 置位则丢弃，否则透传 (InPktsNoSA)
  4. PN 恢复与重放预检：恢复完整 PN，若 replayProtect 使能且 PN < lowestAcceptablePN，丢弃 (InPktsLate)
  5. 密码学验证：调用 Cipher Suite 验证/解密 → 返回 VALID/INVALID
  6. 重放检查更新：若 VALID，更新 nextPN 和 lowestAcceptablePN
  7. 递送：VALID 帧递送到 Controlled Port；INVALID 帧根据 validateFrames 配置决定丢弃或透传

6.2 validateFrames 模式

模式无 Tag 帧Invalid Tag 帧Valid Tag 帧
Strict丢弃丢弃解密递送
Check透传透传解密递送
Disabled透传透传 (不解密)不解密透传
Null透传透传透传 (SecY 不生效)

7. Replay Protection

7.1 机制

  • 每个 receive SA 维护 lowestAcceptablePN
  • 接收帧的 PN < lowestAcceptablePN → 丢弃 (重放包)
  • 验证通过的有效帧更新：nextPN = PN + 1；lowestAcceptablePN = max(原值, nextPN - replayWindow)

7.2 replayWindow

Cipher Suite最大 replayWindow
标准 PN (32-bit)2^32 - 1
扩展 PN (64-bit)2^30 - 1
默认 replayWindow = 0（严格按序）。在存在 QoS 重排序的网络中，可适当增大窗口。

7.3 扩展 PN 恢复算法

SecTAG 只传 32-bit PN，接收端恢复 64-bit PN：

// 假设高 32 位与 lowestAcceptablePN 相同
high_32 = lowestAcceptablePN[63:32];
if (lowestAcceptablePN[31] == 1 && received_PN[31] == 0)
    high_32 = high_32 + 1;  // 低 32 位回绕
full_PN = {high_32, received_PN};
该恢复算法在丢失超过 2^31 个连续帧时可能失效，此时需 MKA 重新同步高 32 位。

8.2 IV (Nonce) 构造

IV = SCI(64-bit) || PN(32/64-bit)  // 按 Cipher Suite 定义
// 对于默认 Cipher Suite (GCM-AES-128):
// IV = SCI || PN (32-bit) = 96-bit

8.3 GCM 操作

输入说明
Key (SAK)128/256 bit
IV96 bit (SCI+PN)
PlaintextUser Data
AADDA || SA || SecTAG (TCI+AN+SL+PN，不含 EtherType)

输出：Ciphertext (Secure Data) + Auth Tag (ICV)

RTL 设计提示：Cipher Engine

  • AES-GCM 加速：必须硬件加速 (AES core + GHASH)。纯软件无法满足 1G+ 线速
  • Key 管理：SAK 存储在专用安全内存/OTP，禁止软件直接读取
  • IV 生成：IV = SCI || PN，硬件自动拼接
  • AAD 构造：DA(6) + SA(6) + SecTAG(6/14) = 18/26 bytes，注意不包含 EtherType
  • 流水线：GCM 加密有 10~14 轮 AES，需要深度流水线或多通道并行以满足线速
  • 吞吐量：10G 线速最小帧 64B @ 14.88Mpps，每帧 GCM 需处理 ~80 bytes。AES-GCM @ 500MHz 约可满足 10G

9. Key Agreement (MKA) 概述

MACsec 自身不定义密钥分发协议，依赖 IEEE 802.1X MKA (MACsec Key Agreement)：

  • 基于 802.1X EAPOL 帧交换密钥参数
  • 生成/分发 SAK (Secure Association Key)
  • 管理 SCI、AN、PN 空间
  • 支持密钥更新 (Key Rotation) 和重认证
RTL 实现中，MKA 通常由嵌入式 CPU/软件处理，SecY 通过 LMI (Local Management Interface) 接收配置。

11. RTL 设计要点

11.1 顶层模块划分

macsec_top
├── rx_parser               // 检测 0x88E5，提取 SecTAG/AN/PN/SCI
├── rx_sa_manager           // SCI+AN → SA 查表，获取 SAK
├── rx_pn_replay_check      // PN 恢复、重放窗口检查
├── rx_crypto_engine        // AES-GCM 解密/验证
├── rx_validate_ctrl        // validateFrames 模式处理
├── tx_sa_manager           // encodingSA 选择，获取 SAK/nextPN
├── tx_pn_alloc             // nextPN 分配、回绕检测
├── tx_sectag_gen           // SecTAG 组装
├── tx_crypto_engine        // AES-GCM 加密
├── tx_protect_ctrl         // protectFrames 控制
├── secy_management         // LMI、计数器、配置寄存器
└── key_store_secure        // SAK 安全存储 (仅硬件可访问)

11.2 关键设计决策

决策点选项 A选项 B
Cipher SuiteGCM-AES-128 (面积小)GCM-AES-256 (安全性高)
扩展 PN32-bit (兼容性好)64-bit XPN (高速链路防回绕)
并发通道单通道 (面积小)多通道并行 (高吞吐)
SA 数量4 Rx + 1 Tx (最小)32+ Rx + 8 Tx (多 peer)
replayWindow0 (严格)2^16 (允许重排序)

11.3 性能指标

  • 线速：加密/解密不能造成背压丢包
  • 延迟：GCM 加解密引入的延迟，10G 场景约 1~2us
  • PN 回绕：32-bit PN @ 10G 最小帧约 8.5 分钟回绕，需 MKA 及时更新密钥
  • 密钥更新：支持在线密钥切换 (encodingSA 切换，不中断流量)
最小可裁剪实现：单 SA (AN=0) + GCM-AES-128 + 32-bit PN + Strict 验证 + 无 Traffic Class Table。覆盖端到端 MACsec 最基本场景。
