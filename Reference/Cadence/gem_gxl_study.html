1. 概述与 Part Number

Cadence GEM GXL 是一个完整的千兆以太网 MAC IP，面向 automotive、TSN 和通用 SoC。其 RTL 位于 hdl/hdl_src/，共约 155 个 Verilog 源文件。主要交付物包括：

交付物路径说明
RTL 源码hdl/hdl_src/~155 个 .v 文件，含 MAC、DMA、PCS、TSU、MMSL、寄存器、安全机制
用户指南doc/cdn_eth_ip7014A_user_guide_v1.0.pdf727 页主参考手册，含寄存器、DMA、TSN、汽车安全
集成指南doc/cdn_eth_IP701x_integration_guide_v1.0.pdfSoC 集成、时钟复位、AXI/AHB、RGMII/RMII/PCS
安全手册doc/cdn_eth_IP701xA_r1p12_safety_manual_v1.1.pdfISO 26262 安全目标、ASIL 假设、安全机制
软件驱动software/core_driver/C 驱动 + 寄存器头文件 emac_regs.h
验证环境func_ver/UVM demo TB + legacy Verilog/SV TB + SVA + coverage
DFT/STA/UPFdft/, sta/, pwr_intent/扫描、时序约束、CPF/UPF 低功耗意图
关键认知: Cadence GEM GXL 是“单端口千兆 MAC + 可选 DMA/PCS/TSU/TSN”的成熟参考。它不包含多端口 L2/L3 Switch，也没有 vPHC 虚拟化。当前项目若定义 4-port Switch + 8 MAC + vPHC，则范围远超此参考 IP。

6. DMA 描述符与数据流

6.1 描述符格式

GEM 使用独立的 TX/RX 描述符环。每个描述符字 32-bit，宽度取决于地址模式和扩展 BD 模式：

地址模式Extended BD每 BD 字数总宽度
32-bitNo264 bit
64-bitNo4128 bit
32-bitYes4128 bit
64-bitYes6192 bit

RX Buffer Descriptor (Word 0 / Word 1)

Word 0  [31:3]  Buffer start address [31:3]
        [2]     Address[2] OR timestamp-valid (extended mode)
        [1]     Wrap
        [0]     Ownership: 0=SW/free, 1=GEM used

Word 1  [31]    Broadcast
        [30]    Multicast hash match
        [29]    Unicast hash match
        [28]    External address match
        [27]    Specific address match
        [26:25] Specific address register number
        [24:22] Type-ID match OR RX checksum-offload status
        [21]    VLAN tag
        [20]    Priority tag
        [19:17] VLAN priority
        [16]    Header buffer flag / FCS error / CFI
        [15]    End of frame (EOF)
        [14]    Start of frame (SOF)
        [13]    Jumbo length MSB OR per-frame FCS status
        [12:0]  Frame length (or header length if header-split)

TX Buffer Descriptor — Non-LSO (Word 0 / Word 1)

Word 0  [31:0]  Byte address of buffer

Word 1  [31]    Used: 0=ready, 1=complete
        [30]    Wrap
        [29]    Retry limit exceeded
        [28]    Transmit underrun
        [27]    TX frame corruption / bus error
        [26]    Late collision
        [23]    Timestamp captured (extended BD)
        [22:20] TX checksum-offload error code
        [16]    No CRC appended by MAC
        [15]    Last buffer
        [13:0]  Buffer length

6.2 DMA 操作流程

SW:  RX: allocate buffers, fill descriptors (addr, ownership=0)
     TX: build frame, fill descriptors (addr, len, last, used=0)

DMA: Fetch descriptor from ring base
     if ownership=1 -> halt / resource error / interrupt
     TX: read data from memory -> MAC
     RX: write data from MAC -> memory
     Write status back to Word 1 (used=1, errors, len, timestamp)
     Advance pointer; wrap on wrap-bit

IRQ: frame transmitted, frame received, buffer unavailable,
     overrun, underrun, bus error

7. MAC TX/RX/过滤深入

7.1 MAC 发送状态机与帧格式

步骤行为
数据输入外部 FIFO / DMA → 小输入缓冲；按 dma_bus_width 读取 32/64/128-bit，后续按字节处理
Preamble/SFD自动添加 7 字节 preamble + 1 字节 SFD
数据宽度千兆：txd[7:0]；10/100M：低 nibble txd[3:0]，txd[7:4]=0
Padding不足 60 字节时补 0 至 60 字节
FCS/CRCCRC-32 计算并取反追加；最小帧 64 字节
No-CRC 模式TX descriptor bit 16 或 FIFO 接口设置时，不 padding、不追加 CRC

7.2 双工与冲突处理

模式行为
全双工立即发送；帧间隔 ≥96 bit times (IFG)
半双工检测载波；若载波有效则等待释放 + 96-bit IFG 后发送
冲突发送 32-bit jam，按截断二进制指数退避重试（最多 16 次）
P/SFD 期间冲突先完成 preamble/SFD，再发送 jam
延迟冲突10/100M：按冲突处理；千兆：中止、不重试、报告 late collision
Underrun自动追加 bad CRC 并置位 tx_er

7.3 MAC 接收与错误检测

项目说明
数据通路16-bit 内部数据通路
FCS 移除Network config bit 17：存储帧时不带 FCS，报告长度减 4
CRC 错误处理bit 26 置位时忽略 CRC 错误，errored 帧不丢弃；descriptor bit[13] 指示 FCS 有效性
过长帧 (giant)标记 bad frame，停止写入内存
过小帧 / short统计计数；标记 bad
对齐错误统计计数
Symbol 错误统计计数
Length field 错误比较测量长度与 length/type 字段；若测量更短则丢弃（仅 64–1518 字节且 length/type < 0x0600）

项目说明

比较48-bit seconds + 22-bit ns 与 tsu_timer_comparison 比较；匹配产生中断 status bit 29
外部计时器可选 94-bit 外部时间戳端口，同步到 tsu_clk
SOF 捕获TX/RX SOF 跨越 MII/GMII 边界时同步到 tsu_clk 采样
单步同步Network-control bit 使能替换时间戳字段；oss_correction_field 使能单步 residence-time correction
802.1AS识别 DA 01-80-C2-00-00-0E；不支持 one-step timestamping

8.2 802.1Qbv EnST

项目说明
概念8 个最高优先级 TX 队列的时间感知门控，与 TSU 同步
每队列寄存器start_time[31:0]（2-bit seconds + 30-bit ns）、on_time[16:0]（bytes）、off_time[16:0]（bytes）、enst_en
控制16-bit enable/disable：bits [7:0] 使能队列，bits [15:8] 禁用（disable 优先级高）
操作Gate 在 start_time 打开，然后重复 on_time / off_time 周期
帧合格性若帧无法在剩余 on_time 内发送完成，则不启动；若永远无法容纳则丢弃并报错
字节-时间换算@1Gb/s：1 byte = 8 ns；@100Mb/s：80 ns；@10Mb/s：800 ns

8.3 802.1CB FRER

项目说明
范围仅支持流识别和帧消除；不支持帧复制
流识别使用 Type 2 Screener compares；每个 CB stream 指向 screeners
序列号源Redundancy Tag（Ethertype 0xF1C1），4-byte（draft 2.4）或 6-byte（draft 2.5+）格式；或 byte offset 模式
恢复算法Match 算法和 Vector 算法，每流可配置
超时frer_timeout 加载到序列恢复复位计时器；超时后重置 RecovSeqNum

8.4 802.3br / 802.1Qbu 帧抢占 (MMSL)

项目说明
架构两个 MAC 实例 + MMSL + AXI arbiter/APB switch。eMAC=express，pMAC=preemptable
eMAC 限制固定 1 队列；若 CB 使能则 CB stream 固定为 2；使用 pMAC 的 TSU 作为外部 TSU；不支持 RSC
TX 抢占eMAC 请求通道时，若 pMAC 正在发送 M-frame，则 pMAC 帧暂停并追加 32-bit MCRC，然后发送 express 帧
不可抢占条件剩余 <64 M-frame 字节；未达 add_frag_size 最小值；抢占禁用；验证失败/握手未完成
RX 重组MMSL 路由 M-frames；pMAC 帧使用修改后的 SFD 检测 fragment；RX 状态机在 express 帧期间暂停，continuation fragment 到达后恢复
验证复位后发送 verify frame，10 ms 内期望 respond；最多再重试 2 次后禁用抢占
地址映射pMAC 0x0000–0x0EFC，MMSL 0x0F00–0x0FFC，eMAC 0x1000–0x1FFC

8.5 802.1Qci 接收流量监管

机制寄存器说明
队列 flushrx_q_flush (0x0B00)按队列丢弃：全部流量、BD-used 置位、SRAM 使用阈值、帧长度阈值
速率限制scr2_reg_rate_limit (0x0B40)超过编程速率的帧被丢弃
软硬件边界: 1588 TSU、EnST 门控、FRER 消除、MMSL 抢占均由硬件实现状态机和数据通路，但配置、BMCA、调度表、流映射、验证重启由软件负责。FRER 的帧复制不由 GEM 完成。

10. 功能安全 / DFT / 低功耗

10.1 Automotive Safety Features (ASF)

机制说明
Fault logging统一 ASF 状态寄存器位于 0x0E00；记录 lockup、parity、ECC、protocol errors
CSR protection配置/控制/状态寄存器 parity 保护；关键寄存器（network control、TX/RX status、interrupt、MDIO、scheduler） duplication + comparison
SRAM ECCTX/RX SRAM SECDED ECC；32/64/128-bit datapath 分别增加 7/8/16 bit。记录不可纠正错误地址
Datapath parityTX/RX 数据通路和描述符写回数据/地址每字节 1-bit parity
Address path parity描述符起始地址 parity 保护，增量访问时重新生成
TSU protection可选 TSU 模块 duplication（gem_protect_tsu）+ 连续输出比较；时间戳值 parity 保护
Scheduler protection可选 TX scheduler + EnST/CBS duplication + 连续输出比较
Transaction timeout每 AXI 通道一个 timeout monitor
Lockup detection可编程 prescaler + timer 监控 DMA TX、MAC TX、MAC RX、DMA RX；检测到后可自动关闭 TX/RX
Protocol fault loggingRX CRC/short/long/symbol/length/IP/TCP/UDP 错误、TX underrun/retry、AHB hresp、overflow 等可屏蔽中断
Interrupt classification专用 asf_int_fatal 和 asf_int_nonfatal 引脚；通过 asf_fatal_nonfatal_select 和 asf_int_mask 路由

项目内容

类别说明

12. 与当前项目的差距分析

当前项目文档（Docs/Arch/ethernet_arch_spec.md 等）定义了一个非常宏大的 Ethernet IP：4-port L2/L3 Switch、8 MAC、全局 DMA 通道池、双 PHC + vPHC、5G/10G、USXGMII 等。而实际 RTL Design/RTL/ip/ethernet/ethernet_top.sv 仍是空壳。主要差距如下：

维度当前项目规划Cadence GEM GXL差距评估风险
端口/MAC 数量1-8 MAC，4-port Switch单端口 MAC；802.3br 为双 MAC + MMSLSwitch 无参考高
Switch 功能L2/L3 Switch、FDB 8K、VLAN、L3 route无 Switch需从零设计极高
DMA 架构全局 8/16/32 通道池，所有 MAC 共享每 MAC 独立 AXI/AHB DMA架构差异大高
时间同步双 PHC + vPHC + Xen IO Rings单 TSU，外部/内部可选vPHC 无参考高
PHY 接口MII/RMII/RGMII/SGMII/USXGMII，2.5G/5G/10GMII/RMII/RGMII + PCS (1G)高速 SerDes 无参考中-高
TSN 实现CBS/TAS/FRER/FP/PSFP 均 P0CBS/EnST/FRER/MMSL 有 RTLPSFP/Switch TAS 无参考中
安全ASIL-B，ECC/Parity/Timeout/SMU_ALERTASF/ECC/Parity/Timeout/Lockup机制可借鉴低-中
验证UVM 计划存在，RTL 可用 TB 未明确UVM + Legacy TB + SVA 完整需尽快搭建 TB高
核心风险: 当前 Arch Spec 的范围（Switch + 多 MAC + vPHC + 5G/10G）远超 Cadence GEM GXL 这一成熟单端口千兆 MAC 参考。若按现有规划继续，IDR 阶段极难完成。建议收敛范围：先实现单/双端口 GMAC（含 DMA、TSU、基本 TSN），Switch 和 vPHC 作为后续 Phase 扩展。

13. 优化建议

13.1 架构文档 (ethernet_arch_spec.md)

建议优先级说明
将“4-port L2/L3 Switch”从默认开启改为可选扩展模块，MVD 先聚焦单/双 GMACP0Switch 无 Cadence 参考，实现风险最高
将 vPHC / Xen IO Rings 从 P0 降级为 P2 可选项P0虚拟化时间域可由软件或 Hypervisor 先承担
将全局 DMA 通道池改为每 MAC 独立 DMA，降低初始集成复杂度P1与 Cadence 一致，便于验证和时序收敛
PHY 接口分阶段：Phase-1 实现 MII/RMII/RGMII；SGMII/USXGMII/2.5G+ 后续扩展P1Cadence 仅支持到 RGMII/PCS 1G
明确 TSN 特性优先级：CBS/EnST/FRER/MMSL 保留 P0；PSFP/Switch TAS 降级 P2P1与 Cadence 已实现子集对齐

13.2 协议分析 (protocol_analysis.md)

建议优先级说明
将 802.1Qbv TAS 的范围限定为端点级 EnST（队列门控），删除“Switch 级 TAS”的 P0 要求P0Cadence 仅在 TX 队列实现 EnST
将 802.1Qci PSFP 从 P0 降级为 P2/NoP0PSFP 需要 Switch/流过滤/门控完整实现，当前无 RTL 基础
明确 802.1AS gPTP 的软硬件边界：RTL 负责硬件时间戳 + SOF 事件；BMCA/数据集由软件实现P1与 Cadence TSU 设计一致
将 MACsec/IPsec/SecOC/D-TLS 统一作为“安全加速器接口”处理，不作为 Ethernet IP 内部实现P1Cadence 无内置 MACsec；当前项目可保留接口但不扩展内部密码学
将 EEE、AVTP/IEEE 1722 保持为 Configurable，默认关闭P2与 Cadence 可选配置一致

13.3 接口规范 (ethernet_interface_spec.md)

建议优先级说明
参考 Cadence APB 寄存器分组，细化 CSR 地址映射与 bit 字段P0当前 CSR 规划较粗，驱动无法落地
AXI ID 分配从 16 路缩减到 4-8 路，与单/双 MAC DMA 匹配P1降低 AXI 互连复杂度
删除或延后 SECURITY_ACCEL 128-bit 接口细节，先定义握手/包头格式P1安全加速器接口应与 CSS/HSE 团队协商标定
时钟/复位域明确划分为 pclk、tx_clk、rx_clk、aclk、tsu_clkP1与 Cadence 跨时钟域设计一致

13.4 设计规范 (ethernet_design_spec.md)

建议优先级说明
立即填充 ethernet_top.sv：定义参数、端口、子模块划分P0当前为 TODO 空壳，IDR 阶段 unacceptable
微架构先实现：eth_mac (TX/RX/filter) → eth_dma → eth_reg → eth_hsphyP0与 Cadence gem_top 模块划分对应
安全模块先实现 CSR parity + 关键 SRAM ECC + bus timeout + lockup detectP1参考 ASF 最小集
验证环境优先搭建模块级 Verilog TB，再迁移到 UVMP1借鉴 Cadence vlog_tb 思路

13.5 推荐开发路线图

Phase 1 — 最小可用 GMAC (MVD)
  └─ MAC TX/RX + FCS + filter + MII/RGMII + APB CSR + AXI DMA + 描述符环
  └─ 模块级 Verilog TB：单包 TX/RX、寄存器读写、FCS 错误注入

Phase 2 — 车规与时间同步
  └─ 1588 TSU + SOF 事件触发 + 时间戳描述符
  └─ ASF：parity + ECC + timeout + lockup detection
  └─ 半双工、PAUSE/PFC、WoL

Phase 3 — TSN 增强
  └─ CBS (802.1Qav) → EnST/TAS (802.1Qbv) → MMSL/帧抢占 (802.1Qbu/802.3br)
  └─ FRER (802.1CB) 接收消除

Phase 4 — 扩展 (可选 / 长期)
  └─ 多 MAC + Switch (L2/L3) + vPHC + 高速 PHY (SGMII/USXGMII)
总结: Cadence GEM GXL 是一份高质量的单端口千兆 Ethernet MAC + DMA + 1588 + TSN 参考实现。当前项目应以其为基线收敛 Arch Spec 和 Design Spec，优先完成最小 GMAC，再按需叠加 TSN 和 Switch/vPHC 扩展。
