cbTxRxTest Tx-Rx with Callbacks Test Single buffer/frame tx-rx using isr & callbacks.

Tx on highest priority queue available (or enter qNum as command parameter). Frame is 256 bytes or reduced if necessary to fit packet buffer. Arbitrary data, no frame headers, CRC auto-generated.

Rx buffer 2048 bytes, promiscuous mode.

Call isr() on both sides, waiting for Tx Complete & Rx Complete events, and accepting Tx Used Read - any other events will cause an error.

Validate basic Tx & Rx statistics and data content.

testSetup

Initialisation of driver for one of the two GEM instances in the VSP test wrapper. Calls probe and init functions to provide inital setup for test cases. Test can either provide a specific configuration (used for both instances), or if cfgPtr==NULL, the initConfig function will be used as a standard initialisation, using the txQSize, rxQSize and rxBufLenBytes parameters. In this case, the maximum number of Tx & Rx queues will be configured. If PCS is present and MII/GMII interface selected, this will be changed to 1000BASE_X.

Parameters
cInstCDDC instance, for debug output
objInstGEM instance: 0 or 1
txQSize- number of descriptors per Tx queue, used if cfgPtr==NULL
rxQSize- number of descriptors per Rx queue, used if cfgPtr==NULL
rxBufLenBytes- size of Rx buffers to use, if cfgPtr==NULL
cfgPtr- defines the configuration to initialise the driver and h/w
Returns
0 for success
1 if probe call returns error or private data malloc fails
2 if Rx descriptors' HWMem alloc fails
3 if Tx descriptors' HWMem alloc fails
4 if init call returns error
