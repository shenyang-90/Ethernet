**Scope**: Read-only RTL analysis of the Cadence GEM GXL (IP7014A, r1p12) TSN/1588-related blocks.

## 1. Executive Summary

The GEM GXL MAC implements a **sub-set of the IEEE TSN and 1588 feature stack** in synthesizable Verilog. The analyzed RTL covers:

| Feature | IEEE Standard | Key Files | Implementation Status |
|---------|--------------|-----------|----------------------|
| Time Synchronization / TSU | IEEE 1588-2008/2019, 802.1AS-2020 | `gem_tsu.v`, `gem_pulse_tsync.v` | Full RTL |
| Credit-Based Shaper (CBS) | 802.1Qav | `edma_tx_sched.v`, `edma_tfc_shaper.v` | Full RTL (2 queues) |
| Scheduled Traffic (EnST/TAS) | 802.1Qbv | `edma_pbuf_tx_enst*.v` | Full RTL (per-queue gates) |
| Frame Preemption (MAC Merge) | 802.1Qbu / 802.3br | `gem_mmsl*.v` | Full RTL (eMAC + pMAC) |
| Frame Replication & Elimination (FRER) | 802.1CB | `gem_rx_frer_elim.v` | Full RTL (elimination only) |
| Receive Classification / Stream ID | 802.1CB / 802.1Qci concepts | `gem_screener_*.v` | Full RTL |

**Overall maturity**: All listed features are implemented in RTL and are parameter-gated or register-configurable. No pure software-emulated paths were found for the functions above. Some functions (e.g., FRER sequence-number source, EnST per-queue parameters) are configured through register maps rather than hard-wired.

## 3. IEEE 1588 / 802.1AS — Time Synchronization Unit

### 3.1 Files
- `gem_tsu.v` — timer core
- `gem_pulse_tsync.v` — generic CDC pulse synchronizer (used for event timestamps)

### 3.2 Timer Architecture

| Attribute | Value | Comment |
|-----------|-------|---------|
| Seconds width | 48 bits | Covers >100 years of POSIX seconds |
| Nanoseconds width | 30 bits | 0–999,999,999 ns |
| Sub-nanoseconds width | 24 bits | Fine-grained drift compensation |
| Total timer bus | 94 bits | `{sec[47:0], nsec[29:0], sub_nsec[23:0]}` |
| Clocking | `tsu_clk` or `pclk` | Selected by `p_edma_tsu_clk` |
| External timer | Optional | `ext_tsu_timer[93:0]` via `p_edma_ext_tsu_timer` |
| Parity protection | Optional | `p_edma_asf_dap_prot` |

### 3.3 Implemented Functions

| Function | Evidence in RTL | Notes |
|----------|-----------------|-------|
| Free-running counter | `int_timer_sec_calc_val`, `int_timer_nsec_calc_val` | Incremented every clock |
| Programmable increment | `tsu_timer_incr[31:0]` | Includes sub-ns portion |
| Alternative increment | `tsu_timer_alt_incr[7:0]`, `tsu_timer_num_incr[7:0]` | Periodic drift correction |
| Add/subtract adjust | `tsu_timer_adj[29:0]`, `tsu_timer_adj_ctrl` | Single-shot phase step |
| Direct write sec/ns | `tsu_timer_sec_wr`, `tsu_timer_nsec_wr` | Initialization / grandmaster set |
| Master/slave mode | `gem_tsu_ms`, `gem_tsu_inc_ctrl[1:0]` | Controls increment behavior |
| Timer comparison | `tsu_timer_sec_cmp`, `tsu_timer_nsec_cmp` | Generates `tsu_timer_cmp_val` for scheduled traffic |
| Second-increment strobe | `tsu_sec_incr` | Toggles on each seconds rollover |
| Strobe register load | `timer_strobe` | Used to sample timestamps |

### 3.4 1588 vs 802.1AS Readiness

- **IEEE 1588**: The timer precision and increment granularity are sufficient for PTP ordinary/boundary/transparent clocks. The one-shot adjustment path supports PTP servo corrections.
- **802.1AS**: The `gem_tsu_ms` control allows the timer to run in master or slave mode, and the sub-ns increment supports the tight drift tracking required by gPTP. However, the analyzed RTL only shows the **timer hardware**; higher-layer gPTP state machines (BMCA, peer-delay, sync interval) are expected to be firmware-driven.

### 3.5 Configurability

| Parameter | Default | Effect |
|-----------|---------|--------|
| `p_edma_tsu` | `1'b1` | Instantiates the TSU block |
| `p_edma_tsu_clk` | `1'b0` | `1` = dedicated `tsu_clk`; `0` = uses `pclk` |
| `p_edma_ext_tsu_timer` | `1'b0` | `1` = timer value taken from external port |
| `p_edma_asf_dap_prot` | `1'b0` | `1` = parity protection on timer data |

## 4. 802.1Qav — Credit-Based Shaper (CBS)

### 4.1 Files
- `edma_tfc_shaper.v` — credit accumulator
- `edma_tx_sched.v` — scheduler integration

### 4.2 Architecture

| Feature | Implementation |
|---------|----------------|
| Number of CBS queues | 2 (queue A = highest priority, queue B = second highest) |
| Credit representation | 45-bit signed magnitude (MSB = sign, 44-bit magnitude) |
| idleSlope | 32-bit per-queue register (`idleslope_q_a/b`) |
| sendSlope | Computed as `port_tx_rate - idleslope` |
| Transmission condition | `credit >= 0` and packets pending |
| Credit reset | On disable, flush, or when queue empty with positive credit |
| Overrun protection | `block_pos_inc` / `block_neg_inc` saturates credit |

### 4.3 Scheduler Modes (edma_tx_sched.v)

The scheduler supports multiple arbitration policies simultaneously:

| Mode | Control Bits | Description |
|------|--------------|-------------|
| Fixed Priority | `dwrr_ets_control[(i*2)+1:(i*2)] = 2'b00` | Strict priority by queue index |
| DWRR | `2'b01` | Deficit round-robin with per-queue quantum |
| ETS | `2'b11` | Enhanced Transmission Selection, credit updated every 100/200 cycles |
| CBS | `cbs_enable_q_a/b` | Applied only to the two top queues |

### 4.4 CBS Gating

```verilog
// edma_tx_sched.v
generate if (p_edma_exclude_cbs == 1'b0 && p_edma_queues > 32'd1) begin : gen_instance_shaper
  edma_tfc_shaper i_edma_tfc_shaper ( ... );
end else begin : gen_no_cbs
  assign cbs_queue = 2'h0;
end
endgenerate
```

| Parameter | Default | Effect |
|-----------|---------|--------|
| `p_edma_exclude_cbs` | `1'b0` | `1` = remove CBS shaper |
| `p_edma_queues` | `32'd1` | CBS meaningful only when `> 1` |

## 5. 802.1Qbv — Scheduled Traffic (EnST / TAS)

### 5.1 Files
- `edma_pbuf_tx_enst.v` — top wrapper + CDC
- `edma_pbuf_tx_enst_fsm.v` — TSU-clock gate FSM
- `edma_pbuf_tx_enst_fc.v` — TX-clock byte counter

### 5.2 Function

Each transmit queue can be gated by a **time-aware gate** driven by the TSU timer. The gate produces:

| Signal | Width | Purpose |
|--------|-------|---------|
| `gatestate` | 1 | Queue open/closed to scheduler |
| `byte_count[18:0]` | 19 | Remaining bytes allowed in current open window |
| `tsu_hold` | 1 | Hold signal for 802.3br preemption |

### 5.3 Timing Parameters (per queue, register-programmed)

| Register Field | Width | Meaning |
|----------------|-------|---------|
| `start_time[31:0]` | 32 | TSU-time-aligned gate open start |
| `on_time[16:0]` | 17 | Bytes (after rate scaling) gate stays open |
| `off_time[16:0]` | 17 | Bytes (after rate scaling) gate stays closed |
| `add_frag_size[1:0]` | 2 | Preemption fragment size: 64/128/192/256 bytes |
| `speed[1:0]` | 2 | 2.5G / 1G / 100M / 10M |

### 5.4 FSM Checkpoints

The FSM in `edma_pbuf_tx_enst_fsm.v` uses six compare checkpoints:

1. Start – `add_frag_size_time`
2. TSU time ≥ `start_time – add_frag_size_time` (early start)
3. TSU time ≥ `start_time`
4. TSU time ≥ `start_time + on_time`
5. TSU time ≥ `start_time + on_time + off_time – add_frag_size_time`
6. TSU time ≥ `start_time + on_time + off_time`

### 5.5 802.3br Integration

`tsu_hold` is asserted during the early-start window so that a preemptable frame can be interrupted before the gate closes, allowing the express MAC to take over. This couples EnST directly with the MAC Merge sublayer.

### 5.6 Configurability

| Parameter | Default | Effect |
|-----------|---------|--------|
| `p_edma_asf_prot_tx_sched` | `1'b0` | `1` = duplicate EnST FSM/FC for ASF fault tolerance |

## 6. 802.1Qbu / 802.3br — Frame Preemption (MAC Merge Sublayer)

### 6.1 Files
- `gem_mmsl.v` — top-level MAC Merge
- `gem_mmsl_tx_proc.v` — TX preemption / SMD / MCRC
- `gem_mmsl_rx_proc.v` — RX reassembly / SMD decode / MCRC check
- `gem_mmsl_rx_exp_flt.v` — Express / Verify / Response filter
- `gem_mmsl_rx_smd_decode.v` — SMD-S / SMD-C / FRAG_COUNT decode
- `gem_mmsl_rx_group16_sys.v`, `gem_mmsl_rx_output_driver.v` — datapath helpers
- `gem_mmsl_ver.v` — Verify/Response handshake state machine
- `gem_mmsl_reg.v`, `gem_mmsl_reg_int_sts.v`, `gem_mmsl_apb_switch.v` — CSR

### 6.2 High-Level Architecture

| MAC | Role | Traffic |
|-----|------|---------|
| eMAC | Express MAC | Time-critical / high-priority frames |
| pMAC | Preemptable MAC | Best-effort / long frames that can be fragmented |

### 6.3 TX Preemption (`gem_mmsl_tx_proc.v`)

| Feature | Detail |
|---------|--------|
| Preemption trigger | `emac_tx_en` or `hold` from EnST while `preemptable_frag_size` reached and `min_remain` true |
| Fragment sizes | 64, 128, 192, 256 bytes via `add_frag_size` |
| Start delimiter | SMD-S (values `e6, 4c, 7f, b3` for frame_count 0..3) |
| Continuation delimiter | SMD-C (values `61, 52, 9e, 2a`) + FRAG_COUNT |
| Integrity check | 32-bit MCRC appended to each fragment |
| Verification | Verify/Response m-packets generated by `gem_mmsl_ver.v` |
| IPG handling | 12 bytes (GMII) / 24 nibbles (MII) |
| LPI passthrough | Detected and forwarded for pMAC |

### 6.4 RX Reassembly (`gem_mmsl_rx_proc.v`)

| Feature | Detail |
|---------|--------|
| SMD decode | SMD-S, SMD-C, SMD-V, SMD-R, SFD, preamble |
| Frame count | Modulo-4 tracking to match continuation to start |
| Fragment count | Modulo-4 `nxt_frag_cnt` to detect missing fragments |
| MCRC check | 32-bit CRC over preemptable fragment; constant `0xff48647d` / inverted `0x384cb906` |
| Halt signal | `pmac_rx_halt` pauses pMAC RX while waiting for continuation |
| Error flags | `smd_error`, `smdc_error`, `smds_error`, `fr_count_error`, `ass_error` |

### 6.5 Verify / Response Protocol (`gem_mmsl_ver.v`)

| State | Purpose |
|-------|---------|
| `V_IDLE` → `SEND_VERIFY` | Transmit SMD-V m-packet when `pre_enable` and not `disable_verify` |
| `WFR` | Wait up to 10 ms for SMD-R response |
| `VERIFIED` | Link partner confirms preemption capability |
| `VERIFY_FAIL` | No response after retries |
| `SEND_RESPOND` | Auto-reply to received SMD-V with SMD-R |

### 6.6 Register Map (`gem_mmsl_reg.v`)

| Register | Offset | Fields |
|----------|--------|--------|
| `MMSL_CONTROL` | `0x00` | `add_frag_size`, `disable_verify`, `pre_enable`, `restart_ver_tog`, `route_rx_to_pmac`, `mmsl_debug_mode`, `invert_mcrc` |
| `MMSL_STATUS` | `0x01` | `p_active`, `respond_status`, `verify_status`, error flags |
| `MMSL_ERR_STATS` | `0x02` | SMD error count, assembly error count |
| `MMSL_ASS_OK_COUNT` | `0x03` | Successful reassembly count |
| `MMSL_FRAG_COUNT_RX` | `0x04` | RX fragment count |
| `MMSL_FRAG_COUNT_TX` | `0x05` | TX fragment count |
| Interrupt regs | `0x06–0x09` | Status, enable, disable, mask |

### 6.7 Configurability

| Parameter | Default | Effect |
|-----------|---------|--------|
| `p_edma_asf_dap_prot` | `1'b0` | Parity on datapath |
| `p_edma_asf_csr_prot` | `1'b0` | Parity on CSRs |
| `p_edma_asf_host_par` | `1'b0` | Generate parity on `prdata` |

## 7. 802.1CB — Frame Replication and Elimination (FRER)

### 7.1 Files
- `gem_rx_frer_elim.v`

### 7.2 Scope

The RTL implements the **elimination function** on the receive path. It does **not** include the replication/transmit-side function in the analyzed files.

### 7.3 Configuration Inputs

| Signal | Width | Purpose |
|--------|-------|---------|
| `frer_to_cnt[15:0]` | 16 | Timeout count for sequence recovery reset |
| `frer_en_vec_alg` | 1 | `1` = Vector Recovery, `0` = Match Recovery |
| `frer_use_rtag` | 1 | `1` = use RTag sequence number, `0` = extract from frame offset |
| `frer_seqnum_oset[8:0]` | 9 | Byte offset for sequence number extraction |
| `frer_seqnum_len[4:0]` | 5 | Number of sequence-number bits to use |
| `frer_scr_sel_1/2[3:0]` | 4 | Screener match bits selecting the stream |
| `frer_vec_win_sz[5:0]` | 6 | History window size for vector recovery |

### 7.4 Algorithms

| Algorithm | Behavior |
|-----------|----------|
| **Match Recovery** | Keeps `highest_seqnum`. Discards frames whose masked sequence number equals the stored value. Updates on each good frame. |
| **Vector Recovery** | Maintains a 64-entry history vector (`hist_vec_seen`, `hist_vec_dup`). Discards duplicates within the window and flags rogue frames outside the window. |

### 7.5 Statistics / Diagnostics

| Output | Meaning |
|--------|---------|
| `frer_to_tog` | Timeout toggled |
| `frer_rogue_tog` | Rogue frame detected (vector mode) |
| `frer_ooo_tog` | Out-of-order frame detected |
| `frer_err_upd_tog` + `frer_err_upd_val[6:0]` | Latent error accumulator update |
| `frer_discard` | Asserted to drop current frame |

### 7.6 Automotive Relevance

- **Essential for safety-critical streams**: FRER elimination is required on redundant receive paths.
- **No replication observed in analyzed files**: If the SoC needs to *send* replicated streams, that function must be implemented elsewhere (e.g., in firmware or a separate transmit FRER block).

## 8. Receive Classification / Stream Identification

### 8.1 Files
- `gem_screener_top.v`
- `gem_screener_type1.v`
- `gem_screener_type2.v`

### 8.2 Type 1 Screener (`gem_screener_type1.v`)

Matches on:
- IPv4 TOS (`ip_v4_tos[7:0]`)
- IPv6 Traffic Class (`ip_v6_tc[7:0]`)
- UDP destination port (`udp_dest_addr[15:0]`)

Match modes per register:

| `udptos_rules[29:28]` | Match condition |
|-----------------------|-----------------|
| `2'b01` | TOS or TC match |
| `2'b10` | UDP destination port match |
| `2'b11` | UDP port match AND (TOS or TC) match |

### 8.3 Type 2 Screener (`gem_screener_type2.v`)

Matches on a boolean combination of:
- VLAN priority (`tci[2:0]`)
- Ethertype match index (`scr2_ethtype_match[7:0]`)
- Three compare-match indices (`compa/b/c_match` from `scr2_compare_match[31:0]`)

Each rule enables/disables individual terms (`vlan_rules[8,12,18,24,30]`).

### 8.4 Top-Level Arbitration (`gem_screener_top.v`)

- Lowest-addressed matching screener wins.
- Type 1 has priority over Type 2.
- `priority_queue[3:0]` is routed to the DMA queue selection.
- `drop_frame` can be asserted on a per-screener basis.
- `scr2_match_vec[15:0]` is exported to FRER for stream selection.

### 8.5 Configurability

| Parameter | Default | Effect |
|-----------|---------|--------|
| `p_num_type1_screeners` | `8'd0` | Number of Type 1 rules |
| `p_num_type2_screeners` | `8'd0` | Number of Type 2 rules (max 16) |

## 10. Essential vs Optional for Automotive Ethernet

### 10.1 Essential for Automotive Use Cases

| Feature | Why Essential | GEM GXL Status |
|---------|---------------|----------------|
| IEEE 1588 / 802.1AS timer | Time synchronization for ADAS sensors, ECUs | ✅ Implemented |
| TX/RX timestamping | PTP event timestamping | ✅ Implemented (gated by `p_edma_tsu`) |
| 802.1Qav CBS | Bandwidth reservation for AVB/TSN streams | ✅ Implemented |
| 802.1Qbv TAS | Deterministic gate scheduling for critical traffic | ✅ Implemented |
| 802.1CB FRER elimination | Redundant stream reception for safety (e.g., camera/lidar) | ✅ Implemented |
| Stream classification (screener) | Identify streams for FRER / QoS | ✅ Implemented |

### 10.2 Optional / Use-Case Dependent

| Feature | When Needed | GEM GXL Status |
|---------|-------------|----------------|
| 802.1Qbu/802.3br preemption | When express traffic must interrupt long best-effort frames | ✅ Implemented |
| External TSU timer | Multi-port shared timebase | ✅ Optional |
| Dedicated `tsu_clk` | Lower jitter than pclk-based timer | ✅ Optional |
| FRER replication (TX) | When endpoint must send redundant streams | ❌ Not in analyzed RTL |
| 802.1Qci per-stream policing/gating | Full PSFP beyond classification | ⚠️ Partial (classification + drop only) |
| ASF fault tolerance | Functional-safety requirements | ✅ Optional parity/duplication |

### 10.3 Gaps / Limitations to Note

1. **FRER replication is receive-side only** in the analyzed files. A complete 802.1CB implementation may need a TX replication block or firmware-managed duplication.
2. **802.1Qci PSFP** is not fully implemented: there is no per-stream gate control or policing meter separate from the queue-level EnST gates.
3. **gPTP protocol state machine** is not in RTL; the TSU provides the clock but firmware/software must run BMCA, peer-delay, and sync logic.
4. **CBS is limited to two queues** (the two highest priority queues). Additional queues use DWRR/ETS, not CBS.
5. **EnST/TAS parameters are byte-scaled** rather than true nanosecond gate control lists, requiring software to compute `on_time`/`off_time` per link speed.

## 11. Conclusion

The Cadence GEM GXL MAC contains a **mature, RTL-level implementation** of the core TSN/1588 building blocks required for automotive Ethernet:

- 1588/802.1AS timer with sub-ns precision
- 802.1Qav CBS on two priority queues
- 802.1Qbv time-aware per-queue gating with 802.3br hold support
- 802.1Qbu/802.3br MAC Merge for frame preemption
- 802.1CB FRER elimination with Match/Vector recovery
- Receive classification (screeners) for stream identification and QoS routing

All analyzed features are synthesizable, register-configurable, and (where noted) parameter-gated. The primary functional gaps for a complete automotive TSN stack are **FRER transmit replication** and **full 802.1Qci PSFP policing/gating**, both of which would need to be addressed by companion logic or firmware.
