1. 协议概述

IEEE 802.1AB-2016 定义了 Link Layer Discovery Protocol (LLDP)，用于直连网络设备之间自动发现邻居信息并交换本地系统能力。LLDP 在数据链路层操作，无需 IP 层配置。

核心功能：每个端口周期性地发送包含本地系统信息的 LLDPDU；接收并存储邻居信息，供网络管理系统查询。

1.1 协议范围

功能说明
邻居发现自动发现直连设备身份与端口信息
拓扑管理构建二层网络拓扑图
能力通告通告系统能力（Bridge/Router/AP 等）
故障定位快速定位物理连接问题
即插即用无需手动配置即可交换管理信息
LLDP 是 单向协议：TX 和 RX 独立运行。接收到的信息存入本地 MIB，不向对方发送确认或响应。

2. 地址与帧封装 (Clause 7)

2.1 目的 MAC 地址 (Table 7-1)

名称MAC 地址作用范围
Nearest bridge01-80-C2-00-00-0E所有 Bridge 类型（C-VLAN/S-VLAN/TPMR/MAC Bridge）都会终止，仅限单 LAN 段
Nearest non-TPMR bridge01-80-C2-00-00-03TPMR 会转发；C-VLAN/S-VLAN/MAC Bridge 终止
Nearest Customer Bridge01-80-C2-00-00-00TPMR 和 S-VLAN 转发；C-VLAN/MAC Bridge 终止

RTL 设计提示：目的地址过滤

  • End Station 必须支持 01-80-C2-00-00-0E（Nearest bridge）
  • 对 03 和 00 的支持为可选，取决于部署场景
  • 接收模块的地址过滤器应可配置匹配哪个 DA

2.2 源地址

发送端口/站的独立 MAC 地址（Individual MAC Address）。

2.3 EtherType

LLDP EtherType = 0x88CC（Table 7-3），编码为 MSDU 中的 2-octet 头。

2.4 接收过滤条件 (Clause 7.4)

帧被递送给 LLDP 接收模块 当且仅当：

  1. DA 匹配该 LLDP Agent 实例关联的 MAC 地址；
  2. EtherType == 0x88CC。

3. LLDPDU 帧格式 (Clause 8.2)

3.1 位/字节序 (Clause 8.1)

  • 所有 LLDPDU 包含 整数个八位组。
  • 八位组从 1 开始编号，按传输顺序从左到右。
  • 八位组内位从 1（LSB）到 8（MSB）编号。
  • 多八位组字段：低编号八位组 = 更高有效值（大端序）。
  • 八位组内位字段：高位号 = 更高有效值。
  • 图示约定：bit 8 在左，bit 1 在右。

3.2 LLDPDU 结构

[ Chassis ID TLV ] [ Port ID TLV ] [ TTL TLV ] [ Optional TLVs ... ] [ End of LLDPDU TLV (optional) ]
规则说明
前 3 个 TLV 为强制必须按 Chassis ID → Port ID → TTL 的严格顺序出现
可选 TLV 顺序可选 TLV 可以以任意顺序跟随
End TLV 位置End of LLDPDU TLV（Type=0）如果存在必须位于最后
End TLV 之后End TLV 之后的任何八位组均被丢弃

3.3 最大长度

  • IEEE 802.3：最大 1500 个八位组（基本无标签 MAC 帧数据字段）。
  • 无定义的最小长度，除强制 TLV 外。
注意：如果构造的 LLDPDU 超出最大帧长，Agent 必须仅发送强制 TLV（Chassis ID + Port ID + TTL），并丢弃多余的可选 TLV。

4. TLV 通用格式与类型 (Clause 8.4)

4.1 TLV 通用头 — 2 个八位组

Octet 1:  [ Type[6:0] | Length[8] ]
Octet 2:  [ Length[7:0] ]
字段位数说明
TLV Type7（头中的 bits 15:9）标识 TLV 类型
TLV Information String Length9（头中的 bits 8:0）载荷长度（八位组）

TLV 总大小 = 2 + Length 个八位组。

4.2 TLV 类型值 (Table 8-1)

Type名称用途参考
0End Of LLDPDU可选8.5.1
1Chassis ID强制8.5.2
2Port ID强制8.5.3
3Time To Live强制8.5.4
4Port Description可选8.5.5
5System Name可选8.5.6
6System Description可选8.5.7
7System Capabilities可选8.5.8
8Management Address可选8.5.9
9–126Reserved——
127Organizationally Specific可选8.6

RTL 设计提示：TLV 解析器

  • 硬件解析器应顺序读取 2-byte TLV 头，提取 Type（7b）和 Length（9b）
  • 用 Length 字段跳转至下一个 TLV，无需解析未知 TLV 内容
  • Type=0（End）时停止解析；Type=127 时继续解析 OUI+subtype
  • 验证总长度不超出帧边界

5. 各 TLV 详解 (Clause 8.5–8.6)

5.1 End Of LLDPDU TLV (Clause 8.5.1)

  • Type = 0, Length = 0
  • 2 个八位组，全零：0x00 0x00
  • 标记 TLV 序列结束，防止将填充字节解析为 TLV

5.2 Chassis ID TLV (Clause 8.5.2)

位置：必须是 LLDPDU 中的 第一个 TLV。

[ TLV Header (2B) ] [ chassis ID subtype (1B) ] [ chassis ID (1..255B) ]
  • Information String Length = 1 + length(chassis ID)，范围 2 到 256
  • 每个 LLDPDU 中恰好一个 Chassis ID TLV
  • 值在端口运行期间必须保持不变

Chassis ID Subtypes (Table 8-2)

Subtype基础RTL 相关性
4MAC address硬件最常见
5Network addressIPv4/IPv6 + AFN 前缀
7Locally assigned用户自定义字符串/二进制
其他—软件处理为主

Network address 编码（subtype 5）：

  • 八位组 1：IANA Address Family Number
  • 八位组 2..n：网络字节序的地址值

5.3 Port ID TLV (Clause 8.5.3)

位置：必须是 LLDPDU 中的 第二个 TLV。

[ TLV Header (2B) ] [ port ID subtype (1B) ] [ port ID (1..255B) ]
  • Information String Length = 1 + length(port ID)，范围 2 到 256
  • 每个 LLDPDU 中恰好一个 Port ID TLV
  • 必须非空；值在端口运行期间保持不变

Port ID Subtypes (Table 8-3)

Subtype基础
3MAC address
4Network address
7Locally assigned
其他软件处理为主

5.4 Time To Live TLV (Clause 8.5.4)

位置：必须是 LLDPDU 中的 第三个 TLV。

[ TLV Header (2B) ] [ TTL (2B, unsigned) ]
  • Information String Length = 2
  • TTL 范围：0 到 65535 秒
  • TTL = 0：shutdown 帧 — 接收方必须删除该 MSAP 的所有信息
  • TTL > 0：正常帧 — 接收方替换该 MSAP 的所有现有信息
关键规则：TTL=0 的 shutdown 帧只包含强制 TLV（Chassis ID + Port ID + TTL=0），不含任何可选 TLV。

5.5 Port Description TLV (Clause 8.5.5)

  • Type = 4，可变长 UTF-8 字符串
  • 每个 LLDPDU 最多一个

5.6 System Name TLV (Clause 8.5.6)

  • Type = 5，可变长 UTF-8 字符串（建议使用 FQDN）
  • 每个 LLDPDU 最多一个

5.7 System Description TLV (Clause 8.5.7)

  • Type = 6，可变长 UTF-8 字符串
  • 每个 LLDPDU 最多一个

5.8 System Capabilities TLV (Clause 8.5.8)

[ TLV Header (2B) ] [ system capabilities (2B) ] [ enabled capabilities (2B) ]
  • Type = 7，Information String Length = 4
  • 两个 16-bit 位图

Capability Bits (Table 8-4)

Bit能力
0Other
1Repeater
2MAC Bridge component
3802.11 Access Point
4Router
5Telephone
6DOCSIS cable device

8C-VLAN component

验证规则：如果 enabled capabilities 中某位被置位但 system capabilities 中对应位未置位，该 TLV 出错，应被丢弃。

5.9 Management Address TLV (Clause 8.5.9)

[ TLV Header (2B) ]
[ mgmt addr string length (1B) ]
[ mgmt addr subtype (1B) ]
[ mgmt addr (1..31B) ]
[ interface numbering subtype (1B) ]
[ interface number (4B) ]
[ OID string length (1B) ]
[ OID (0..128B) ]
  • Type = 8
  • Management address string length = 1 + length(mgmt addr)，最大 31
  • Interface numbering subtype：1=Unknown, 2=ifIndex, 3=system port number
  • Interface number：4 个八位组；subtype=Unknown 时设为 0
  • OID length = 0 表示 OID 不存在
  • 至少应包含一个 Management Address TLV；允许多个，但地址必须唯一

验证：TLV info string length == mgmt addr string length + OID string length + 7。若不正确，忽略并终止该 TLV 的处理。

5.10 Organizationally Specific TLVs (Clause 8.6)

[ TLV Header (2B) ] [ OUI (3B) ] [ subtype (1B) ] [ info string (0..507B) ]
  • Type = 127
  • OUI：3 个八位组（IEEE 分配）
  • Subtype：1 个八位组，由组织定义
  • 信息字符串最大 507 个八位组（以适应 Type 127 的 511 八位组 TLV info string 限制）

RTL 设计提示：Org TLV 存储

  • 硬件无法预知所有 Type 127 TLV 的语义
  • 建议按 (OUI, subtype) 索引存储原始字节
  • 软件通过 (OUI, subtype) 查找并解释内容
  • 限制每端口存储的 Org TLV 数量以节省资源

6. LLDPDU 验证规则 (Clause 9.2.7.7)

6.1 强制 TLV 验证 (rxProcessFrame)

步骤检查项失败动作
第 1 个 TLVType 必须为 1 (Chassis ID)丢弃帧，inc statsFramesDiscardedTotal, statsFramesInErrorsTotal, badFrame=TRUE
第 1 个 TLVLength 必须为 2 < n < 256同上丢弃
第 2 个 TLVType 必须为 2 (Port ID)同上丢弃
第 2 个 TLVLength 必须为 2 < n < 256同上丢弃
第 3 个 TLVType 必须为 3 (TTL)同上丢弃
第 3 个 TLVLength 必须 >= 2同上丢弃
第 3 个 TLV提取前 2 个八位组作为 rxTTL若 rxTTL==0：shutdown 帧，传递 MSAP+rxTTL 给 MIB 管理器，停止验证

6.2 后续 TLV 验证

Type处理
0End Of LLDPDU。将所有已验证 TLV 传递给 MIB 管理器。忽略之后的任何内容。
1–7基本管理 TLV。按通用规则 + 特定 TLV 规则验证。
8–126保留。未识别但假设有效。按 Type 索引存储。inc statsTLVsUnrecognizedTotal。
127组织特定。若 OUI+subtype 被识别 → 按组织规则验证；否则 inc statsTLVsUnrecognizedTotal，假设有效。

6.3 通用验证规则 (Clause 9.2.7.7.2)

  1. 重复强制 TLV（Chassis ID、Port ID、TTL）：丢弃整个帧。
  2. 长度过短（info string length < 定义字段长度之和）：丢弃整个帧。
  3. TLV 特定错误：仅丢弃该 TLV（不丢弃帧）。inc statsTLVsDiscardedTotal。使用 length 字段跳至下一个 TLV。
  4. 字段长度超出范围：仅丢弃该 TLV。跳至下一个 TLV。
  5. TLV 超出帧尾：仅丢弃该 TLV。
  6. End TLV 之后的信息：忽略。

RTL 设计提示：验证流水线

  • 第一阶段：验证强制 TLV（Type 顺序、Length 范围）
  • 第二阶段：顺序解析可选 TLV，用 Length 跳转
  • 错误分级：强制错误 → 整帧丢弃；可选错误 → 单 TLV 跳过
  • 并行计数器更新：statsFramesInTotal 在帧接收时递增；错误/丢弃计数器在验证失败时递增

7.2 定时器规格 (Clause 9.2.2)

  • 分辨率：1 秒
  • 范围：0 < n < 65535 秒
  • 倒计时：当 n > 0 时每个 tick 减 1
  • Tick 间隔：
    • 点对点 LAN：精确 1 秒
    • 共享介质 LAN：0.8 s + random(0.0 到 0.4 s)，平均值 = 1 s

7.4 TX TTL 计算 (Clause 9.2.5.22)

txTTL = min( (msgTxInterval × msgTxHold) + 1 , 65535 )

若 adminStatus → disabled 或 portEnabled → FALSE：txTTL = 0。

7.5 发送定时器状态机伪代码 (Clause 9.2.10)

// 每个 txTick 执行一次（1 秒）
IF txTick THEN
    txTick = FALSE

    // 信用累积
    IF txCredit < txCreditMax THEN
        txCredit++

    // 快速发送处理
    IF txFast > 0 THEN
        dec(txFast)
        txTTR = msgFastTx
    ELSE
        txTTR = msgTxInterval

    // 定时器倒计时
    IF txTTR > 0 THEN
        dec(txTTR)

    // 判断是否需要发送
    IF txTTR == 0 THEN
        IF txCredit > 0 THEN
            txNow = TRUE
        // 否则等待信用累积

    // 新邻居快速启动
    IF newNeighbor THEN
        newNeighbor = FALSE
        IF remote MIB 可以容纳新邻居 THEN
            txFast = txFastInit
            txTTR = msgFastTx
            txNow = TRUE   // 第一次快速发送立即执行

    // 本地变化处理
    IF localChange THEN
        localChange = FALSE
        txFast = txFastInit
        txTTR = msgFastTx
        IF txCredit > 0 THEN
            txNow = TRUE

7.6 发送状态机伪代码 (Clause 9.2.8)

STATE: IDLE（初始状态）

EXIT CONDITIONS:
    IF !portEnabled OR adminStatus == disabled THEN
        GOTO SHUTDOWN

    IF txNow AND txCredit > 0 THEN
        txNow = FALSE
        GOTO TRANSMIT

STATE: TRANSMIT
    IF adminStatus 正在转为 disabled OR !portEnabled THEN
        txTTL = 0
        mibConstrShutdownLLDPDU()
    ELSE IF txFast > 0 THEN
        txTTL = min((msgTxInterval × msgTxHold) + 1, 65535)
        mibConstrInfoLLDPDU()
    ELSE
        txTTL = min((msgTxInterval × msgTxHold) + 1, 65535)
        mibConstrInfoLLDPDU()

    txFrame()
    dec(txCredit)
    statsFramesOutTotal++
    GOTO IDLE

STATE: SHUTDOWN
    // 尝试发送 shutdown LLDPDU
    IF txCredit > 0 THEN
        txTTL = 0
        mibConstrShutdownLLDPDU()
        txFrame()
        dec(txCredit)
    txShutdownWhile = reinitDelay
    GOTO WAIT_FOR_REINIT

STATE: WAIT_FOR_REINIT
    IF txShutdownWhile > 0 THEN
        dec(txShutdownWhile)
    IF txShutdownWhile == 0 THEN
        GOTO IDLE   // 重新初始化

7.7 接收状态机伪代码 (Clause 9.2.9)

STATE: IDLE（初始状态）

EXIT CONDITIONS:
    IF !portEnabled THEN
        rxInitializeLLDP()
        // 清除 remote systems MIB
        // tooManyNeighbors = FALSE
        STAY in IDLE

    IF rcvFrame THEN
        rcvFrame = FALSE
        GOTO PROCESS_FRAME

STATE: PROCESS_FRAME
    rxProcessFrame()   // 按 9.2.7.7 验证 TLV

    IF badFrame THEN
        badFrame = FALSE
        GOTO IDLE

    // 有效帧已处理
    IF rxTTL == 0 THEN
        // Shutdown 帧
        mibDeleteObjects(MSAP)
        somethingChangedRemote()
    ELSE
        // 正常帧
        IF MSAP 存在于 remote MIB 中 THEN
            IF TLV 值与存储值不同 THEN
                rxChanges = TRUE
                mibUpdateObjects()
                somethingChangedRemote()
            ELSE
                rxChanges = FALSE
        ELSE
            // 新邻居
            IF remote MIB 有足够空间 THEN
                rxChanges = TRUE
                tooManyNeighbors = FALSE
                mibUpdateObjects()
                newNeighbor = TRUE
                somethingChangedRemote()
            ELSE
                // 邻居过多
                tooManyNeighbors = TRUE
                tooManyNeighborsTimer = max(tooManyNeighborsTimer, rxTTL)
                // 丢弃帧或驱逐最旧邻居
                statsFramesDiscardedTotal++

    // 刷新老化定时器
    rxInfoTTL = rxTTL
    GOTO IDLE

7.8 somethingChangedLocal() 过程 (Clause 9.2.7.8)

somethingChangedLocal():
    localChange = TRUE
    txFast = txFastInit    // 触发快速发送周期
    // 通知 PTOPO MIB 管理器和其他可选 MIB 管理器

7.9 LLDPDU 过长处理 (Clause 9.2.7.2)

在 mibConstrInfoLLDPDU() 期间：

  1. 若选中的 TLV 超出最大 LLDPDU 长度：递增 lldpduLengthErrors。
  2. 仅发送强制 TLV（Chassis ID + Port ID + TTL）。
  3. 按顺序追加可选 TLV，直到达到长度限制。
  4. 若空间允许，可选择性追加 End Of LLDPDU TLV。
