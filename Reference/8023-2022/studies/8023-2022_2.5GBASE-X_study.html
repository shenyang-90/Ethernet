1. 协议概述

2.5GBASE-X 是 2.5 Gb/s BASE-X PHY 的 PCS 与 PMA 子层规范，采用与 Clause 36 (1000BASE-X) 完全相同的 8B/10B 编码。服务接口为 XGMII（Clause 46 定义），名义速率为 78.125 Msymbols/s ± 100 ppm。

核心特性：XGMII 32-bit 接口 → Word Encode → 2.5GPII → 8B/10B Encode → PMA 串行化；接收方向逆序处理。

1.1 子层结构

子层功能接口时钟/速率
RS (Reconciliation)MAC 与 XGMII 适配XGMII78.125 MHz DDR (32-bit)
PCS8B/10B 编解码、同步、LPIXGMII / 2.5GPII78.125 MHz (byte)
PMA串行化、码组对齐PMD312.5 MHz (10-bit) / 3.125 GHz serial
PMD光电转换、线缆驱动MDI—
2.5GPII 是 PCS 内部接口，不可见、无外部意义。每符号 1 byte + 1-bit enable + 1-bit error，速率 78.125 Msymbols/s。

RTL 提示：Word Encode 实现

  • 每个 XGMII 时钟周期处理 4 lane × 1 byte = 32 bit
  • Sequence ordered set ||Q|| 需要两个 XGMII 周期完成：周期1输出 S0/S1，周期2输出 S2/S3
  • 用 1-bit 状态寄存器 wencode_state 区分 SEQ1/SEQ2
  • LPI 由四个 lane 同时发送 /L/ 控制字符触发

3. 8B/10B 传输码

2.5GBASE-X 采用与 1000BASE-X (Clause 36) 完全相同的 8B/10B 编码。PCS 将 2.5GPII byte 映射为 10-bit code-group， Running Disparity (RD) 跟踪机制也完全一致。

3.1 核心规则

  • RD 初始为负 (RD-)
  • 每个 code-group 根据当前 RD 选择编码（正/负码）
  • 数据码-group (/Dx.y/) 和特殊码-group (/Kx.y/) 均来自标准 8B/10B 表
  • Comma (/K28.5/) 用于码组边界对齐：bit pattern 0011111 或 1100000 (bits a–f)

3.2 常用 Ordered Sets

Ordered SetCode-Group 序列用途
||I||/K28.5/D16.2/ 或 /K28.5/D5.6/Idle (维持同步)
||S||/K27.7/Start-of-Frame
||T||/K29.7/End-of-Frame
||R||/K23.7/End-of-Frame Carrier Extend
||V||无效码接收错误指示
||Q||/K28.5/W/K28.5/W/K28.5/W/K28.5/W/Sequence (XGMII 映射)
||LI||/K28.5/D0.0/ (tx) /K28.5/D1.0/ (tx)LPI 请求/唤醒 (EEE)

RTL 提示：8B/10B 编解码器复用

  • 可直接复用现有 1000BASE-X (Clause 36) 或 Fibre Channel 的 8B/10B 编解码模块
  • 只需确保 RD 状态在每个 code-group 后正确更新
  • 解码器需检测无效码-group (not_in_table) 并上报

4. PCS 同步状态机

PCS Synchronization process 负责建立 code-group 边界，并监测通道可靠性。状态机与 Clause 36 的同步机制相同，使用 sync_status 标志指示同步状态。

4.1 同步建立流程

  1. Comma 检测：在串行比特流中搜索 /K28.5/ 的 comma 模式 (0011111 或 1100000)
  2. 码组对齐：一旦检测到 comma，即确定 10-bit 边界
  3. 有效码验证：连续接收有效 code-group（包括 Idle ordered sets）
  4. sync_status = OK：当通道稳定后，PCS 开始正常接收数据

4.2 失步处理

条件行为
检测到无效 code-group 或 comma 丢失增加错误计数器
连续错误超过阈值sync_status = FAIL，重新启动 comma 搜索
失步期间PCS 向 XGMII 输出 Carrier Extend (/R/) 或 Idle
注意：2.5GBASE-X 没有 10GBASE-R 的 block sync 机制，而是依赖 8B/10B 的 comma 对齐。comma 密度足够高（Idle 中每 2 个 code-group 有一个 /K28.5/），锁定速度快。

5. EEE LPI 支持 (可选)

2.5GBASE-X 可选支持 Energy-Efficient Ethernet (Clause 78)。LPI 请求/指示通过 2.5GPII 的 LPI 编码传递，PCS 负责在 XGMII 和 PMA 之间转换 LPI 信号。

5.1 LPI 编码

方向信号编码
TXtx_lpi_activeXGMII 四 lane 发 /L/ → 2.5GPII 四 symbol 发 LPI (0x01)
RXrx_lpi_active收到连续 LPI code-groups → 2.5GPII LPI → XGMII /L/

5.2 LPI 状态机要点

  • TX LPI：收到 LPI 请求后，PCS 完成当前帧发送，然后发送 Sleep 序列进入 Quiet 状态
  • RX LPI：检测到 LPI 后，PCS 向 RS 声明 rx_lpi_active，并监测 Wake 序列以退出 LPI
  • Refresh：在 LPI 期间，定期发送 Refresh 序列以维持通道对齐和时钟恢复

RTL 提示：EEE 实现

  • 如果不支持 EEE，可忽略 LPI 编码，将 /L/ 视为普通 Idle 处理
  • 支持 EEE 时，需要额外的 LPI TX/RX 状态机，处理 sleep、quiet、refresh、wake 时序
  • LPI 状态机与 Clause 36 的 EEE 扩展相同，可参考 1000BASE-X EEE 实现

6. PMA 功能

6.1 服务原语

原语方向数据说明
PMA_UNITDATA.requestPCS → PMAtx_code-group<9:0>发送 10-bit code-group
PMA_UNITDATA.indicationPMA → PCSrx_code-group<9:0>接收 10-bit code-group
PMA_TXQUIET.requestPCS → PMAtx_quiet (bool)EEE quiet 请求
PMA_RXQUIET.requestPCS → PMArx_quiet (bool)EEE quiet 请求

6.2 串行化与码组对齐

  • Transmit：将 10-bit tx_code-group 串行化为比特流，LSB (bit 0) 先发送
  • Receive：将串行比特流反串行化为 10-bit rx_code-group
  • Code-group slipping：PMA 可在接收端进行 ±1 bit 的滑动调整，以帮助 PCS 的 comma 对齐

6.3 可选 PRBS9 测试码型

PMA 可选生成 PRBS9 测试码型（多项式 1 + x⁵ + x⁹）用于发送方向的测试。实现此功能需通过管理接口使能。

7.2 时钟域

时钟域频率用途
xgmii_clk78.125 MHzXGMII 32-bit DDR 接口
pcs_byte_clk78.125 MHz2.5GPII 8-bit 处理

时钟关系：xgmii_clk 与 pcs_byte_clk 通常同源（由 PHY 的 RX_CLK 或内部 PLL 产生）。pma_ser_clk 是 pcs_byte_clk 的 4 倍频。所有时钟应来自同一 PLL 以保证相位关系。

7.3 关键设计注意事项

跨时钟域

  • TX 方向：XGMII → PCS → PMA 是同步路径，无需 CDC
  • RX 方向：PMA 从串行数据恢复时钟 (CDR)，通常使用弹性 FIFO (Elastic Buffer) 将 PMA 时钟域数据转到 PCS 时钟域
  • 弹性 FIFO 深度需考虑 ±100 ppm 频差

8B/10B 编解码面积优化

  • 8B/10B 编码可用纯组合逻辑查表实现（256 数据 + 12 特殊码 × 2 RD 状态 = 536 条目）
  • 解码器需要 RD 跟踪寄存器，面积较小
  • 如果同时实现 1000BASE-X 和 2.5GBASE-X，可复用同一 8B/10B 模块，仅需调整接口速率
