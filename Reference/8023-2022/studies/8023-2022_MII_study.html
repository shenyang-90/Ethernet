1. MII — Media Independent Interface (Clause 22)

1.1 Overview

The MII provides a simple, inexpensive interconnection between the MAC sublayer and PHYs for data transfer at 10 Mb/s and 100 Mb/s, plus a two-wire management interface (MDC/MDIO). Key characteristics:

  • 4-bit wide independent transmit and receive data paths
  • TTL signal levels (5 V or 3.3 V tolerant)
  • Supports both half-duplex and full-duplex operation
  • TX_CLK sourced by PHY; RX_CLK sourced by PHY (recovered or nominal)

1.4 Signal Timing Relationships

1.4.1 Transmit Path (Synchronous to TX_CLK)

  • TX_EN: Asserted synchronously with the first nibble of preamble; remains asserted while all nibbles are presented; negated before the first TX_CLK following the final nibble.
  • TXD[3:0]: Transition synchronously with TX_CLK. Accepted by PHY on each TX_CLK rising edge where TX_EN is asserted.
  • TX_ER: Transition synchronously with TX_CLK. When asserted while TX_EN is also asserted, the PHY emits invalid symbols within the frame.

1.4.2 Receive Path (Synchronous to RX_CLK)

  • RX_DV: Asserted synchronously with RX_CLK from the first recovered nibble through the final recovered nibble; negated before the first RX_CLK following the final nibble. Must encompass the complete frame starting no later than SFD.
  • RXD[3:0]: Transition synchronously with RX_CLK. Valid while RX_DV is asserted.
  • RX_ER: Asserted for one or more RX_CLK periods to indicate an error in the currently transferred frame. While RX_DV is deasserted, RX_ER has no effect on the RS (except for specific encodings like LPI or False Carrier).

1.4.3 CRS and COL Timing

  • CRS assertion: PHY asserts CRS when either the transmit or receive medium is non-idle. CRS shall remain asserted throughout the duration of a collision condition.
  • CRS deassertion: PHY deasserts CRS when both transmit and receive media are idle.
  • COL assertion: PHY asserts COL upon detection of a collision and remains asserted while the collision condition persists. In 10 Mb/s operation, COL is asserted in response to a signal_quality_error message from the PMA.
  • Neither CRS nor COL have a required synchronous relationship to TX_CLK or RX_CLK.

1.5 Nibble Ordering on TXD[3:0] / RXD[3:0]

For the MII, each octet is transmitted and received as two nibbles with low-order nibble first:

  • Bits 0–3 of the octet → first nibble transmitted/received (corresponds to TXD[3:0] / RXD[3:0])
  • Bits 4–7 of the octet → second nibble transmitted/received (corresponds to TXD[3:0] / RXD[3:0])

TXD[0] and RXD[0] are the least significant bits. The SFD (0xD5) is transmitted as nibbles 0x5 (first) then 0xD (second).

                        |  low nibble  |  high nibble  |
MII Nibble Stream:     TXD[3:0]=D3..D0   TXD[3:0]=D7..D4

1.6 TX_ER Propagation

When TX_ER is asserted for one or more TX_CLK periods while TX_EN is also asserted, the PHY shall emit one or more symbols that are not part of the valid data or delimiter set somewhere in the frame being transmitted. The relative position of the error within the frame need not be preserved.

Assertion of TX_ER does not affect transmission when TX_EN is deasserted. At 10 Mb/s (except 10BASE-T1L/T1S), TX_ER assertion has no effect.

RTL Design Note: A repeater that detects RX_ER during frame reception may propagate the error to its output ports by asserting TX_ER during transmission of that frame. This requires the RS to support TX_ER generation even though the MAC itself has no mechanism to deliberately corrupt data.

1.7 RX_ER — MII Error Indication

RX_ER is asserted by the PHY for one or more RX_CLK periods to indicate that an error (coding error or any PHY-detectable error) was detected somewhere in the frame currently being transferred. If both RX_DV and RX_ER are asserted during frame reception, the RS shall ensure the MAC detects a FrameCheckError in that frame.

While RX_DV is deasserted, RX_ER has no effect on the RS, except when combined with specific RXD values:

2. GMII — Gigabit Media Independent Interface (Clause 35)

2.1 Overview

The GMII extends the MII to support 1000 Mb/s operation. It is based on the MII and uses the same management interface and register set. Key differences from MII:

  • 8-bit wide independent transmit and receive data paths (instead of 4-bit)
  • GTX_CLK is sourced by the Reconciliation Sublayer (not PHY)
  • RX_CLK remains sourced by PHY
  • Supports carrier extension and burst transmission (for half-duplex Gigabit)

Key RTL Design Point: In GMII, the MAC/RS drives the transmit clock. This is fundamentally different from MII where the PHY drives TX_CLK. RTL designs supporting both modes must mux the clock direction or use separate clock domains.

2.4 Byte Ordering

For GMII, each octet is transferred in parallel on TXD[7:0] / RXD[7:0]. The bit ordering within each byte corresponds directly to the MAC serial bit stream:

  • TXD[0] / RXD[0] = LSB of the octet (first bit transmitted serially)
  • TXD[7] / RXD[7] = MSB of the octet (last bit transmitted serially)

Byte 0 (first octet of preamble) is transferred first, then byte 1, etc. Unlike MII, there is no nibble splitting.

2.6 Carrier Sense and Collision in GMII

In half-duplex mode:

  • CRS is asserted when either transmit or receive medium is non-idle.
  • CRS remains asserted throughout the duration of a collision.
  • COL is asserted upon detection of a collision and remains asserted while the collision persists.

In full-duplex mode:

  • The behavior of CRS and COL is unspecified.
  • COL is still present on the interface for backward compatibility but has no defined function.
  • Most GMII implementations operate exclusively in full-duplex mode.

3. XGMII — 10 Gigabit Media Independent Interface (Clause 46)

3.1 Overview

The XGMII supports 2.5 Gb/s, 5 Gb/s, and 10 Gb/s operation. It is functionally similar to MII/GMII but uses a much wider parallel bus with DDR clocking. Key characteristics:

  • 32-bit data + 4-bit control per direction
  • Double Data Rate (DDR) at 156.25 MHz nominal (10 Gb/s: 1/64 of MAC bit rate)
  • Four lanes of 8-bit data + 1-bit control each
  • Full-duplex operation only
  • Start control character aligned to lane 0

Note: Unlike MII/GMII, XGMII has no CRS, COL, TX_EN, RX_DV, TX_ER, or RX_ER signals. Frame delimitation and error indication are encoded entirely via control characters on the data lanes.

3.7 Link Fault Signaling State Machine

The RS implements a link fault signaling state machine that monitors received Sequence ordered sets and controls transmitted data accordingly:

3.7.1 State Machine Behavior

  • OK state (default): RS sends MAC frames as requested. In the absence of MAC frames, generates Idle control characters.
  • Local Fault detected: When the PHY detects a fault on the receive path, it sends Local Fault ordered sets. Upon receiving four Local Fault sequences (with each pair separated by less than 128 non-fault columns and no intervening different fault sequences), the RS sets link_fault = Local Fault.
  • Local Fault response: The RS continuously generates Remote Fault Sequence ordered sets on the transmit path (possibly truncating a MAC frame being transmitted).
  • Remote Fault / Link Interruption received: When the RS receives Remote Fault or Link Interruption ordered sets, it sets link_fault = Remote Fault or Link Interruption and continuously generates Idle control characters on the transmit path.
  • Return to OK: After any interval of 128 columns not containing a fault Sequence ordered set, link_fault returns to OK.

3.8 Inter-Frame Spacing Rules

  • The interpacket gap (IPG) at the XGMII of the receiving RS is minimum 5 octets.
  • The IPG may be changed between transmitting MAC and receiving MAC by RS lane alignment, PHY clock rate compensation, or 10GBASE-W data rate adaptation.
  • The minimum IPG at the XGMII of the transmitting RS is 1 Idle control character between frames, but can be 0 in some cases for clock compensation.
  • When the Terminate control character is in lane 0, 1, or 2, the following lanes in sequence are encoded with Idle.

3.9 Lane Alignment and Deficit Idle Count (DIC)

On transmit, the RS must align the Start control character to lane 0. Two methods are permitted:

Method 1: Always align on 4-byte boundary

The MAC inserts additional Idle characters so that the start of preamble always falls on a 4-byte boundary. This reduces the effective data rate for certain packet sizes.

Method 2: DIC (Deficit Idle Count)

The RS maintains a Deficit Idle Count to sometimes insert and sometimes delete Idle characters:

  • DIC is incremented for each Idle character deleted
  • DIC is decremented for each Idle character inserted
  • DIC is bounded: 0 ≤ DIC ≤ 3
  • DIC is only reset at initialization
  • This may result in inter-frame spacing up to 3 octets shorter than the minimum transmitted IPG specified in Clause 4
DIC Purpose: The DIC mechanism maintains the average data rate while allowing the Start character to always align to lane 0. Without DIC, always padding to 4-byte boundaries would waste bandwidth (~3 bytes per frame average). DIC amortizes the alignment overhead across multiple frames.

4. XAUI / XGXS — 10 Gigabit Attachment Unit Interface (Clause 47)

4.1 Overview

The XGMII Extender (XGXS + XAUI) transparently extends the physical reach of the XGMII and reduces pin count. It is inserted between the RS and the PHY. Key characteristics:

  • 4-lane serial interface at 3.125 Gbaud per lane
  • 8B/10B encoding per lane (same as 10GBASE-X PCS/PMA in Clause 48)
  • Low-voltage differential signaling (AC-coupled)
  • Extends reach from ~7 cm (XGMII) to ~50 cm (XAUI)
  • Independent clocks at DTE XGXS and PHY XGXS

4.2 XAUI Architecture

The XGMII Extender is logically composed of two XGXSs interconnected with XAUI data paths:

  • DTE XGXS: At the RS end; converts XGMII parallel data to 4 serial XAUI lanes
  • PHY XGXS: At the PHY end; converts 4 serial XAUI lanes back to XGMII parallel data
  • Each XGXS is bidirectional, containing both source and destination functionality

4.4 8B/10B Encoding per Lane

Each XGMII byte on a lane is 8B/10B encoded before serial transmission. The 8B/10B code provides:

  • DC balance (running disparity tracking)
  • Rich transition density for clock recovery
  • Special control codes distinct from data codes
  • Error detection (invalid code groups)

4.7 Lane Deskew Mechanism (using /A/ ordered set)

Because the four XAUI lanes may experience different propagation delays, the destination XGXS must deskew the lanes:

  • The source XGXS periodically transmits /A/ ordered sets (Align) on all four lanes simultaneously during inter-frame gaps.
  • The /A/ ordered set consists of /K28.3/ /D6.2/ on each lane.
  • The destination XGXS uses the /A/ ordered set as a deskew reference. It buffers incoming data on each lane and aligns the lanes so that /A/ columns arrive simultaneously.
  • Lane deskew must compensate for the maximum expected differential skew across the four lanes.

RTL Implementation Sketch — Lane Deskew Buffer

// Per-lane elastic buffer for XAUI deskew
// Depth must accommodate max expected lane skew
module xaui_lane_deskew (
    input        rx_clk,
    input        reset,
    input  [3:0] lane_codegroup_valid,
    input  [9:0] lane_codegroup [0:3],   // 8B/10B decoded or raw
    input  [3:0] lane_align_detected,     // /A/ ordered set detected
    output [3:0] lane_aligned_valid,
    output [7:0] lane_aligned_data  [0:3],
    output [3:0] lane_aligned_control
);

// Elastic FIFO per lane (e.g., depth 16)
// Write pointer advances with each valid code group
// Read pointers aligned when /A/ detected on all lanes
// After alignment, read all lanes with common read pointer

localparam FIFO_DEPTH = 16;
localparam PTR_W = 4;

reg [9:0] fifo [0:3][0:FIFO_DEPTH-1];
reg [PTR_W-1:0] wr_ptr [0:3];
reg [PTR_W-1:0] rd_ptr;
reg aligned;

integer i;
always @(posedge rx_clk) begin
    if (reset) begin
        aligned <= 1'b0;
        rd_ptr <= 0;
        for (i = 0; i < 4; i = i + 1) wr_ptr[i] <= 0;
    end else begin
        // Write each lane independently
        for (i = 0; i < 4; i = i + 1) begin
            if (lane_codegroup_valid[i]) begin
                fifo[i][wr_ptr[i]] <= lane_codegroup[i];
                wr_ptr[i] <= wr_ptr[i] + 1'b1;
            end
        end
        // Alignment logic: stall until /A/ seen on all lanes
        if (!aligned && (&lane_align_detected)) begin
            aligned <= 1'b1;
            // Optionally set rd_ptr = min(wr_ptr) - margin
        end
        if (aligned) begin
            rd_ptr <= rd_ptr + 1'b1;
        end
    end
end
endmodule

4.8 Clock Tolerance Compensation (Skip Columns)

Because the source XGXS and destination XGXS may operate on independent clocks (each with ±100 ppm tolerance), the destination XGXS must compensate for clock rate disparity:

  • The source XGXS converts XGMII Idle control characters into 8B/10B Idle sequences (/I/ ordered sets).
  • The destination XGXS adds or deletes Idle columns (skip columns) as needed to compensate for clock rate differences.
  • Maximum clock rate disparity: 200 ppm (±100 ppm at each end).
  • For every 10,000 columns, up to 2 columns may need to be added or deleted.
  • Columns are added/deleted only during inter-frame gaps (Idle sequences).
Clock Tolerance Compensation Math: At 10 Gb/s with 200 ppm max disparity, the rate difference is 2 Mb/s. Since each column is 4 bytes (32 bits), the compensation rate is approximately 2e6 / 32 ≈ 62,500 columns/second, or about 1 column every 16 µs. A typical elastic buffer depth of 4–8 columns is sufficient.

4.9 XGXS PCS Synchronization State Machine

The XGXS PCS implements a synchronization state machine per lane (similar to Clause 48):

  • LOSS_OF_SYNC: Initial state; searching for valid comma (/K28.5/) to establish byte boundary.
  • COMMA_DETECT_x: Comma detected; verifying consistent alignment.
  • SYNC_ACQUIRED_x: Synchronization acquired; monitoring for invalid code groups.

State transitions depend on:

  • valid_codegroup: Received code group is valid 8B/10B.
  • comma_detect: Comma pattern detected (establishes byte boundary).
  • invalid_codegroup: Received code group violates 8B/10B rules.

After a programmable number of consecutive invalid code groups (typically 4), the PCS returns to LOSS_OF_SYNC.

4.10 Code Group Validity Checker

Each XGXS lane independently checks received 10-bit code groups for validity:

  • Running Disparity Error: The received code group does not match the expected running disparity.
  • Invalid Code Group: The 10-bit pattern does not correspond to any valid 8B/10B code (data or control).
  • Comma Misalignment: A comma appears in an unexpected position.

When an invalid code group is detected, the XGXS may:

  • Signal an Error control character (0xFE) on the corresponding XGMII lane
  • Increment a synchronization error counter
  • Transition the PCS sync state machine toward LOSS_OF_SYNC if errors persist

5.4 Deficit Idle Count (DIC) Mechanism

DIC is specified in Clause 4 (MAC frame transmission) and affects the MII/GMII/XGMII timing:

  • The MAC interFrameSpacing parameter is nominally 96 bit times (12 bytes at 8 bits/byte, or 24 nibbles at 4 bits/nibble).
  • At the XGMII, the RS may need to insert or delete Idle characters to align Start to lane 0.
  • The DIC mechanism bounds the cumulative difference between inserted and deleted Idles to [0, 3].
  • DIC ensures that average inter-frame spacing complies with the MAC specification while allowing per-frame variation.
DIC Consequence for RTL: When receiving at the XGMII, the RX IPG may be as short as 5 octets (minimum at receiving RS). When transmitting, the effective IPG may vary by ±3 octets from the MAC's nominal IPG. Any rate-matching FIFO or clock compensation logic must tolerate this variation.

6.5 8B/10B Disparity Tracking in XGXS

6.5.1 Running Disparity Rules

8B/10B encoding maintains DC balance by tracking running disparity (RD):

  • RD starts at negative (–) after reset.
  • Each valid 10-bit code group is either RD– or RD+.
  • After transmitting an RD– code group, RD becomes negative.
  • After transmitting an RD+ code group, RD becomes positive.
  • Most data bytes have two encodings: one for RD– and one for RD+.
  • Special control codes (K-codes) also have RD– and RD+ versions.

6.5.2 Disparity Error Detection

A disparity error occurs when:

  • A received code group does not match the expected RD (e.g., an RD– code is received when RD is currently positive).
  • The received 10-bit pattern does not correspond to any valid RD– or RD+ code group.

RTL Pattern: 8B/10B Encoder with Disparity Tracking

module encode_8b10b (
    input        clk,
    input        reset,
    input  [7:0] data_in,
    input        k_char,         // 1 = control code
    input        disp_in,        // running disparity in: 0=neg, 1=pos
    output [9:0] code_group,
    output       disp_out,       // running disparity out
    output       code_error
);
    // Lookup tables for RD- and RD+ encodings
    // 256 data codes + 12 control codes
    // Use combinatorial logic or ROM

    reg [9:0] codegroup_rd_minus [0:267]; // 256 + 12 control
    reg [9:0] codegroup_rd_plus  [0:267];

    wire [8:0] lookup_addr = {k_char, data_in};

    assign code_group = disp_in ? codegroup_rd_plus[lookup_addr]
                                : codegroup_rd_minus[lookup_addr];

    // Disparity of the selected code group
    // A code group has positive disparity if it has more 1s than 0s
    // Neutral disparity (e.g., /D00.0/) does not flip RD
    wire [3:0] ones = $countones(code_group);
    wire neutral = (ones == 5);
    wire pos_disp = (ones > 5);
    wire neg_disp = (ones < 5);

    assign disp_out = neutral ? disp_in : pos_disp;
    assign code_error = /* invalid combination */ 1'b0;
endmodule

RTL Pattern: 8B/10B Decoder with Disparity Tracking

module decode_8b10b (
    input         clk,
    input         reset,
    input  [9:0]  code_group,
    input         disp_in,
    output [7:0]  data_out,
    output        k_char,
    output        disp_out,
    output        code_error,     // invalid code group
    output        disp_error      // running disparity error
);
    // Reverse lookup: 10-bit -> {k_char, 8-bit data}
    // Two lookup tables: one for RD- input, one for RD+ input

    reg [8:0] decode_rd_minus [0:1023];
    reg [8:0] decode_rd_plus  [0:1023];
    reg       valid_rd_minus [0:1023];
    reg       valid_rd_plus  [0:1023];
    reg       disp_rd_minus  [0:1023];
    reg       disp_rd_plus   [0:1023];

    wire [8:0] decoded = disp_in ? decode_rd_plus[code_group]
                                 : decode_rd_minus[code_group];
    wire valid  = disp_in ? valid_rd_plus[code_group]
                          : valid_rd_minus[code_group];
    wire dflip  = disp_in ? disp_rd_plus[code_group]
                          : disp_rd_minus[code_group];

    assign k_char    = decoded[8];
    assign data_out  = decoded[7:0];
    assign disp_out  = dflip ? ~disp_in : disp_in;
    assign code_error = ~valid;
    assign disp_error = valid && (/* expected disp mismatch */ 1'b0);
endmodule

6.5.3 Disparity Initialization

After reset or loss of sync, RD must be initialized to negative. The /K28.5/ comma has negative disparity (RD–), so the first valid comma received after sync acquisition should match RD–.

6.6 Idle Insertion / Removal Logic

6.6.1 XGMII Idle Handling

The XGMII inter-frame gap consists of Idle control characters (0x07). The RS must:

  • Generate Idle characters when no MAC frame is being transmitted.
  • Insert or delete Idles to align Start to lane 0 (DIC mechanism).
  • Never insert or delete Idles within a frame.

RTL Pattern: XGMII Idle Insertion / DIC

module xgmii_idle_manager (
    input         clk,
    input         reset,
    input         tx_frame_valid,    // MAC has frame to send
    input  [31:0] tx_frame_data,
    input  [3:0]  tx_frame_ctrl,
    output [31:0] xgmii_txd,
    output [3:0]  xgmii_txc,
    output        ready
);

    localparam IDLE_CHAR = 8'h07;
    localparam START_CHAR = 8'hFB;
    localparam TERM_CHAR = 8'hFD;

    reg [1:0] dic;           // Deficit Idle Count: 0 to 3
    reg [1:0] lane_ptr;      // Current lane for next byte (0-3)
    reg       in_frame;

    // State machine for transmit column assembly
    // When frame pending and lane_ptr==0: emit Start + preamble
    // When frame ending: emit Terminate in appropriate lane, Idles after
    // DIC updated when adding or removing Idles between frames

    always @(posedge clk) begin
        if (reset) begin
            dic <= 2'd0;
            lane_ptr <= 2'd0;
            in_frame <= 1'b0;
        end else begin
            if (!in_frame && tx_frame_valid) begin
                // Need Start aligned to lane 0
                if (lane_ptr != 2'd0) begin
                    // Must insert Idles until lane_ptr == 0
                    // OR delete Idles (if dic > 0) to reach alignment sooner
                    if (dic > 0) begin
                        // Delete one idle: decrement DIC, advance lane_ptr faster
                        dic <= dic - 1'd1;
                        lane_ptr <= lane_ptr + 1'd1; // skip one idle slot
                    end else begin
                        // Insert idle: stay in inter-frame, increment DIC
                        dic <= dic + 1'd1;
                        lane_ptr <= lane_ptr + 1'd1;
                    end
                end else begin
                    // Aligned to lane 0: emit Start
                    in_frame <= 1'b1;
                end
            end else if (in_frame && !tx_frame_valid) begin
                // Frame ended, emit Terminate
                in_frame <= 1'b0;
                lane_ptr <= lane_ptr + 1'd1; // Terminate consumes one lane
            end else begin
                // Normal progression
                lane_ptr <= lane_ptr + 1'd1;
            end
        end
    end
endmodule

The XGXS destination may add or delete Idle columns to compensate for clock rate differences:

RTL Pattern: XGXS Clock Compensation FIFO

module xgxsk_clock_comp (
    input        wr_clk,       // source XGXS clock (e.g., 156.25 MHz div)
    input        rd_clk,       // destination XGXS clock (async)
    input        reset,

    input  [31:0] wr_col_data,
    input  [3:0]  wr_col_ctrl,

    output [31:0] rd_col_data,
    output [3:0]  rd_col_ctrl,
    output [4:0]  fifo_level
);
    // Dual-clock FIFO with column width = 36 bits (32 data + 4 ctrl)
    // Depth typically 8-16 columns
    // Clock comp decision: when FIFO level > threshold, delete Idle column
    //                      when FIFO level < threshold, insert Idle column

    localparam FIFO_DEPTH = 16;
    localparam ADD_THRESH = 4;
    localparam DEL_THRESH = 12;

    reg [35:0] fifo [0:FIFO_DEPTH-1];
    reg [3:0]  wr_ptr, rd_ptr;
    reg [3:0]  gray_wr, gray_rd;
    wire [3:0] sync_wr_ptr;

    // Gray code sync from write to read domain
    // ...

                       (wr_col_data == {4{8'h07}});

    always @(posedge wr_clk) begin
        if (reset) begin
            wr_ptr <= 0;
        end else begin
            if (wr_col_valid) begin
                if (level >= DEL_THRESH && is_idle_col) begin
                    // Delete this idle column (don't write)
                end else begin
                    fifo[wr_ptr] <= {wr_col_ctrl, wr_col_data};
                    wr_ptr <= wr_ptr + 1'd1;
                end
            end
        end
    end

    always @(posedge rd_clk) begin
        if (reset) begin
            rd_ptr <= 0;
        end else begin
            if (level <= ADD_THRESH) begin
                // Insert idle column: don't advance read pointer
                rd_col_valid <= 4'b1111;
                rd_col_ctrl  <= 4'b1111;
                rd_col_data  <= {4{8'h07}};
            end else begin
                {rd_col_ctrl, rd_col_data} <= fifo[rd_ptr];
                rd_ptr <= rd_ptr + 1'd1;
            end
        end
    end
endmodule

  • TX_EN assertion aligned to first preamble nibble/byte
  • TX_EN negation before first clock after final nibble/byte
  • RX_DV encompasses complete frame from SFD through CRC
  • RX_ER causes FrameCheckError at MAC
  • CRS remains asserted throughout collision
  • MDIO turnaround handled correctly for read vs write
  • XGMII Start character aligned to lane 0
  • XGMII DIC bounded 0–3
  • XGMII minimum IPG at receiver ≥ 5 octets
  • Link fault state machine transitions verified (OK ↔ Local Fault ↔ Remote Fault)
  • XAUI 8B/10B encoding valid for all data and control codes
  • XAUI running disparity initialized negative
  • XAUI deskew FIFO compensates max skew (≥ 75 ps)
  • XAUI clock compensation handles ±200 ppm disparity
  • All async FIFOs have gray-code pointers and proper depth
  • Lint clean (no combinational loops, no latches, no multi-driven nets)
  • CDC verified with proper constraints (set_max_delay -datapath_only)
Critical RTL Design Rules (from AGENTS.md):
  • Do not guess clock relationships. TX_CLK and RX_CLK have no guaranteed phase relationship. Always treat them as asynchronous unless explicitly designed otherwise.
  • Do not delete legacy signals without confirmation. COL and CRS may appear unused in full-duplex designs but are required for backward compatibility and management loopback modes.
  • Verify with real timing constraints. Do not assume setup/hold margins. Apply correct SDC constraints for MII (10 ns), GMII (2.5/0.5 ns), and XGMII (0.96/0.48 ns).
  • Use standard primitives. For XGMII DDR, use vendor-specific ODDR/IDDR primitives. Do not implement DDR with 2× clocking unless absolutely necessary.

6.10.2 Synchronization Requirements

  • To achieve sync: 4 consecutive valid commas must be detected with correct spacing.
  • To lose sync: 4 consecutive invalid code groups (or disparity errors).
  • Comma pattern: /K28.5/ = 0011111010 (RD–) or 1100000101 (RD+).
  • Comma appears in /I/ and /A/ ordered sets.

RTL Pattern: PCS Synchronization State Machine

module pcs_sync_sm (
    input        clk,
    input        reset,
    input  [9:0] code_group,
    input        code_valid,
    input        comma_detect,
    output reg   sync_status,     // 1 = in sync
    output reg   code_group_align // 1 = aligned
);
    localparam LOSS_OF_SYNC   = 4'd0,
               COMMA_DETECT_1 = 4'd1,
               COMMA_DETECT_2 = 4'd2,
               COMMA_DETECT_3 = 4'd3,
               SYNC_ACQUIRED_1 = 4'd4,
               SYNC_ACQUIRED_2 = 4'd5,
               SYNC_ACQUIRED_3 = 4'd6,
               SYNC_ACQUIRED_3A = 4'd7,
               SYNC_ACQUIRED_4 = 4'd8;

    reg [3:0] state;
    reg [2:0] good_cnt;
    reg [2:0] bad_cnt;

    always @(posedge clk) begin
        if (reset) begin
            state <= LOSS_OF_SYNC;
            sync_status <= 1'b0;
            code_group_align <= 1'b0;
            good_cnt <= 0;
            bad_cnt <= 0;
        end else begin
            case (state)
                LOSS_OF_SYNC: begin
                    sync_status <= 1'b0;
                    if (comma_detect) begin
                        state <= COMMA_DETECT_1;
                        good_cnt <= 3'd1;
                    end
                end
                COMMA_DETECT_1: begin
                    if (code_valid && comma_detect) begin
                        if (good_cnt >= 3) state <= SYNC_ACQUIRED_1;
                        else good_cnt <= good_cnt + 1'b1;
                    end else if (!code_valid) begin
                        state <= LOSS_OF_SYNC;
                    end
                end
                SYNC_ACQUIRED_1: begin
                    sync_status <= 1'b1;
                    code_group_align <= 1'b1;
                    if (!code_valid) begin
                        bad_cnt <= bad_cnt + 1'b1;
                        if (bad_cnt >= 3) state <= LOSS_OF_SYNC;
                    end else begin
                        bad_cnt <= 0;
                    end
                end
                // Additional states for hysteresis...
                default: state <= LOSS_OF_SYNC;
            endcase
        end
    end
endmodule

6.12 MII-to-GMII Adapter RTL

When a MAC supports both MII and GMII, an adapter must handle the width conversion and clock switching:

RTL Pattern: MII/GMII Multiplexed MAC Interface

module mii_gmii_adapter (
    input         clk_125,        // GMII / system clock
    input         clk_25,         // MII 100M clock
    input         clk_2_5,        // MII 10M clock
    input         reset,
    input         gmii_mode,      // 1=GMII, 0=MII
    input  [7:0]  mac_tx_data,
    input         mac_tx_sof,
    input         mac_tx_eof,
    input         mac_tx_valid,
    output [7:0]  mac_rx_data,
    output        mac_rx_sof,
    output        mac_rx_eof,
    output        mac_rx_valid,
    output        mac_rx_error,
    // MII / GMII PHY interface
    output        gtx_clk,        // GMII only (125 MHz)
    output        tx_clk_out,     // MII TX_CLK to PHY (driven by PHY, but buffered here)
    input         tx_clk_in,      // MII TX_CLK from PHY
    output [7:0]  txd,
    output        tx_en,
    output        tx_er,
    input         rx_clk,
    input  [7:0]  rxd,
    input         rx_dv,
    input         rx_er,
    input         crs,
    input         col
);
    // Clock muxing for MII mode
    wire tx_clk_sel = gmii_mode ? clk_125 : tx_clk_in;
    assign gtx_clk = gmii_mode ? clk_125 : 1'b0;

    // TX path: GMII = 8-bit @ 125 MHz; MII = 4-bit @ 25/2.5 MHz
    reg [7:0] txd_reg;
    reg       tx_en_reg;
    reg       tx_er_reg;
    reg       tx_nibble_sel;      // 0=lower nibble, 1=upper nibble

    always @(posedge tx_clk_sel or posedge reset) begin
        if (reset) begin
            tx_nibble_sel <= 1'b0;
        end else begin
            if (gmii_mode) begin
                txd_reg  <= mac_tx_data;
                tx_en_reg<= mac_tx_valid;
                tx_er_reg<= 1'b0; // TX_ER driven by MAC separately if needed
            end else begin
                // MII mode: multiplex 8-bit data into 4-bit nibbles
                if (mac_tx_valid || tx_nibble_sel) begin
                    tx_nibble_sel <= ~tx_nibble_sel;
                    if (!tx_nibble_sel) begin
                        txd_reg[3:0] <= mac_tx_data[3:0]; // low nibble first
                        tx_en_reg    <= mac_tx_valid;
                    end else begin
                        txd_reg[3:0] <= mac_tx_data[7:4]; // high nibble second
                        tx_en_reg    <= mac_tx_valid || (tx_nibble_sel && mac_tx_eof);
                    end
                end else begin
                    tx_en_reg <= 1'b0;
                end
            end
        end
    end

    assign txd  = gmii_mode ? txd_reg : {4'b0, txd_reg[3:0]};
    assign tx_en = tx_en_reg;
    assign tx_er = tx_er_reg;

    // RX path: MII 4-bit to GMII 8-bit assembly
    reg [7:0] rxd_assembled;
    reg       rx_dv_assembled;
    reg       rx_er_assembled;
    reg       rx_nibble_sel;

    always @(posedge rx_clk or posedge reset) begin
        if (reset) begin
            rx_nibble_sel <= 1'b0;
        end else begin
            if (gmii_mode) begin
                rxd_assembled  <= rxd;
                rx_dv_assembled<= rx_dv;
                rx_er_assembled<= rx_er;
            end else begin
                if (rx_dv || rx_nibble_sel) begin
                    if (!rx_nibble_sel) begin
                        rxd_assembled[3:0] <= rxd[3:0];
                        rx_nibble_sel <= 1'b1;
                        rx_dv_assembled <= 1'b0; // byte not complete yet
                    end else begin
                        rxd_assembled[7:4] <= rxd[3:0];
                        rx_nibble_sel <= 1'b0;
                        rx_dv_assembled <= 1'b1; // complete byte
                    end
                    rx_er_assembled <= rx_er;
                end else begin
                    rx_dv_assembled <= 1'b0;
                    rx_nibble_sel <= 1'b0;
                end
            end
        end
    end

    assign mac_rx_data  = rxd_assembled;
    assign mac_rx_valid = rx_dv_assembled;
    assign mac_rx_error = rx_er_assembled;
    assign mac_rx_sof   = rx_dv_assembled && !rx_dv_delayed;
    assign mac_rx_eof   = !rx_dv_assembled && rx_dv_delayed;
endmodule

6.13 XGMII Lane Alignment Logic Detail

The XGMII RS must ensure that the Start control character (0xFB) is always aligned to lane 0. When the MAC presents a frame that would not naturally align to lane 0, the RS inserts or deletes Idle characters:

RTL Pattern: XGMII Transmit Lane Aligner with DIC

module xgmii_tx_aligner (
    input         clk,
    input         reset,
    // MAC interface
    input         mac_tx_valid,
    input  [31:0] mac_tx_data,
    input  [3:0]  mac_tx_ctrl,
    output        mac_tx_ready,
    // XGMII interface
    output reg [31:0] xgmii_txd,
    output reg [3:0]  xgmii_txc
);
    localparam IDLE = 8'h07;
    localparam START = 8'hFB;
    localparam TERM  = 8'hFD;

    reg [1:0] dic;           // Deficit Idle Count: 0..3
    reg [1:0] lane;          // Next lane for data: 0..3
    reg       in_frame;
    reg [1:0] state;
    localparam ST_IDLE = 0, ST_DATA = 1, ST_TERM = 2;

    assign mac_tx_ready = (state == ST_IDLE) && (lane == 2'd0 || dic > 0);

    always @(posedge clk) begin
        if (reset) begin
            dic <= 2'd0;
            lane <= 2'd0;
            in_frame <= 1'b0;
            state <= ST_IDLE;
            xgmii_txd <= {4{IDLE}};
            xgmii_txc <= 4'b1111;
        end else begin
            case (state)
                ST_IDLE: begin
                    if (mac_tx_valid) begin
                        if (lane == 2'd0) begin
                            // Perfect alignment: emit Start in lane 0
                            xgmii_txd <= {mac_tx_data[31:8], START};
                            xgmii_txc <= {mac_tx_ctrl[3:1], 1'b1};
                            lane <= 2'd1;
                            state <= ST_DATA;
                        end else if (dic > 0) begin
                            // Delete an idle to accelerate alignment
                            dic <= dic - 1'd1;
                            lane <= lane + 1'd1;
                            // Stay in ST_IDLE, emit nothing this cycle
                            xgmii_txd <= {4{IDLE}};
                            xgmii_txc <= 4'b1111;
                        end else begin
                            // Insert idle, increment DIC
                            dic <= dic + 1'd1;
                            lane <= lane + 1'd1;
                            xgmii_txd <= {4{IDLE}};
                            xgmii_txc <= 4'b1111;
                        end
                    end else begin
                        xgmii_txd <= {4{IDLE}};
                        xgmii_txc <= 4'b1111;
                    end
                end
                ST_DATA: begin
                    if (!mac_tx_valid) begin
                        // Frame ended: need Terminate
                        xgmii_txd <= {IDLE, IDLE, IDLE, TERM};
                        xgmii_txc <= 4'b1111;
                        lane <= 2'd0; // Terminate consumes lane, next is 0
                        state <= ST_IDLE;
                    end else begin
                        xgmii_txd <= mac_tx_data;
                        xgmii_txc <= mac_tx_ctrl;
                        lane <= 2'd0; // XGMII always 4-lane aligned in data
                    end
                end
                default: state <= ST_IDLE;
            endcase
        end
    end
endmodule
