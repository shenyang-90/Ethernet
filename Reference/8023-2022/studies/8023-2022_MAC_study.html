1. MAC Frame Format

1.1 Packet Layout Overview

A packet consists of a Preamble, SFD, the MAC frame (DA, SA, Length/Type, Data, Pad, FCS), and an optional Extension field (1000 Mb/s half-duplex only). Octets are transmitted top-to-bottom; bits within each octet are transmitted least significant bit (LSB) first.

1.3 DA / SA Address Field Bit Numbering

Each address is 48 bits. The first bit transmitted (bit 0 of the first octet) is the LSB of the first octet. The octets are transmitted in order: octet 0 first, octet 5 last. Within each octet, bits are transmitted LSB first.

Broadcast Address: All 48 bits = 1 (0xFF-FF-FF-FF-FF-FF). Both I/G and U/L bits are 1. All stations shall recognize the broadcast address.
Source Address: I/G bit is reserved and set to 0. U/L bit may be 0 or 1 depending on address administration.

1.4 Length/Type Field Threshold

The two-octet field is interpreted based on its numeric value (first octet is most significant):

  • Length interpretation: Value ≤ 1500 decimal (0x05DC). Indicates the number of MAC client data octets in the basic frame.
  • Type interpretation: Value ≥ 1536 decimal (0x0600). Indicates the EtherType of the MAC client protocol (e.g., 0x0800 = IPv4, 0x86DD = IPv6, 0x8808 = MAC Control).
RTL Trap: Values between 0x05DD and 0x05FF (1501–1535) are technically undefined. Do not use these values. MAC Control uses 0x8808.

1.6 Pad Calculation Formula

From IEEE 802.3-2022 Clause 3.2.8:

padSize = max[ 0, minFrameSize – (clientDataSize + 2 × addressSize + lengthOrTypeSize + crcSize) ]

Where:
  minFrameSize   = 512 bits  (64 octets)
  addressSize    = 48 bits   (6 octets)
  lengthOrTypeSize = 16 bits (2 octets)
  crcSize        = 32 bits   (4 octets)
  clientDataSize = bits of MAC client data supplied by the client

In octets:
  pad_octets = max(0, 46 – client_data_octets)   // for basic frames

For a basic frame, the minimum client data + pad is 46 octets (to make DA+SA+Length/Type+Data+Pad = 60 octets before FCS). With FCS = 4 octets, total = 64 octets = 512 bits.

1.7 Extension Field Conditions

The Extension field is used only in half-duplex mode at 1000 Mb/s. It follows the FCS field and contains non-data extension bits.

  • Length range: 0 to (slotTime – minFrameSize) bits inclusive.
  • slotTime at 1 Gb/s half-duplex = 4096 bit times.
  • minFrameSize = 512 bit times.
  • Max extension = 4096 – 512 = 3584 bits = 448 octets.
The Extension field is not included in the FCS computation. It ensures the carrier event duration is at least one slotTime so that CSMA/CD operates correctly on the desired network topologies.

1.8 VLAN Tag Insertion — Exact TCI Format

A Q-tagged frame carries a 4-octet VLAN tag (IEEE 802.1Q) inserted between the Source Address and the Length/Type field. The tag consists of:

Sub-fieldWidth (bits)Bit PositionDescription

PCP (Priority Code Point)315:13 of TCI802.1p priority 0–7
DEI (Drop Eligible Indicator)112 of TCI0 = not drop eligible, 1 = drop eligible
VID (VLAN Identifier)1211:0 of TCIVLAN ID 0–4095 (0x000 = null, 0xFFF = reserved)

The Tag Control Information (TCI) is the 2 octets following the TPID. The overall VLAN tag increases the maximum client data from 1500 to 1504 octets so that the maximum MAC frame remains 1522 octets (1518 + 4).

2. CRC-32 / FCS

2.1 Generating Polynomial

The Frame Check Sequence is a 32-bit CRC computed over all MAC frame fields except the FCS itself: Destination Address, Source Address, Length/Type, MAC Client Data, and Pad.

Exact generating polynomial (from Clause 3.2.9):

G(x) = x32 + x26 + x23 + x22 + x16 + x12 + x11 + x10 + x8 + x7 + x5 + x4 + x2 + x + 1

In hex representation, the polynomial is 0x04C11DB7. Note: this is the reversed (reflected) polynomial used in many software CRC-32 implementations; Ethernet hardware typically uses the normal (non-reversed) form.

2.2 Mathematical Procedure

  1. The first 32 bits of the frame are complemented (inverted).
  2. The n bits of the protected fields are considered as coefficients of a polynomial M(x) of degree n – 1. The first bit of DA corresponds to the xn–1 term; the last bit of Pad corresponds to the x0 term.
  3. M(x) is multiplied by x32 and divided by G(x), producing a remainder R(x) of degree ≤ 31.
  4. The coefficients of R(x) form a 32-bit sequence.
  5. This bit sequence is complemented to produce the final CRC.

2.3 Bit Ordering on the Wire

  • Each octet of the MAC frame (except FCS) is transmitted LSB first.
  • The 32 bits of the CRC are placed in the FCS field so that the x31 term is the left-most bit of the first octet, and the x0 term is the right-most bit of the last octet.
  • The bits of the CRC are transmitted in the order x31, x30, …, x1, x0.
Critical RTL Trap: Standard software CRC-32 (PKZIP, Ethernet, etc.) uses reflected input and reflected output with final XOR 0xFFFFFFFF, producing a residue of 0xC704DD7B on valid frames. Ethernet FCS uses the same polynomial but with MSB-first transmission within each byte for the FCS field specifically, yielding a verification residue of 0x2144DF1C (a.k.a. the "magic residue") when the FCS is included in the CRC computation over the entire received packet.

2.4 Serial LFSR Implementation

The canonical hardware implementation is a 32-bit LFSR with taps at the polynomial positions.

// 32-bit CRC LFSR (serial, one bit per clock)
// Polynomial: G(x) = x^32 + x^26 + x^23 + x^22 + x^16 + x^12 + x^11 + x^10
//                    + x^8 + x^7 + x^5 + x^4 + x^2 + x + 1
// Initial value: all 1's (0xFFFFFFFF)
// Final XOR: all 1's (0xFFFFFFFF)
// Input bit order: LSB of each data byte first (matches wire order)

module crc32_serial (
    input        clk,
    input        rst_n,
    input        data_valid,
    input        data_bit,   // serial bit stream, LSB first
    output [31:0] crc_out    // final FCS value
);

    reg [31:0] crc;
    wire feedback = data_bit ^ crc[31];

    always @(posedge clk or negedge rst_n) begin
        if (!rst_n)
            crc <= 32'hFFFFFFFF;          // Initial value: all 1s
        else if (data_valid) begin

            crc[1]  <= crc[0]  ^ feedback;
            crc[2]  <= crc[1]  ^ feedback;
            crc[3]  <= crc[2];
            crc[4]  <= crc[3]  ^ feedback;

2.5 Parallel Byte-Wise LFSR Implementation

For high-speed MACs (100M/1G+), a byte-wide (or nibble-wide) parallel CRC update is required. The next-state logic is derived by iterating the serial LFSR 8 times.

// Parallel CRC-32 update for one data byte (LSB-first input)
// data_in[0] is transmitted first on the wire.
module crc32_byte (
    input  [31:0] crc_in,
    input  [7:0]  data_in,
    output [31:0] crc_out
);
    reg [31:0] crc;
    reg [7:0]  d;
    integer i;

    always @(*) begin
        crc = crc_in;
        d   = data_in;
        for (i = 0; i < 8; i = i + 1) begin
            crc = {crc[30:0], 1'b0} ^ ({32{d[0] ^ crc[31]}} & 32'h04C11DB7);
            d   = d >> 1;
        end
    end
    assign crc_out = crc;
endmodule
Implementation Note: The above loop unrolls to pure combinational logic. For a pipelined 1 Gb/s MAC running at 125 MHz (8-bit datapath), this logic comfortably meets timing in modern FPGAs. For 10 Gb/s, a 64-bit parallel CRC is typically used.

3. MAC Transmit State Machine

3.1 Overview

The transmit path comprises Transmit Data Encapsulation (frame assembly, pad insertion, FCS generation) and Transmit Media Access Management (carrier deference, interpacket gap, collision detection, backoff, carrier extension, and bursting).

3.2 Complete State Diagram (Pseudo-code)

STATE IDLE:
    if (transmitEnabled && frameWaiting) {
        attempts = 0;
        transmitSucceeding = false;
        lateCollisionCount = 0;
        deferred = false;
        goto STATE_DEFER;
    }

STATE DEFER:
    if (bursting) {
        // Burst continuation: skip deference, transmit immediately
        frameWaiting = true;
        goto STATE_TRANSMIT;
    }
    if (attempts > 0) {
        BackOff();   // compute and wait random backoff
    }
    frameWaiting = true;
    while (deferring) {
        // wait for medium to become idle
        if (halfDuplex) deferred = true;
    }
    burstStart = true;
    if (burstMode) bursting = true;
    goto STATE_TRANSMIT;

STATE_TRANSMIT:
    lateCollisionError = false;
    StartTransmit();
    frameWaiting = false;
    if (halfDuplex) {
        while (transmitting) {
            WatchForCollision();
        }
        if (lateCollisionError)
            lateCollisionCount = lateCollisionCount + 1;
        attempts = attempts + 1;
        if (transmitSucceeding) goto STATE_DONE_OK;
        if (attempts >= attemptLimit) goto STATE_DONE_EXCESSIVE;
        if (extend && lateCollisionCount > 0) goto STATE_DONE_LATE;
        // collision occurred: send jam then backoff
        goto STATE_BACKOFF;
    } else {
        // Full duplex: no collision handling
        while (transmitting) { /* wait */ }
        goto STATE_DONE_OK;
    }

STATE_BACKOFF:
    // Jam has already been sent by BitTransmitter/StartJam
    // BackOff() schedules retransmission after random delay
    goto STATE_DEFER;

STATE_DONE_OK:
    if (burstMode) burstStart = false;
    return transmitOK;

STATE_DONE_EXCESSIVE:
    return excessiveCollisionError;

STATE_DONE_LATE:
    return lateCollisionErrorStatus;

3.4 InterFrame Gap (IFG)

  • Minimum interPacketGap: 96 bit times for all speeds.
  • In half duplex, timing starts when carrierSense goes false.
  • In full duplex, timing starts when transmitting goes false.
  • Optional robustness measure: reset IFG timer if carrierSense becomes true during the first 2/3 of the gap; do NOT reset during the final 1/3.

RTL Check — IFG Timer

// For 1 Gb/s: 96 bit times @ 125 MHz (8 ns/bit) = 12 clock cycles.
// For 100 Mb/s MII: 96 bit times @ 25 MHz (40 ns/bit) = 24 clock cycles.
// For 10 Mb/s MII: 96 bit times @ 2.5 MHz = 240 clock cycles.
localparam IFG_BITS = 96;
reg [7:0] ifg_counter;
always @(posedge clk)
    if (!rst_n) ifg_counter <= 0;
    else if (tx_state == TX_IFG) ifg_counter <= ifg_counter + 1;
    else ifg_counter <= 0;

3.5 Truncated Binary Exponential Backoff

After a collision, the MAC waits a random integer multiple of slotTime before retransmitting.

Random delay = r × slotTime

where:
    r = uniformly distributed integer in range [0, 2k – 1]
    k = min(n, 10)
    n = current attempt number (1st retry n=1, 2nd retry n=2, ...)

Maximum backoff range:
    Attempt 1:  r ∈ [0, 1]      → 0 or 1 slotTimes
    Attempt 2:  r ∈ [0, 3]      → 0..3 slotTimes
    Attempt 3:  r ∈ [0, 7]      → 0..7 slotTimes
    ...
    Attempt 10+: r ∈ [0, 1023]  → 0..1023 slotTimes
attemptLimit = 16. After 16 failed attempts, the frame is discarded with excessiveCollisionError. The backoff counter must be a true random or pseudo-random number; a simple LFSR is acceptable but must minimize correlation between stations.

3.6 Jam Sequence

  • jamSize = 32 bits for all half-duplex speeds (10M, 100M, 1G).
  • The jam content is unspecified; it may be any fixed or variable pattern.
  • It must NOT be intentionally designed to be the 32-bit CRC value of the partial packet.
  • The jam is not octet-aligned; it is a bit count.

3.8 Carrier Extension (1000 Mb/s Half-Duplex Only)

If a frame is shorter than slotTime bits, non-data extension bits are appended after the FCS so that the total carrier event is at least slotTime bits long.

  • Extension bits are readily distinguished from data bits by the Physical Layer.
  • Max extension length = slotTime – minFrameSize = 4096 – 512 = 3584 bits.
  • The MAC monitors for collisions during extension; a collision after slotTime is a late collision.

3.9 Packet Bursting (1000 Mb/s Half-Duplex Only)

After a successful first frame, the MAC may transmit additional frames without relinquishing the medium.

  • The interpacket gap between burst frames is filled with extensionBits (not idle).
  • burstLimit = 65536 bits (65,536 bit times).
  • Only the first frame of a burst may require carrier extension.
  • Any collision after the first frame (or after slotTime in the first frame) is treated as a late collision.

4. MAC Receive State Machine

4.1 Overview

Receive frame operations comprise Receive Data Decapsulation (address recognition, FCS validation, frame disassembly) and Receive Media Access Management (collision fragment filtering, octet-boundary alignment).

4.2 Complete State Diagram (Pseudo-code)

STATE RX_IDLE:
    if (receiveEnabled) {
        StartReceive();
        goto STATE_RX_SFD;
    } else {
        return receiveDisabled;
    }

STATE RX_SFD:
    // PhysicalSignalDecap discards idle/extension, strips preamble, detects SFD
    PhysicalSignalDecap();
    if (sfd_detected) {
        enableBitReceiver = true;
        extensionOK = true;
        goto STATE_RX_DATA;
    } else if (receiveDataValid == false) {
        // No frame arrived
        goto STATE_RX_IDLE;
    }

STATE RX_DATA:
    while (receiveDataValid && !frameFinished) {
        b = ReceiveBit();
        incomingFrameSize = incomingFrameSize + 1;
        if (b == 0 || b == 1) {
            if (enableBitReceiver) {
                if (incomingFrameSize > currentReceiveBit)
                    extensionOK = false;   // error mapped to data during extension
                incomingFrame[currentReceiveBit] = b;
                currentReceiveBit = currentReceiveBit + 1;
            }
        } else if (!extending) {
            frameFinished = true;   // b is extensionBit after data done
        }
        if (incomingFrameSize >= slotTime)
            extending = false;      // past collision window
    }
    if (enableBitReceiver) {
        frameSize = currentReceiveBit – 1;
        receiveSucceeding = !extending;
        receiving = false;
        goto STATE_RX_FCS;
    } else {
        goto STATE_RX_IDLE;   // frame was not for us or aborted
    }

STATE RX_FCS:
    excessBits = frameSize mod 8;
    frameSize = frameSize – excessBits;   // truncate to octet boundary
    receiveSucceeding = receiveSucceeding && (frameSize >= minFrameSize);
    if (!receiveSucceeding) {
        // Collision fragment or too short
        goto STATE_RX_FAILED;
    }
    // Perform address recognition and FCS check
    status = ReceiveDataDecap();
    if (status == receiveOK)       goto STATE_RX_PASSED;
    if (status == frameCheckError) goto STATE_RX_FAILED;
    if (status == alignmentError)  goto STATE_RX_FAILED;
    if (status == lengthError)     goto STATE_RX_FAILED;
    if (status == frameTooLong)    goto STATE_RX_FAILED;
    goto STATE_RX_FAILED;

STATE RX_PASSED:
    return receiveOK;

STATE RX_FAILED:
    // Invalid frames are discarded; not passed to MAC client.
    // Optionally count in management counters.
    goto STATE_RX_IDLE;

4.4 Frame Length Validation

  • Minimum valid frame size: minFrameSize = 512 bits = 64 octets (from DA through FCS inclusive).
  • Frames shorter than 64 octets are presumed to be collision fragments and are silently discarded.
  • In half-duplex mode at 1 Gb/s, the first frame of a burst must be at least slotTime = 4096 bits long to be accepted; subsequent frames must be at least minFrameSize.
  • In full duplex mode, the shortest valid frame is minFrameSize (64 octets).

4.5 FCS Check at End of Frame

FCS validation is performed by computing the CRC over the received bits from DA through the last data/pad octet, then comparing with the received FCS field.

  • If the computed CRC does not match the received FCS, the frame is marked frameCheckError.
  • If passReceiveFCSMode is enabled, the FCS field is passed to the MAC client along with the frame.

4.7 RX Error Propagation (RX_ER, MII)

The MII/GMII provides RX_ER (Receive Error) to propagate physical-layer errors to the MAC:

  • RX_ER asserted during a frame causes the frame to be marked with an error.
  • In 10/100 MII, RX_ER is synchronous with RX_CLK and RXD[3:0].
  • In GMII (1 Gb/s), RX_ER is synchronous with RX_CLK and RXD[7:0].
  • The RS (Reconciliation Sublayer) maps GMII error indications into the MAC's receive data stream.

STATE PAUSE_RX_WAIT:

5.5 PAUSE Timer Operation

The receiving station maintains a pause timer that decrements once per pause quantum (512 bit times):

  • On receipt of a PAUSE frame, the timer is reloaded with the received pause_time.
  • If pause_time = 0, the timer is cleared and transmission resumes immediately (XON).
  • The timer decrements by 1 every 512 bit times while the link is active.
  • If a new PAUSE frame arrives while the timer is non-zero, the timer is reloaded with the new value (overwriting the old).
  • Transmission of non-control frames is inhibited while pause_active is true.
  • PAUSE frames themselves may be transmitted regardless of the timer state (to send XON).

RTL Check — Pause Timer Reload & Underflow

// Pause timer: counts in units of 512 bit times (1 quantum)
// For 1 Gb/s @ 125 MHz: 512 bits / 8 bits/clk = 64 clock cycles per quantum.
localparam QUANTA_CLKS = 64;   // speed-dependent
reg [15:0] pause_timer;
reg [5:0]  quantum_counter;
reg        pause_active;

always @(posedge clk or negedge rst_n) begin
    if (!rst_n) begin
        pause_timer <= 0;
        pause_active <= 0;
        quantum_counter <= 0;
    end else begin
        if (pause_rx_valid) begin
            pause_timer <= rx_pause_time;      // Reload on any valid PAUSE
            pause_active <= (rx_pause_time != 0);
            quantum_counter <= 0;
        end else if (pause_active) begin
            if (quantum_counter == QUANTA_CLKS - 1) begin
                quantum_counter <= 0;
                if (pause_timer == 0) begin
                    pause_active <= 0;           // Underflow: resume TX
                end else begin
                    pause_timer <= pause_timer - 1;
                end
            end else begin
                quantum_counter <= quantum_counter + 1;
            end
        end
    end
end

  • 10 Mb/s: Minimum spacing between packets can be as low as 47 BT at the AUI receive line due to clock skew and variable delays.

  • 10 Gb/s / 25 Gb/s: Minimum spacing can be as low as 40 BT at the XGMII / 25GMII.

RTL Trap: RX MACs must accept interpacket gaps smaller than 96 BT (down to the limits above) without dropping frames. TX MACs should generate at least 96 BT, but must tolerate shrinkage on the receive path.

7.3 FIFO Depth Calculations for PAUSE Thresholds

PAUSE is used to prevent RX FIFO overflow. The threshold must account for:

  • Round-trip wire delay (link segment + PHY delay).
  • MAC/RS/MAC Control delay (up to 8192 BT = 16 pause_quanta for 10G).
  • PHY PMA/PCS delay (see Clause 44 delay tables).
  • Time to transmit the PAUSE frame (64 bytes minimum + IFG).
  • Time for the link partner to react and stop transmitting.
Worst-case bytes in flight during PAUSE =
    (link_delay_BT + mac_delay_BT + phy_delay_BT) / 8
    + max_frame_size
    + pause_frame_size
    + IFG_bytes

Example for 1 Gb/s full-duplex copper (moderate delay):
    Link delay    ≈ 512 BT  (1 quantum)
    MAC+RS delay  ≈ 512 BT
    PHY delay     ≈ 2048 BT (GMII to MDI and back)
    Total delay   ≈ 3072 BT = 384 bytes
    In-flight     ≈ 384 + 1518 + 64 + 12 ≈ 1978 bytes

Recommended RX FIFO "XOFF" threshold = FIFO_depth – 2048 bytes (margin)
Recommended RX FIFO "XON"  threshold = FIFO_depth – 4096 bytes (hysteresis)

7.6 Minimum Frame Size Enforcement in TX

  • TX MAC must pad any frame with client data < 46 octets so that DA+SA+L/T+Data+Pad = 60 octets before FCS.
  • Pad bytes are arbitrary; commonly 0x00.
  • If the MAC client supplies the FCS (fcsParamPresent = true), the MAC shall not pad; the client is responsible for meeting minFrameSize.
  • SVA assertion: assert property (@(posedge clk) tx_done |-> tx_byte_count >= 64);

7.7 Jumbo Frame Support

IEEE 802.3-2022 does not standardize jumbo frames (> 2000 octets). However, many implementations support them:

  • Maximum non-standard sizes: 9018 bytes (4× standard data + header), 9216 bytes, or 9600 bytes.
  • If jumbo frames are supported, maxFrameSizeLimit must be increased accordingly.
  • FCS coverage remains over the entire frame; CRC-32 does not change.
  • PAUSE quanta remain 512 bit times regardless of frame size.
  • Management counters for oversized frames may need wider fields.
Interoperability Warning: Jumbo frames are not guaranteed to pass through standard-compliant bridges. If your MAC supports jumbo frames, ensure the connected PHY and switch also support the chosen maximum size.

When EEE (Clause 78) is implemented, the MAC may see LPI (Low Power Idle) assertions:

  • The RS asserts PLS_CARRIER.indication(CARRIER_ON) during LPI to prevent the MAC from transmitting.
  • The MAC TX state machine treats this as an extended deferral condition.
  • PAUSE frames should not be sent during LPI; the MAC defers until LPI ends.
  • Wake time (Tw_sys_tx) must be respected before resuming normal transmission.

7.20 BackOff Implementation — Verilog

module backoff_unit (
    input        clk,
    input        rst_n,
    input        collision_detected,
    input  [3:0] attempts,
    input        start_backoff,
    output reg   backoff_done,
    output reg   excessive_collision
);
    localparam MAX_ATTEMPTS = 16;
    localparam MAX_BACKOFF  = 1024;  // 2^10

    reg [9:0]  max_backoff;
    reg [9:0]  random_val;
    reg [15:0] slot_counter;
    reg        backing_off;

    // Truncated binary exponential backoff limit
    always @(*) begin
        if (attempts == 1)       max_backoff = 2;      // 0..1
        else if (attempts <= 10) max_backoff = 10'd1 << attempts; // 2^n
        else                     max_backoff = MAX_BACKOFF;        // 1024
    end

    // Simple LFSR for pseudo-random number (11-bit, taps at 11,9)
    reg [10:0] lfsr;
    always @(posedge clk or negedge rst_n)
        if (!rst_n) lfsr <= 11'h7FF;
        else if (collision_detected)
            lfsr <= {lfsr[9:0], lfsr[10] ^ lfsr[8]};

    always @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            backing_off <= 0;
            backoff_done <= 0;
            excessive_collision <= 0;
            slot_counter <= 0;
        end else begin
            backoff_done <= 0;
            if (start_backoff) begin
                if (attempts >= MAX_ATTEMPTS) begin
                    excessive_collision <= 1;
                end else begin
                    random_val <= lfsr % max_backoff;
                    slot_counter <= 0;
                    backing_off <= 1;
                end
            end else if (backing_off) begin
                // Wait random_val * slotTime bit times
                // slotTime = 512 bits; at 1G = 64 clocks per slotTime
                if (slot_counter >= random_val * 64 - 1) begin
                    backing_off <= 0;
                    backoff_done <= 1;
                end else begin
                    slot_counter <= slot_counter + 1;
                end
            end
        end
    end
endmodule
RTL Trap: The LFSR random number generator above is simplistic. For production, use a larger LFSR (≥16 bits) with good spectral properties, or a true random source (e.g., thermal noise sampler). The standard requires minimizing correlation between stations.

7.21 Envelope Frame and Q-Tagged Frame Handling

Envelope frames (max client data 1982 octets) are intended for higher-layer encapsulations such as Provider Bridges (802.1ad), MACsec (802.1AE), or MPLS.

  • Basic frame: DA(6) + SA(6) + L/T(2) + Data(46–1500) + Pad(0–46) + FCS(4) = 64–1518 octets.
  • Q-tagged frame: DA(6) + SA(6) + TPID(2)=0x8100 + TCI(2) + L/T(2) + Data(46–1504) + Pad(0–42) + FCS(4) = 64–1522 octets.
  • Envelope frame: Same as Q-tagged but Data can be up to 1982 octets, total up to 2000 octets.

7.22 IPG Stretch Mode (10 Gb/s WAN)

For WAN-compatible applications, the MAC may extend the interpacket gap to adapt the average data rate to SONET/SDH rates.

  • ipgStretchRatio = 104 bits for 10 Gb/s (adapts to STS-192).
  • After each frame, the MAC counts bits transmitted. The next IFG is extended by frame_bits / ipgStretchRatio octets.
  • This is only applicable at 10 Gb/s and above in full-duplex mode.
  • Not applicable to 1 Gb/s or standard LAN operation.

7.23 Link Fault Signaling (10 Gb/s+)

At 10 Gb/s and above, the Reconciliation Sublayer supports Local Fault (LF) and Remote Fault (RF) signaling:

  • Local Fault: PHY detects a receive fault; RS substitutes fault sequences on RXD and stops MAC receive.
  • Remote Fault: Received from link partner; indicates partner's receive path is faulty.
  • The MAC should not transmit normal frames during Local Fault; only Idle control characters are sent.
  • PAUSE frames should not be transmitted during fault conditions.
