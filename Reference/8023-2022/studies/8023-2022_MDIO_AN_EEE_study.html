1.4 SGMII Registers (Clause 22 Extension)

Serial GMII (SGMII) typically maps to Clause 22 registers with extensions in Registers 17/18 (or vendor-specific). 2.3 Address-Increment Operations

The post-read-increment-address operation (OP=10) reads the register at the current address register value, then increments the address register by one (unless it contains 65535). This enables burst reads across consecutive registers without separate address frames.

Typical Indirect Read Sequence

// Step 1: Write address to MMD's address register
  ST=00, OP=00 (Address), PRTAD, DEVAD, TA=10, ADDRESS

// Step 2: Read data from that address
  ST=00, OP=11 (Read), PRTAD, DEVAD, TA=Z0, DATA

3.6 Parallel Detection Rules

When the local device has Auto-Negotiation disabled or the link partner does not support AN, Parallel Detection allows detection of 10BASE-T (NLP), 100BASE-TX, or 100BASE-T4 via their respective link integrity signals. A Parallel Detection Fault occurs if:

  • Zero or more than one technology indicates link_status=READY when autoneg_wait_timer expires, OR
  • flp_receive_idle = false at expiration
RTL Note: Parallel Detection is not a full AN exchange. The HCD resolution skips the Acknowledge/Complete Acknowledge states. Implementations must gate the link_fail_inhibit_timer properly per Table 28-9.

4.4 ACK Requirement (37.2.1.6)

The Acknowledge bit shall be set to logic one in the transmitted Config_Reg after the reception of at least three consecutive and consistent /C/ ordered sets from the link partner with the Acknowledge bit set. This is detected by the acknowledge_match function, which requires three matching consecutive rx_Config_Reg<D15:D0> values with Ack=1.

5.8 Half-Duplex Backoff & Arbitration

The AN half-duplex function (Figure 98-10) ensures only one device transmits a DME page at a time. It uses:

  • backoff_timer: Random wait to resolve concurrent transmissions

6.7 EEE Capability Negotiation

EEE capability is advertised during Auto-Negotiation (except fast-wake-only PHYs or PHYs that exchange EEE during link training). EEE is enabled only if both link partners advertise EEE capability for the resolved PHY type. Deep sleep is enabled only if both advertise deep sleep.

6.8 LLDP TLV Timing (78.4.1)

  • LLDPDU with EEE TLV sent within 10 s of dll_enabled && dll_ready asserted
  • Updated LLDPDU sent within 10 s of receiving changed Tw_sys_tx value
  • All fractional values rounded up to nearest integer µs

module lpi_tx_control (
  input        clk,
  input        rst_n,
  input        lpi_request,      // From MAC/RS
  input  [15:0] tw_sys_tx,        // Resolved wake time (µs)
  input        timer_tick_1us,
  output reg   lpi_active,
  output reg   carrier_off,
  output reg   wake_in_progress
);
  localparam [2:0] ACTIVE=0, ASSERT_LPI=1, SLEEP=2,
                   QUIET=3, WAKE=4, WAKE_WAIT=5;
  reg [2:0] state;
  reg [15:0] timer;

  always @(posedge clk or negedge rst_n) begin
    if (!rst_n) begin
      state <= ACTIVE;
      timer <= 0;
      lpi_active <= 0;
      carrier_off <= 0;
      wake_in_progress <= 0;
    end else if (timer_tick_1us) begin
      case (state)
        ACTIVE: begin
          if (lpi_request) begin
            state <= ASSERT_LPI;
            lpi_active <= 1;
          end
        end
        ASSERT_LPI: begin
          // Transmit Ts sleep signal
          state <= SLEEP;
          timer <= 0;
          carrier_off <= 1;
        end
        SLEEP: begin
          // Wait Ts, then enter quiet
          state <= QUIET;
        end
        QUIET: begin
          if (!lpi_request) begin
            state <= WAKE;
            wake_in_progress <= 1;
          end
        end
        WAKE: begin
          // Start wake signal, load timer
          timer <= tw_sys_tx;
          state <= WAKE_WAIT;
        end
        WAKE_WAIT: begin
          if (timer == 0) begin
            state <= ACTIVE;
            lpi_active <= 0;
            carrier_off <= 0;
            wake_in_progress <= 0;
          end else begin
            timer <= timer - 1;
          end
        end
      endcase
    end
  end
endmodule

7.14 DME Page Encoder/Decoder (Clause 98)

HSM DME Transition Generator

// T1 = 30 ns nominal @ 16.667 Mb/s
// For 1 GHz clock: 30 counts per T1
// Clock transitions at odd positions (1,3,5,...,155)
// Data transitions at even positions if data_bit=1

module dme_encoder (
  input        clk_1ghz,      // or equivalent fast clock
  input        rst_n,
  input        start,
  input  [47:0] page_data,
  input  [15:0] crc,
  output reg   tx_transition,
  output reg   tx_polarity,
  output       tx_active
);
  reg [7:0]  pos_cnt;    // 1-157
  reg [5:0]  data_idx;   // 0-63 (48 data + 16 CRC)
  reg [63:0] payload;

  // Start Delimiter pattern for HSM (positions 1-26)
  // Pre-loaded or computed

  always @(posedge clk_1ghz or negedge rst_n) begin
    if (!rst_n) begin
      pos_cnt <= 0;
      tx_transition <= 0;
    end else if (start) begin
      pos_cnt <= 1;
      payload <= {crc, page_data};
    end else if (pos_cnt != 0 && pos_cnt <= 157) begin
      // Generate transition at current position
      if (pos_cnt[0]) begin
        // Odd position: always clock transition
        tx_transition <= 1;
      end else begin
        // Even position: data transition if bit=1
        data_idx <= pos_cnt[7:1] - 1;
        tx_transition <= payload[data_idx];
      end
      pos_cnt <= pos_cnt + 1;
    end else begin
      tx_transition <= 0;
    end
  end
endmodule

  RX_PAGE → Decode DME page, check CRC16

CRC16 check:
  - Polynomial: x^16 + x^15 + x^2 + 1
  - Initialize S[15:0] = 0
  - Process 48 data bits with switch=gen
  - Switch to out, transmit S15...S0
  - Receiver computes same CRC; match = valid page

5.15 Clause 98 Nonce Collision Handling

If a device receives a DME page with good CRC16 and the partner's Transmitted Nonce Field matches the local device's generated nonce, the device must invert T[0] and regenerate T[3:1] randomly. This guarantees nonce_match is never true, preventing deadlock in Master/Slave resolution.

5.16 Clause 98 HSM vs LSM Selection (98.5.6)

A PHY supporting both HSM and LSM must automatically choose the appropriate mode:

  • Attempt HSM first (faster negotiation)
  • If HSM fails (no response within timeout), fall back to LSM
  • 10BASE-T1L PHYs must support LSM; may optionally support HSM
  • 1000BASE-T1, 100BASE-T1, 10BASE-T1S PHYs must support HSM; may optionally support LSM

6.18 EEE Wake Error Handling

Register 3.22 (PCS EEE wake error counter) increments when the PHY fails to exit LPI within the required time. This indicates:

  • Partner violated Tw_sys_tx agreement
  • Local PHY timing degraded (temperature, voltage)
  • Clock drift during LPI mode
Wake errors should trigger alarm thresholds in management software. Excessive wake errors indicate a link reliability issue.
