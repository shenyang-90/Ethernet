1. 协议概述

IEEE Std 802.3-2022 定义了 Ethernet 标准，涵盖从 10 Mb/s 到 400 Gb/s 的多种物理层实现。标准采用分层架构：MAC 子层、Reconciliation 子层（RS）、Media Independent Interface（MII 系列）、Physical Coding Sublayer（PCS）、Physical Medium Attachment（PMA）、Physical Medium Dependent（PMD）。

核心功能：在共享或点对点介质上实现帧的可靠传输；提供 MAC 帧格式、介质访问控制、物理层编码/调制、自动协商、能源管理等功能。

2.2 地址字段格式

bit 47          bit 1   bit 0
[ 46-bit Address ] [U/L] [I/G]
  • I/G (bit 0)：0 = Individual Address，1 = Group Address（多播/广播）
  • U/L (bit 1)：0 = Globally Administered，1 = Locally Administered
  • Broadcast：全 1 (FF-FF-FF-FF-FF-FF)
  • 每个八位组 LSB first 传输

2.3 Length/Type 字段

值范围解释
0x0000 – 0x05DC (≤1500)Length：后续 MAC Client Data 的字节数
0x0600 – 0xFFFF (≥1536)Type：EtherType（如 0x0800=IPv4, 0x8100=VLAN）

2.4 FCS (CRC-32)

生成多项式：

G(x) = x³² + x²⁶ + x²³ + x²² + x¹⁶ + x¹² + x¹¹ + x¹⁰ + x⁸ + x⁷ + x⁵ + x⁴ + x² + x + 1

计算步骤：

  1. 前 32 位（DA 前 4 字节）取反
  2. 受保护字段（DA + SA + Length/Type + Data + Pad）作为 M(x)
  3. M(x) × x³² 除以 G(x)，得余数 R(x)
  4. R(x) 系数取反，即为 FCS
  5. FCS 传输顺序：x³¹ 在前（第一个八位组的 MSB）

RTL 设计提示：CRC-32 实现

  • 可使用 LFSR 并行实现（每时钟处理 1/4/8/32 bit）
  • 常见优化：按字节查表法（256×32 bit LUT）
  • 注意初始值和最终 XOR：802.3 要求前 32 bit 和余数都取反
  • FCS 字节序：传输时 x³¹ 在前，但存储时通常按大端

2.5 最小帧长与 Pad

Pad 长度计算公式：

Pad = max[0, minFrameSize – (clientDataSize + 2×addressSize + 48)] bits

其中 addressSize = 48 bit，minFrameSize 见 Clause 4.4（通常为 512 bit = 64 byte）。

2.6 无效 MAC 帧判定

  • 帧长度与 Length/Type 字段中的 Length 值不一致（Type 解释时忽略此项）
  • 帧长度不是八位组的整数倍
  • CRC 校验失败
无效 MAC 帧的内容 不得 传递给 LLC 或 MAC Control 子层。

3.3 退避算法

r = random(k)  where k = min(n, backoffLimit)
wait_time = r × slotTime

其中 n 为当前冲突次数（从 0 开始），backoffLimit = 10。第 10 次及以后的冲突，k 固定为 1024。

3.4 全双工操作

全双工模式下：

  • CSMA/CD 算法禁用（carrierSense 和 transmitDeference 不活动）
  • 无碰撞检测，无退避
  • MAC 可连续发送，仅需满足 interFrameGap
  • 需要 PAUSE 帧进行流量控制（见 Clause 31）

RTL 设计提示：MAC 核心设计

  • 现代实现几乎全部使用 全双工，CSMA/CD 逻辑可作为可选项或完全省略
  • TX 路径：添加 Preamble/SFD → 计算并追加 FCS → 插入 Pad（若需要）
  • RX 路径：检测 SFD → 提取 DA/SA/Length-Type/Data → 验证 FCS → 去除 Pad
  • interFrameGap 用计数器实现，对接 MII 的 TX_EN 时序
  • 地址过滤：可选实现 hash 表或 CAM 用于多播/单播过滤

RTL 设计提示：MII/GMII/XGMII 接口实现

  • MII：4-bit 数据在 25 MHz 采样，跨时钟域到 MAC 的更快时钟
  • GMII：8-bit 数据在 125 MHz，通常直连 FPGA 的 IO，需要 IOB 寄存器满足时序
  • XGMII：32-bit DDR @ 156.25 MHz，需要专用 IO 或 XGXS 扩展到 XAUI
  • 全双工模式下 CRS/COL 可忽略，简化设计
  • 注意 TX_CLK 和 RX_CLK 可能不同频（尤其是 100M 自协商后），需要异步 FIFO

RTL 设计提示：MDIO 控制器

  • Clause 22 和 Clause 45 可共用同一个 bit-bang FSM：32-bit preamble → 2-bit ST → 2-bit OP → 5-bit addr → 5-bit reg/dev → 2-bit TA → 16-bit data
  • MDC 最大频率 ≤ 2.5 MHz (周期 ≥ 400 ns)
  • Clause 45 需要先发送 Address 帧设置寄存器地址，再发送 Read/Write 帧访问数据
  • MDIO 为双向开漏信号，需配置上拉电阻；RTL 中需要三态控制
  • 对于 32-bit 计数器：读 MSB 会锁存整个 32-bit 值并清零；读 LSB 返回锁存的 LSB

Arbitration 状态机

1. AUTO-NEGOTIATION ENABLE  ──→ mr_autoneg_enable=true
2. TRANSMIT DISABLE          ──→ 启动 break_link_timer (1200–1500 ms)
3. ABILITY DETECT            ──→ 发送 Base Page (tx_link_code_word ← mr_adv_ability)
4. ACKNOWLEDGE DETECT        ──→ 等待 acknowledge_match=true & consistency_match=true
5. COMPLETE ACKNOWLEDGE      ──→ 发送 6–8 个 Ack=1 的突发
6. NEXT PAGE WAIT            ──→ 处理 Next Page 交换
7. LINK STATUS CHECK         ──→ 启动 autoneg_wait_timer (500–1000 ms)
8. PARALLEL DETECTION FAULT  ──→ multiple/single_link_ready 不匹配
9. FLP LINK GOOD CHECK       ──→ 使能 HCD PMA
10. FLP LINK GOOD            ──→ 协商完成

优先级解析：HCD (Highest Common Denominator) = 本地设备和链路伙伴共同支持的优先级最高的技术位。

8.2 流格式

[IDLE] ... [IDLE]  /J/ /K/  <Data code-groups>  /T/ /R/  [IDLE] ... [IDLE]
|<------ IFG ------>||SSD||<------ SDU ------>||ESD||<------ IFG ------>|

8.3 TX 状态机

IDLE: tx_bits = /I/
  TX_EN=TRUE, TX_ER=FALSE → START_STREAM_J

START_STREAM_J: tx_bits = /J/ (SSD1)
  transmitting = TRUE; COL = receiving → START_STREAM_K

START_STREAM_K: tx_bits = /K/ (SSD2) → TRANSMIT_DATA

TRANSMIT_DATA:
  TX_EN=TRUE, TX_ER=TRUE → tx_bits = /H/
  否则 → tx_bits = ENCODE(TXD[3:0])
  COL = receiving
  TX_EN=FALSE → END_STREAM_T

END_STREAM_T: tx_bits = /T/ (ESD1)
  transmitting = FALSE; COL = FALSE → END_STREAM_R

END_STREAM_R: tx_bits = /R/ (ESD2) → IDLE

8.4 RX 状态机

IDLE: receiving = FALSE; RX_DV = FALSE
  监测 rx_bits[9:0] 中 10 bit 内两个非连续 0 → CARRIER DETECT

CARRIER DETECT: receiving = TRUE
  扫描 /I/J/ 或 /J/K/
  /J/K/ 找到 → START_OF_STREAM_J
  错误 SSD → RX_ER=TRUE, RXD=1110, BAD_SSD

START_OF_STREAM_J: RX_DV = TRUE; RXD = 0101 → START_OF_STREAM_K
START_OF_STREAM_K: RXD = 0101 → DATA

DATA:
  rx_bits[9:5] ∈ DATA → RXD = DECODE(rx_bits[9:5])
  /T/R/ (ESD) → END_OF_STREAM
  IDLES → PREMATURE_END
  其他 → RX_ER = TRUE

END_OF_STREAM: receiving = FALSE → IDLE

RTL 设计提示：100BASE-X PCS

  • 5-bit code-group 内部按 MSB-first 传输（bit 4 先，bit 0 后）
  • rx_bits[9:0] 是 10-bit 滑动窗口，用于码组对齐和 ESD 检测
  • 载波检测准则：任意 10 个 code-bit 内两个非连续的 ZERO
  • 通过检测 SSD (/J/K/) 实现码组对齐

9. 1000BASE-X PCS/PMA (Clause 36)

9.1 8B/10B 编码概述

  • Data code-groups：/Dxx.y/ — 256 个有效数据码组
  • Special code-groups：/Kxx.y/ — 12 个有效特殊码组
  • Running Disparity (RD)：Current RD− 或 Current RD+，上电后从负开始
  • Comma：0011111 (comma+) 或 1100000 (comma−)，包含在 /K28.1/、/K28.5/、/K28.7/ 中用于对齐

9.4 PCS 状态机摘要

  • PCS Transmit：编码 GMII 八位组 → 10-bit code-groups；监测 Auto-Negotiation xmit 标志
  • PCS Synchronization：从 PMA 接收 code-groups，通过 comma 检测建立同步，设置 sync_status
  • PCS Receive：解码 code-groups → GMII RXD[7:0], RX_DV, RX_ER
  • Carrier Sense：控制 GMII CRS（半双工需求）

RTL 设计提示：1000BASE-X PCS

  • 码组 bit 传输顺序：a b c d e i f g h j（bit 0=a, bit 9=j）
  • Comma+ (0011111) 必须比 comma− 更频繁或同等频率地传输（用于 /I/ 和 /C/）
  • 10-bit 接口 (TBI) 可选地位于 PMA 服务接口
  • 8B/10B 编解码器可用查找表或组合逻辑实现

11.4 块同步状态机

STATE LOCK_INIT:
  rx_block_lock = FALSE; sh_cnt = 0; sh_invalid_cnt = 0

STATE TEST_SH:
  sh_valid (rx_coded<0> ≠ rx_coded<1>) → VALID_SH
  否则 → INVALID_SH

STATE VALID_SH:
  sh_cnt++
  sh_cnt < 64 → TEST_SH
  sh_cnt == 64 and sh_invalid_cnt == 0:
    rx_block_lock = TRUE → 64_GOOD

STATE INVALID_SH:
  sh_cnt++; sh_invalid_cnt++
  sh_cnt == 64 and sh_invalid_cnt > 0:
    → SLIP (rx_block_lock = FALSE, shift by 1 bit)

STATE 64_GOOD:
  继续测试；发现无效 SH → TEST_SH/INVALID_SH

11.5 BER 监测

  • 125 µs 定时器窗口
  • 统计无效 sync header 数量 (ber_cnt)
  • 若 125 µs 内 ber_cnt == 16：hi_ber = TRUE
  • BER 改善后 hi_ber 解除

12. 10GBASE-T (Clause 55)

12.1 64B/65B 块格式

Bit 0    : Data/Ctrl Header (0=Data, 1=Control)
Bit 1-64 : Payload
  • Data blocks：8 个数据八位组 (D0-D7)
  • Control blocks：8-bit 块类型字段 + 控制码/数据
  • 块类型字段值与 64B/66B 相同

12.2 Scrambler 多项式

PHY 角色多项式
MASTERG(x) = 1 + x³⁹ + x⁵⁸
SLAVEG(x) = 1 + x¹⁹ + x⁵⁸

12.3 CRC8 多项式

C(x) = 1 + x + x⁵ + x⁶ + x⁸
  • 初始化为零
  • 覆盖 50 × 65B blocks = 3250 bits
  • 8 个校验位附加在 50 个块之后

12.4 LDPC 编码

  • 码型：LDPC(1723, 2048) systematic
  • 输入：1723-bit 向量 x
  • 输出：2048-bit 码字 c = x × G
  • 生成矩阵 G 定义在 Annex 55A

12.5 PHY 帧结构

[1 aux bit] + [50 × 65B blocks] + [8 CRC8 bits] = 3259 bits
    ↓
  1536 uncoded bits (3 × 512, mapped to 512 DSQ128 symbols)
+ 1723 coded bits
    ↓
  LDPC encode → 2048 coded bits (4 × 512)
    ↓
  512 groups of (3 uncoded + 4 coded) = 7 bits/DSQ128 symbol
    ↓
  512 DSQ128 2D symbols
    ↓
  256 4D-PAM16 symbols (2 PAM16 per DSQ128)
    ↓
  4 wire pairs × 256 PAM16 symbols

12.6 DSQ128 位映射算法

输入: u0 u1 u2 (3 uncoded), c0 c1 c2 c3 (4 coded)

Step 1:
  x13 = (!u0) & u2
  x12 = u0 XOR u2
  x11 = c0
  x10 = c0 XOR c1
  x23 = (u1 & u2) OR (u0 & !u1)
  x22 = u1 XOR u2
  x21 = c2
  x20 = c2 XOR c3

Step 2:
  x1 = 8*x13 + 4*x12 + 2*x11 + x10
  x2 = 8*x23 + 4*x22 + 2*x21 + x20

Step 3:
  y1 = (x1 + x2) mod 16
  y2 = (-x1 + x2) mod 16

Step 4:
  PAM16_1 = 2*y1 - 15
  PAM16_2 = 2*y2 - 15

12.7 4D-PAM16 映射

  • 512 DSQ128 symbols → 256 4D symbols
  • 每个 DSQ128 提供两个 PAM16 值，映射到同一对线上的两个连续时间周期
  • PAM16 值：{−15, −13, −11, −9, −7, −5, −3, −1, 1, 3, 5, 7, 9, 11, 13, 15}

12.8 训练 Scrambler (PAM2 模式)

角色多项式
MASTER1 + x¹³ + x³³
SLAVE1 + x²⁰ + x³³

12.9 状态机

  • PCS TX：65B blocks → scrambler → CRC8 → LDPC → DSQ128 → 4D-PAM16
  • PCS RX：PAM2 训练模式对齐 → LDPC decode → CRC8 check → descramble → 65B decode
  • block_lock 在 40 个连续 LDPC 帧错误后解除

RTL 设计提示：10GBASE-T PCS

  • 符号周期：1.25 ns（每对线 800 Msymbols/s）
  • 总速率：10 Gb/s over 4 pairs（每对线 2500 Mb/s）
  • LDPC 解码器是最大硬件挑战，需要迭代解码（通常 10-20 次迭代）
  • Tomlinson-Harashima Precoder (THP) 在 PMA TX 中将 PAM16 映射为准连续离散时间值
  • DSQ128 映射可用查找表或组合逻辑实现

13. Energy-Efficient Ethernet (Clause 78)

13.1 LPI (Low Power Idle) 概述

EEE 允许 PHY 在链路空闲时进入低功耗状态。LPI 信号通过 MII/GMII/XGMII 的控制编码传递，PCS 将 LPI 转换为 PHY 特定的低功耗信号。

13.2 LPI 定时参数

参数10M/100M1G10G说明
tw_phy—2.5 µs7.5 µsTX Wake 时间
ts_phy—3.6 µs11.5 µsTX Sleep 时间
tq_phy—2.2 µs7.6 µsTX Quiet 时间
tr_phy—1.4 µs5.5 µsRX Refresh 间隔

13.3 LPI 状态机 (以 10GBASE-R 为例)

TX_ACTIVE → T_TYPE=LI → TX_SLEEP (start tx_ts_timer)
TX_SLEEP → timer done → TX_QUIET (tx_mode=QUIET, start tx_tq_timer)
TX_QUIET → timer done + T_TYPE=LI → TX_ALERT (tx_mode=ALERT)
TX_ALERT → one_us_timer_done → TX_WAKE (tx_mode=DATA, start tx_tw_timer)
TX_WAKE → tx_tw_timer_done → TX_ACTIVE

RX_ACTIVE → R_TYPE=LI → RX_SLEEP (rx_lpi_active=TRUE)
RX_SLEEP → !energy_detect + rx_tq_timer_done → RX_QUIET (rx_mode=QUIET)
RX_QUIET → energy_detect → RX_WAKE (rx_mode=DATA, start rx_tw_timer)
RX_WAKE → rx_tw_timer_done + rx_block_lock → RX_ACTIVE
RX_WAKE → !rx_tw_timer_done + !rx_block_lock → RX_WTF (wake_error_counter++)
RX_WTF → rx_wf_timer_done → RX_LINK_FAIL
不同 PHY 类型的 LPI 编码方式不同：
  • MII/GMII：TX_ER/RX_ER = 1，TXD/RXD = 0x01
  • XGMII：TXC/RXC = 1，TXD/RXD = 0x06 (所有 lane 同时)
  • 1000BASE-X：/LI/ ordered set
  • 10GBASE-R：/LI/ control block

14. 单对以太网 (100BASE-T1 / 1000BASE-T1)

14.1 100BASE-T1 (Clause 96)

  • 编码：Differential Manchester Encoding (DME) + 4B/5B + 17-bit 自同步扰码器
  • 调制：PAM3（3 电平脉冲幅度调制）
  • 速率：100 Mb/s，全双工，单对双绞线
  • PCS：4B/5B 编码 → 17-bit 扰码 → DME 编码
  • PMA：PAM3 符号映射，时钟恢复

14.2 1000BASE-T1 (Clause 97)

  • 编码：80B/81B 编码 + 15-bit side-stream 扰码器 + RS-FEC
  • 调制：PAM3 @ 750 MBd
  • 速率：1 Gb/s，全双工，单对双绞线
  • 帧结构：45 个 80B/81B blocks (3645 bits) + 9 bits OAM + 396 bits RS-FEC parity = 4050 bits/PHY frame
  • 映射：4050 bits → 2700 PAM3 symbols (3B2T mapper)
  • RS-FEC：Reed-Solomon 前向纠错

14.3 Auto-Negotiation for Single Pair (Clause 98)

  • 使用 Differential Manchester Encoding (DME) 页面交换
  • 高速模式：16.667 Mb/s；低速模式：625 kb/s
  • DME 页面：48-bit Auto-Negotiation page，157 个 transition positions
  • 支持 Link Code Word 交换（Nonce, Ack, RF, NP 等字段）

14.4 PoDL (Clause 104)

  • Power over Data Lines：通过单对双绞线同时传输数据和电力
  • 支持 100BASE-T1 和 1000BASE-T1

15. 10BASE-T1S / PLCA (Clause 147)

15.1 10BASE-T1S 概述 (Clause 147)

  • 速率：10 Mb/s，半双工，单对双绞线
  • 拓扑：支持点对点 (point-to-point) 和多点总线 (multidrop) 模式
  • 编码：Differential Manchester Encoding (DME) + 4B/5B + 17-bit 自同步扰码器
  • PLCA：可选的 PHY Level Collision Avoidance (Clause 148)，替代 CSMA/CD
  • 工作模式：
    • 半双工点对点 (Clause 147.7)
    • 全双工点对点 (Clause 147.7，可选)
    • 半双工多点共享介质 (multidrop，Clause 147.8，可选)

15.2 PLCA (Physical Layer Collision Avoidance)

  • BEACON：协调节点发送时序的广播信号
  • COMMIT：节点声明发送意图的信号
  • 节点 ID：每个节点唯一的 ID (0-255)
  • 发送机会：每个节点在分配的时隙内获得发送机会
  • MII 编码：
    • BEACON request：TX_ER=1, TXD=0x02
    • COMMIT request：TX_ER=1, TXD=0x03
    • BEACON indication：RX_ER=1, RXD=0x02
    • COMMIT indication：RX_ER=1, RXD=0x03

15.3 10BASE-T1S PCS/PMA 数字部分

  • 扰码器：17-bit 自同步扰码器（与 100BASE-T1 相同结构）
  • 4B/5B 编码：与 100BASE-X (Clause 24) 相同的编码表
  • DME 编码：差分曼彻斯特编码，自带时钟恢复，低直流漂移
  • 碰撞检测：半双工模式下支持碰撞检测（CSMA/CD 或 PLCA）

16. 2.5GBASE-T / 5GBASE-T (Clause 126)

16.1 2.5GBASE-T / 5GBASE-T 概述 (Clause 126)

  • 2.5GBASE-T：2.5 Gb/s over Cat5e/Cat6，4 对线
  • 5GBASE-T：5 Gb/s over Cat6，4 对线
  • PCS：64B/65B 编码 → 扰码 → CRC8 → LDPC(1723,2048) → PAM16
  • PHY 帧：512 PAM16 symbols over 4 pairs (128 symbols/pair)
  • 映射：4-bit labels (LDPC-encoded) → PAM16 symbols
  • PMA：Tomlinson-Harashima Precoder (THP)，回声消除，NEXT/FEXT 消除

16.2 2.5GBASE-X (Clause 127)

  • 2.5 Gb/s 8B/10B 编码
  • PCS + PMA 数字接口
