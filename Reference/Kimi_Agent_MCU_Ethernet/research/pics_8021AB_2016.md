# IEEE Std 802.1AB-2016 协议分析与 PICS 提取报告

## LLDP (Link Layer Discovery Protocol) - 链路层发现协议

---

## 1. 协议概述

### 1.1 协议范围和目的

IEEE Std 802.1AB-2016 定义了**链路层发现协议（LLDP, Link Layer Discovery Protocol）**，这是一种用于 IEEE 802 局域网的站点和媒体访问控制连接发现的标准协议。LLDP 允许连接到同一 IEEE 802 LAN 的站点向其他相邻站点通告以下信息：

- 系统所提供的主要功能和能力（Capabilities）
- 管理实体（Management Entity）的管理地址
- 站点连接到 IEEE 802 LAN 的接入点标识信息

LLDP 的核心目标是实现**物理拓扑发现（Physical Topology Discovery）**。协议通过将分布式信息存储在标准的 MIB（Management Information Base）中，使网络管理系统（NMS）能够通过 SNMP 等管理协议访问这些信息。

本标准是对 IEEE Std 802.1AB-2009 的修订版本，主要整合了以下内容：
- IEEE Std 802.1AB-2009/Cor 1-2013
- IEEE Std 802.1AB-2009/Cor 2-2015

> **注**：本修订版本不包含任何新功能，仅将之前的勘误内容整合到基础文本中。

### 1.2 LLDP 帧格式和 TLV 结构

#### 1.2.1 LLDPDU 格式

LLDP 数据单元（LLDPDU）的基本格式遵循以下严格顺序：

```
+---------------------------------------------------+
| Chassis ID TLV (Type=1)        - 强制，第一个     |
| Port ID TLV (Type=2)           - 强制，第二个     |
| Time To Live TLV (Type=3)      - 强制，第三个     |
| Optional TLVs (Type 4-8, 127)  - 可选，任意顺序   |
| End of LLDPDU TLV (Type=0)     - 可选，最后       |
+---------------------------------------------------+
```

**LLDPDU 约束条件**：
- 最大长度：由具体传输速率和协议决定的最大信息字段长度（例如 IEEE 802.3 中最大为 1500 字节）
- 三个强制 TLV 必须位于 LLDPDU 开头且顺序固定
- End of LLDPDU TLV（如存在）必须是最后一个 TLV

#### 1.2.2 基本 TLV 格式

每个 TLV（Type-Length-Value）使用统一的基本格式：

```
+--------+--------+----------------------+
| Type   | Length | Information String   |
| 7 bits | 9 bits | (变长)               |
+--------+--------+----------------------+
```

- **TLV Type**（7 bits）：标识特定 TLV 类型
- **TLV Information String Length**（9 bits）：信息字符串长度（字节）
- **TLV Information String**（0-511 字节）：实际数据内容

### 1.3 LLDP-MED 扩展

LLDP-MED（Media Endpoint Discovery）是 TIA（Telecommunications Industry Association）定义的 LLDP 组织特定扩展（基于 OUI = 00-BB-C2），主要用于 IP 电话、视频会议终端等媒体终端设备的发现。**IEEE 802.1AB-2016 标准本身不包含 LLDP-MED 的具体定义**，LLDP-MED 在 TIA-1057 中定义。

标准提供了 Organizationally Specific TLV（Type=127）机制，允许不同组织定义自己的扩展 TLV：
- **IEEE 802.1 组织扩展**：定义于 IEEE Std 802.1Q-2014 Annex D
- **IEEE 802.3 组织扩展**：定义于 IEEE Std 802.3-2012 Clause 79
- **其他组织扩展**：如 IETF、设备厂商自定义等

Organizationally Specific TLV 格式：
```
+--------+--------+--------+------------------+-------------------+
| Type   | Length | OUI    | Org-defined      | Org-defined       |
| (127)  |        | 3 bytes| Subtype          | Info String       |
+--------+--------+--------+------------------+-------------------+
```

### 1.4 车载网络应用分析

#### 1.4.1 在车载 Zonal 架构中的应用

LLDP 对于车载网络（Automotive Ethernet，基于 IEEE 802.1 和 IEEE 802.3）具有以下关键应用价值：

**网络拓扑发现（Topology Discovery）**：
- 自动发现车载网络中的 ECU、交换机、传感器等节点
- 帮助网络管理系统实时了解车辆网络物理拓扑结构
- 支持多 MAC 地址（多 LLDP Agent）的端口操作

**设备自动识别与配置（Auto-Identification & Configuration）**：
- 通过 Chassis ID TLV 识别设备类型和序列号
- 通过 System Capabilities TLV 识别设备功能（如 Bridge、Station Only）
- 通过 Management Address TLV 获取设备管理地址
- 减少车辆下线时的手动网络配置工作

**诊断与故障定位（Diagnostics & Troubleshooting）**：
- 通过 LLDP 远程系统 MIB 监控邻居设备状态变化
- 检测链路故障或设备离线（通过 TTL 超时机制）
- 辅助诊断网络连通性问题
- 支持 shutdown LLDPDU 实现优雅端口关闭通知

**软件实现特性**：
- LLDP 完全可通过软件实现，通常不需要硬件加速
- 各 MCU 通常通过软件协议栈支持 LLDP
- 状态机（Transmit/Receive/Transmit Timer）适合嵌入式实现
- 资源消耗较低，适合 AUTOSAR 等车载软件架构集成

#### 1.4.2 车载场景特殊考虑

| 方面 | 考虑因素 |
|:---|:---|
| **操作模式** | 车载节点通常需要 Tx+Rx 模式以支持双向拓扑发现 |
| **目的地地址** | 使用 Nearest Bridge 地址（01-80-C2-00-00-0E）限制传播范围 |
| **TLV 选择** | 必须包含强制 TLV；建议包含 Management Address TLV |
| **安全性** | LLDP 帧在保护链路上传输，需考虑信息安全风险 |
| **TSN 兼容性** | 与 IEEE 802.1AS（gPTP）、IEEE 802.1Qbv 等 TSN 协议共存 |
| **ASIL 考虑** | LLDP 通常为非安全相关功能，但拓扑信息可能影响安全相关通信路径 |

## 2. PICS 提取（Annex A）

### 2.1 PICS 概览

IEEE Std 802.1AB-2016 在 **Annex A（normative）** 中提供了完整的 PICS（Protocol Implementation Conformance Statement）proforma。PICS 是声明实现符合本标准所必须填写的标准化问卷。

**状态符号说明**：

| 符号 | 含义 |
|:---:|:---|
| **M** | Mandatory - 强制要求 |
| **O** | Optional - 可选 |
| **O.n** | 可选，但至少支持同一数字 n 标记的一个选项 |
| **C** | Conditional - 条件性的 |
| **X** | Prohibited - 禁止 |
| **N/A** | Not Applicable - 不适用 |

| Supplier | （供应商名称） |

| Implementation Name(s) and Version(s) | （实现名称和版本） |
| Other information | （机器/操作系统名称和版本） |

| **custom_tlv** | 自定义组织特定 TLVs | 8.6 | O | Yes / No | 厂商自定义 |

## 3. 协议操作原理摘要

### 3.1 操作模式

LLDP Agent 支持三种操作模式：

| 操作模式 | 发送状态机 | 接收状态机 | 适用场景 |
|:---|:---:|:---:|:---|
| **Tx Only** (仅发送) | 强制 | — | 简单终端设备 |
| **Rx Only** (仅接收) | — | 强制 | 被动监控设备 |
| **Tx + Rx** (收发双向) | 强制 | 强制 | **推荐车载场景** |

### 3.2 关键状态机

1. **发送状态机（Transmit State Machine，9.2.8）**
   - 管理 LLDPDU 的构造和发送
   - 处理正常 LLDPDU 和 Shutdown LLDPDU
   - 受发送定时器状态机控制

2. **接收状态机（Receive State Machine，9.2.9）**
   - 处理接收到的 LLDP 帧
   - 执行帧验证和错误检查
   - 更新 LLDP 远程系统 MIB

3. **发送定时器状态机（Transmit Timer State Machine，9.2.10）**
   - 控制发送时序
   - 管理基于信用的传输策略
   - 处理快速发送初始化（新邻居检测）

### 3.3 定时器参数

| 参数 | 默认值 | 说明 |
|:---|:---:|:---|
| **msgTxInterval** | 30 秒 | 正常发送间隔 |
| **msgTxHold** | 4 | TTL 乘数 |
| **txCreditMax** | 5 | 最大发送信用值 |
| **msgFastTx** | 1 秒 | 快速发送间隔 |
| **txFastInit** | 4 | 快速发送次数 |
| **reinitDelay** | 2 秒 | 重新初始化延迟 |
| **txDelay** | 2 秒 | 连续发送最小间隔 |

### 3.4 目的地 MAC 地址与传播范围

| MAC 地址 | 值 | 传播范围 |
|:---|:---|:---|
| **Nearest Bridge** | 01-80-C2-00-00-0E | 单条物理链路；被所有桥接设备阻止 |
| **Nearest non-TPMR Bridge** | 01-80-C2-00-00-03 | 通过 TPMR；被 C-VLAN/S-VLAN/MAC Bridge 阻止 |
| **Nearest Customer Bridge** | 01-80-C2-00-00-00 | 通过 TPMR 和 S-VLAN；仅被 C-VLAN/MAC Bridge 阻止 |

## 4. 车载 MCU Zonal 控制器实现建议

### 4.1 最小功能集（Minimum Profile）

对于车载 Zonal Controller 的 LLDP 实现，建议至少包含以下功能：

| 类别 | 建议 |
|:---|:---|
| **操作模式** | Tx + Rx（收发双向） |
| **必选 TLV** | Chassis ID, Port ID, Time To Live |
| **推荐可选 TLV** | System Capabilities, Management Address, Port Description |
| **目的地地址** | Nearest Bridge (01-80-C2-00-00-0E) |
| **Chassis ID 子类型** | MAC address (4) 或 Locally assigned (7) |
| **Port ID 子类型** | Locally assigned (7) 或 Interface name (6) |
| **System Capability** | Station Only (bit 8) 或 MAC Bridge (bit 3) |
| **数据存储** | 等效存储（非 SNMP）或轻量级 SNMP Agent |

### 4.2 实现复杂度评估

| 方面 | 评估 |
|:---|:---|
| **软件实现** | 完全可通过软件实现，无需硬件加速 |
| **内存需求** | 低 - 仅需存储本地 MIB 和少量邻居条目 |
| **CPU 占用** | 低 - 状态机简单，定时器驱动 |
| **代码大小** | 小 - 核心状态机约数百行 C 代码 |
| **配置需求** | 支持按端口使能/禁用 TLV 传输 |
| **与 AUTOSAR 集成** | 可作为 EthTSyn 或独立模块集成 |

### 4.3 与 TSN 协议共存

LLDP 在车载 TSN 网络中需要与以下协议共存：
- **IEEE 802.1AS (gPTP)**：时间同步 - LLDP 使用不同的 EtherType (0x88CC vs 0x88F7)，无冲突
- **IEEE 802.1Qbv (TAS)**：时间感知整形 - LLDP 帧需配置适当的门控调度
- **IEEE 802.1CB (FRER)**：帧复制和消除 - LLDP 通常不需要 FRER 保护
- **IEEE 802.1Qci (PSFP)**：逐流过滤和监管 - LLDP 帧（目的地址 01-80-C2-00-00-0E）通常被归类为 SR 类帧

## 5. 总结

IEEE Std 802.1AB-2016 定义的 LLDP 协议是一个轻量级、低复杂度的链路层发现协议，非常适合在车载以太网网络中实现。其核心特点包括：

1. **标准化拓扑发现**：通过强制 TLV（Chassis ID, Port ID, TTL）实现邻居设备自动发现
2. **可扩展信息模型**：通过可选 TLV 和组织特定 TLV 支持丰富的设备信息交换
3. **软件可完全实现**：状态机简单，资源需求低，适合 MCU 嵌入式实现
4. **车载场景适用**：支持物理拓扑发现、设备自动识别和诊断功能
5. **TSN 兼容**：与 gPTP、TAS 等 TSN 协议无冲突，可共存于同一网络

PICS 表格（Annex A）提供了完整的协议符合性声明框架，实现者应根据具体应用场景选择支持的功能子集。对于车载 Zonal Controller，推荐实现 Tx+Rx 操作模式、基本管理 TLV 全集以及 IEEE 802.1/802.3 组织特定 TLV 扩展。
