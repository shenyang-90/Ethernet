1. 协议概述与范围

IEEE 802.1Q-2022 定义了 VLAN Bridges and Bridged Networks 的运作方式。本文档聚焦 RTL 可实现的数据平面，忽略纯控制平面协议（如 RSTP/MSTP 的 BPDU 处理状态机，虽然端口状态对数据平面有直接影响）。

核心数据平面功能：VLAN 标签识别/插入/删除、基于 DMAC+VID 的帧转发决策、FDB 动态学习/静态配置、优先级/Traffic Class 映射、TSN 调度与整形、帧抢占。

字段位宽说明
TPID16 bits0x88E7
PCP3 bits优先级
DEI1 bit丢弃资格

RTL 要点：接收侧需要一个 Tag Parser，按 TPID 顺序检测 0x8100 / 0x88A8 / 0x88E7。发送侧需要 Tag Inserter，根据 egress port 的 AcceptableFrameTypes (Tagged/Untagged/All) 决定是否剥离标签。

4. Forwarding Process (转发流程)

Forwarding Process 是数据平面的核心，定义于 Clause 8.6。每帧的处理管线如下：

接收帧 → [Ingress Filtering 8.6.2] → [Frame Filtering 8.6.3 (FDB 查找)] → [Egress Filtering 8.6.4]
    → [Flow Classification & Metering 8.6.5] → [Queuing 8.6.6] → [Transmission Selection 8.6.8]

4.1 Active Topology Enforcement (8.6.1)

每个端口维护以下控制参数（由 Spanning Tree / 管理配置设置）：

  • enableLearning — 是否允许 MAC 学习
  • enableForwarding — 是否允许转发
  • enableFiltering — 是否基于 FDB 过滤（若禁用则泛洪）

4.2 Ingress Filtering (8.6.2) 与 Egress Filtering (8.6.4)

Ingress Filtering：检查接收端口的 VLAN Member Set。若 VID 不在该端口成员集中，丢弃该帧。

Egress Filtering：检查潜在发送端口的 VLAN Member Set。若 VID 不在发送端口成员集中，从潜在发送集合中移除该端口。

过滤类型检查条件丢弃条件
Ingress FilteringVID ∈ port VLAN Member Set?VID 不在成员集中
Egress FilteringVID ∈ potential_tx_port VLAN Member Set?VID 不在发送端口成员集中

4.3 Frame Filtering (8.6.3) — FDB 查询

Frame Filtering 基于 DMAC + VID (或 FID) 查询 FDB，决定转发端口集合：

FDB 查询结果行为
Static/Dynamic Entry 存在，Port Map 指定单个端口转发到该端口（若不等于接收端口，除非同端口回环允许）
Static/Dynamic Entry 存在，Port Map 指定多个端口转发到多个端口（组播/广播）
无匹配 Entry (Unknown)泛洪到 VLAN 成员集中除接收端口外的所有端口
Static Entry = Filter丢弃
FID (Filtering Identifier)：支持 IVL (Independent VLAN Learning) 和 SVL (Shared VLAN Learning)。IVL 下每个 VID 对应一个 FID；SVL 下多个 VID 可共享同一个 FID。FDB 查找时实际用 DMAC+FID 作为 key。

4.4 Flow Classification & Metering (8.6.5) — PSFP / ATS

Flow Classification 在 Egress Filtering 之后、Queuing 之前执行。支持三种模式：

  • General flow classification (8.6.5.1) — 基于 DMAC/SMAC/VID/Priority 的流量计量
  • PSFP (8.6.5.2.1) — Per-Stream Filtering and Policing (802.1Qci)
  • ATS (8.6.5.2.2) — Asynchronous Traffic Shaping (802.1Qcr)

4.4.1 Stream Filtering (8.6.5.3)

每帧通过 stream_handle (来自 802.1CB Stream Identification) + priority 匹配 Stream Filter Instance Table。

Stream Filter 字段类型说明
stream_filter_identifierinteger表项索引 (0..MaxStreamFilterInstances-1)
stream_handlesingle value or wildcard匹配 802.1CB stream handle
prioritysingle value or wildcard匹配帧优先级
MaximumSDUSizeinteger最大 SDU 字节数，0=禁用
StreamBlockedDueToOversizeFrameEnableboolean超尺寸帧是否阻塞后续帧
stream_gate_identifierinteger指向 Stream Gate Instance Table
flow_meter_instance_identifierinteger (optional)指向 Flow Meter Instance Table (PSFP)
scheduler_instance_identifierinteger (optional)指向 ATS Scheduler Instance Table

匹配规则：帧与 stream_filter_identifier 最小且 stream_handle 和 priority 均匹配的表项关联。可在表尾配置全 wildcard + 永久关闭的 gate，用于丢弃未匹配任何 filter 的帧。

4.4.2 Maximum SDU Size Filtering (8.6.5.3.1)

if (frame_SDU_size > MaximumSDUSize):
    discard(frame)
    NotPassingSDUCount++
    if (StreamBlockedDueToOversizeFrameEnable):
        StreamBlockedDueToOversizeFrame = TRUE  // 后续帧全丢弃，直到管理复位
else:
    PassingSDUCount++

4.4.3 Stream Gating (8.6.5.4)

Stream Gate 决定帧是否通过，并可映射 Priority → IPV (Internal Priority Value)。

4.5 Queuing Frames (8.6.6)

每个端口支持 nTrafficClasses 个队列 (通常 8 个，对应 8 个 priority 值)。帧根据 traffic_class_table[port][priority] 映射到队列。

Default Traffic Class 映射 (Table 8-5)Traffic Class (队列)
Priority 0 (Background)2
Priority 1 (Best Effort)0
Priority 2 (Excellent Effort)1
Priority 3 (Critical Applications)3
Priority 4 (Video, <100ms latency)4
Priority 5 (Voice, <10ms latency)5
Priority 6 (Internetwork Control)6
Priority 7 (Network Control)7
映射表可通过管理配置改写。默认映射体现设计意图：Voice (5) 和 Network Control (7) 映射到最高队列，Background (0) 映射到中间队列，Best Effort (1) 映射到最低队列。

4.6 Transmission Selection (8.6.8)

每个队列独立运行 Transmission Selection Algorithm，决定何时从该队列取帧发送。同一时刻可能有多个队列认为自己可以发送，此时由 frame preemption (6.7) 或严格优先级仲裁决定。

4.6.1 Strict Priority (8.6.8.1)

最简单的算法：队列号越大优先级越高。队列 7 有帧时总是先发送队列 7 的帧。 starvation 风险：低优先级队列可能长期得不到服务。

4.6.2 Credit-Based Shaper (CBS) (8.6.8.2 / 34.3)

为 SR (Stream Reservation) 流量设计的整形器，保证带宽下限。

参数符号单位说明
idleSlopeidleSlopebits/scredit 增长速率
sendSlopesendSlopebits/scredit 消耗速率 (= idleSlope - portTransmitRate)
creditcreditbits当前 credit 值
hiCredithiCreditbitscredit 上限 = maxFrameSize × (idleSlope / portTransmitRate)
loCreditloCreditbitscredit 下限 = -(maxInterferenceSize × idleSlope / portTransmitRate)
// Credit-Based Shaper 伪代码
// 每个 SR 队列独立维护 credit

if (queue 非空 && credit >= 0):
    if (帧正在传输):
        credit = credit + sendSlope × delta_t   // sendSlope 为负
    else:
        // 被更高优先级队列抢占
        credit = credit + idleSlope × delta_t   // credit 增长
else:
    if (queue 空):
        credit = min(0, credit + idleSlope × delta_t)  // 上限为 0
    else:
        // credit < 0，不能发送，credit 持续增长
        credit = credit + idleSlope × delta_t

// 边界: loCredit ≤ credit ≤ hiCredit

RTL Tip: CBS 实现

  • 每个 SR 队列需要一个 credit 寄存器（有符号整数）。
  • 需要一个周期定时器（如每 125μs 一个 tick）来更新 credit。
  • idleSlope 和 sendSlope 以 定点数 形式存储（如 16.16 格式）。
  • 发送决策：当 credit ≥ 0 且队列非空时，该队列可被选中。

4.6.3 ETS (Enhanced Transmission Selection) (8.6.8.3)

ETS 将队列分组为 Traffic Class Groups，组间使用 Strict Priority，组内使用加权轮询 (WRR)。配置参数：

  • etsTrafficClassGroup[n] — 队列 n 属于哪个组
  • etsGroupBandwidthTable[group] — 组的带宽百分比

4.6.4 Scheduled Traffic / Gate Control (8.6.8.4 / 8.6.9)

Scheduled Traffic 通过 Gate Control List 精确控制每个 queue 的 open/close 时间。基于 IEEE 802.1Qbv。

Gate Control 参数说明
AdminControlList / OperControlList管理态/运行态门控列表
AdminBaseTime / OperBaseTimeSchedule 起始时间 (PTP 时间)
AdminCycleTime / OperCycleTime周期时间（有理数，整数分子/分母）
GateEnabled是否启用 scheduled traffic
queueMaxSDU[n]队列 n 的最大 SDU

Gate Control List 中的每个条目为 SetGateStates(GateState, TimeInterval)：

  • GateState — 8-bit bitmap，每位对应一个 queue 的 open(1)/closed(0)
  • TimeInterval — 持续时间 (tick 数，每个 tick = CycleTime/Nanosecond 精度)

4.6.5 ATS Transmission Selection (8.6.8.5)

ATS 队列的传输选择基于 assignedEligibilityTime：队列中帧的 eligibility time 到达后，该队列才可参与竞争。同一端口多个 ATS 队列间按 eligibility time 先后排序。

5. Filtering Database (FDB) — Clause 8.8

FDB 是桥接转发的核心查找表。支持 IVL (Independent VLAN Learning) 和 SVL (Shared VLAN Learning)。

5.1 FDB 表项类型

表项类型ClauseKey内容

5.2 FDB 查询逻辑 (8.8.9)

// 帧转发时的 FDB 查找流程

1. 确定 FID:
   if (IVL mode):
       FID = VID
   else if (SVL mode):
       FID = vlan_to_fid_mapping[VID]  // 多个 VID 可映射到同一 FID

2. 用 {DMAC, FID} 查找 Dynamic Filtering Entry:
   if (命中):
       port_map = entry.port_map
   else:
       // 检查 Static Filtering Entry (用 DMAC+VID)
       if (命中 Static Entry):
           port_map = entry.port_map
       else:
           port_map = ALL_PORTS_EXCEPT_RX  // 泛洪

3. 应用 VLAN Member Set (Egress Filtering):
   for each potential_tx_port:
       if (port not in VLAN[VID].member_set):
           port_map[port] = 0

4. 应用 Static Filtering Entry 的 per-port 控制:
   if (Static Entry 对某端口标记为 Filter):
       port_map[port] = 0
   if (Static Entry 对某端口标记为 Dynamic && Dynamic Entry 未命中):
       port_map[port] = 1  // 泛洪时该端口也参与

5.3 MAC Learning (8.8.3 / 8.10)

当端口处于 Learning 或 Forwarding 状态时，接收到的帧的源 MAC 地址可被学习：

  • 学习条件：enableLearning == TRUE 且端口状态允许
  • 学习 key：{SMAC, FID}（或 {SMAC, VID} 若 IVL）
  • 若 FDB 中已有相同 key 但不同端口：更新端口（move）
  • 若 FDB 已满：可丢弃最老的条目（LRU/age-based）或不学习

5.4 Ageing (8.8.3 / 8.10.2)

动态条目在一段时间无匹配流量后自动删除。

参数默认值说明
Ageing Time300 秒动态 FDB 条目的最大存活时间
// Ageing 逻辑 (简化)
for each dynamic_entry in FDB:
    if (entry.hit == 1):
        entry.age = 0
        entry.hit = 0
    else:
        entry.age += ageing_tick_interval
        if (entry.age >= AgeingTime):
            delete(entry)

RTL Tip: FDB 硬件设计

  • 表结构：使用 CAM/TCAM 或 Hash 表。Hash 表需要处理冲突（chaining 或 cuckoo hash）。
  • Key 宽度：48-bit MAC + 12-bit VID/FID = 60 bits (IVL) 或 48-bit MAC + FID bits。
  • 条目宽度：Port Map (N bits for N ports) + Age + Hit bit + Valid bit。
  • 并发：需要支持每时钟周期 1 读 (lookup) + 1 写 (learn/age) 的并行访问。
  • Ageing 引擎：后台扫描所有条目，每 tick 减 age。可用 ping-pong 双端口 RAM + 顺序扫描实现。
  • 静态/动态分离：静态条目可存于独立 TCAM 或作为 FDB 中 valid=1, static=1 的条目。

6. Frame Preemption (Clause 6.7)

Frame Preemption (802.1Qbu / 802.3br) 允许高优先级 Express 帧中断低优先级 Preemptable 帧的传输。

6.1 核心概念

概念说明
Express 帧不可抢占，必须完整发送。对应 frame_preemption_status = express 的 priority。
Preemptable 帧可被 Express 帧中断。发送中途可暂停，恢复时继续发送剩余片段。
Frame Preemption Status Table每端口每 priority 一个状态：express 或 preemptable。
holdRequestExpress 帧到达时，Preemptable MAC 收到 holdRequest，暂停当前帧。
mVerify对端能力验证过程（802.3br 定义）。

6.2 Frame Preemption Status Table

默认值：所有 priority 均为 express。管理可配置某个 priority 为 preemptable。

Priority典型用途建议状态
0-2Best Effort / Backgroundpreemptable
3-4Video / Criticalexpress 或 preemptable
5-7Voice / Control / TSNexpress
抢占粒度：Preemptable 帧被中断后，剩余部分以 mPacket ( fragment ) 形式发送， fragments 之间需要 IFG。被抢占的帧必须至少有 64 字节才能被成功抢占（包括 CRC）。

RTL Tip: Frame Preemption 模块

  • 发射侧 (MAC 客户端 → MAC)：维护 Express 和 Preemptable 两个 FIFO。Express FIFO 非空时，向 Preemptable MAC 发 holdRequest，切换发送 Express 帧。
  • Preemptable 帧被打断时，记录已发送字节数，恢复时从断点继续。
  • 接收侧 (MAC → 上层)：识别 mPacket (fragment) 并重组完整帧。需要 fragment sequence number 检测丢失的 fragment。
  • 与 Scheduled Traffic 配合：Gate 控制的 queue 若标记为 preemptable，其帧可被 Express 队列抢占。

7. TSN 子系统详细设计

7.1 Scheduled Traffic / Gate Control (8.6.8.4 / 8.6.9)

Scheduled Traffic 是 TSN 的核心特性，通过精确的时间门控实现 时间触发以太网 (TTE) 行为。

7.1.1 状态机总览

Scheduled Traffic 由三个状态机组成：

状态机功能触发条件
Cycle Timer (8.6.9.1)维护周期计时，产生 CycleStart 信号PTP 时间到达 CycleStartTime
List Execute (8.6.9.2)顺序执行 OperControlList 中的 SetGateStates 操作CycleStart 或 前一个操作完成
List Config (8.6.9.3)管理 Admin→Oper 配置切换ConfigChange 信号

7.1.2 Cycle Timer 状态机

CycleStartTime = OperBaseTime + N × OperCycleTime  (N 为使 CycleStartTime ≥ CurrentTime 的最小整数)

// 状态: INIT → (GateEnabled && 时间到) → RUNNING
// 每周期开始时设置 CycleStart = TRUE
// List Execute 收到 CycleStart 后重置 CycleStart = FALSE
精度要求：OperCycleTime 是有理数，由整数 Numerator / Denominator 表示，单位为纳秒。分母通常取 10^9，实现上可用定点数表示周期。

7.1.3 List Execute 状态机

INIT:
    OperGateStates = AdminGateStates (默认全 open 或全 closed)
    CycleStart = FALSE
    ListPointer = 0
    Timer = 0

RUNNING:
    if (CycleStart || Timer == 0):
        if (ListPointer < OperControlListLength):
            operation = OperControlList[ListPointer]
            ExecuteOperation(operation)
            ListPointer++
            Timer = operation.TimeInterval  (若为 0 则设为 1)
        else:
            // 到达列表末尾，等待下一周期
            ListPointer = 0
            Timer = 0
    else:
        Timer--

7.1.4 SetGateStates 操作

SetGateStates(GateState_bitmap, TimeInterval):
    // GateState: 8-bit, bit[n]=1 表示 queue[n] open, bit[n]=0 表示 closed
    for each queue n:
        if (GateState[n] != current_gate_state[n]):
            if (GateState[n] == 1):
                generate gate-open event for queue n
            else:
                generate gate-close event for queue n
    current_gate_state = GateState

7.1.5 List Config 状态机

ConfigChange 触发时:
    if (AdminBaseTime >= CurrentTime):
        ConfigChangeTime = AdminBaseTime
    else if (AdminBaseTime < CurrentTime && GateEnabled == FALSE):
        ConfigChangeTime = AdminBaseTime + N × AdminCycleTime
        (N 为使 ConfigChangeTime ≥ CurrentTime 的最小整数)
    else if (AdminBaseTime < CurrentTime && GateEnabled == TRUE):
        ConfigChangeError++
        ConfigChangeTime = AdminBaseTime + N × AdminCycleTime  (同上)

当 CurrentTime >= ConfigChangeTime 时:
    OperControlList = AdminControlList
    OperCycleTime = AdminCycleTime
    OperBaseTime = ConfigChangeTime
    ListPointer = 0

RTL Tip: Gate Control 硬件实现

  • Control List 存储：使用双端口 SRAM/寄存器文件存储 {GateState[7:0], TimeInterval}。Oper 列表和 Admin 列表分离，切换时整块复制。
  • 计时器：使用 PTP 时间（64-bit nanoseconds）作为时间基准。Cycle Timer 比较 CurrentTime 与 CycleStartTime。
  • 原子切换：List Config 切换发生在周期边界（ListPointer=0 时），避免在列表中间切换导致状态不一致。
  • Gate 状态输出：每队列一个 gate_open 信号，连接到 Queuing/Transmission Selection 模块。gate_close 时即使队列非空也不能发送。
  • 精度：时间戳精度应 ≤ 1μs。Gate 开关延迟应远小于 TimeInterval 的最小值。

7.3 ATS Scheduler (8.6.11)

ATS (Asynchronous Traffic Shaping, 802.1Qcr) 为每帧计算 eligibility time，实现跨桥异步整形，无需全网时间同步。

7.3.1 ATS Scheduler Clock

  • 每个 Bridge 可有一个或多个 ATS Scheduler Clock 实例。
  • 同一接收端口的所有 ATS Scheduler 实例共享同一个 clock。
  • ATS Scheduler Clock 与 Transmission Selection Clock 长期速率相同，但存在 bounded offset variation：ClockOffsetMin ≤ t_TS - t_FA ≤ ClockOffsetMax

7.3.2 ProcessFrame 伪代码

ProcessFrame(frame) { // 帧长度恢复时间 = 帧长度(bit) / CIR lengthRecoveryDuration = length(frame) / CommittedInformationRate; // 空桶到满桶时间 = CBS / CIR emptyToFullDuration = CommittedBurstSize / CommittedInformationRate; // 调度器 eligibility time = 桶空时间 + 长度恢复时间 schedulerEligibilityTime = BucketEmptyTime + lengthRecoveryDuration; // 桶满时间 = 桶空时间 + 空到满时间 bucketFullTime = BucketEmptyTime + emptyToFullDuration; // eligibility time 取三者最大 eligibilityTime = max(arrivalTime(frame), GroupEligibilityTime, schedulerEligibilityTime); // 检查是否超过最大驻留时间 if (eligibilityTime <= (arrivalTime(frame) + MaxResidenceTime/1.0e9)) { // 帧有效 GroupEligibilityTime = eligibilityTime; // 更新 BucketEmptyTime if (eligibilityTime < bucketFullTime) { BucketEmptyTime = schedulerEligibilityTime; } else { BucketEmptyTime = schedulerEligibilityTime + eligibilityTime - bucketFullTime; } // 计算 assignedEligibilityTime (考虑时钟偏移和处理延迟) assignedEligibilityTime = eligibilityTime + ClockOffsetMin + ProcessingDelayMax; AssignAndProceed(frame, assignedEligibilityTime); } else { // 帧无效 (驻留时间过长) Discard(frame); } }

7.3.3 关键状态变量

变量初始值更新规则
BucketEmptyTime< (当前时间 - CBS/CIR)见上伪代码
GroupEligibilityTime0更新为最新帧的 eligibilityTime
arrivalTime(frame)N/AATS Scheduler Clock 识别的帧到达时间

RTL Tip: ATS Scheduler 硬件实现

  • 每 Scheduler 实例：维护 BucketEmptyTime 和 GroupEligibilityTime 两个状态寄存器。
  • 运算精度：时间变量使用 64-bit 定点数（如 32.32 或 48.16），CIR/CBS 使用定点数。
  • 除法：length/CIR 和 CBS/CIR 需要除法器，可用迭代除法或查表法。
  • 并行：多流场景下，每个 stream filter 可指向不同 scheduler 实例，需支持每周期处理一帧。
  • 与队列集成：计算出的 assignedEligibilityTime 随帧存入 queue 的 metadata。Transmission Selection 比较当前时间与 eligibility time 决定是否可以出队。

7.4 Credit-Based Shaper 详细设计 (34.3)

7.4.1 参数计算

参数公式RTL 注意
idleSlope由管理配置 (bits/s)定点数存储
sendSlopeidleSlope - portTransmitRate负值，有符号
hiCreditmaxFrameSize × idleSlope / portTransmitRate预计算
loCredit-maxInterferenceSize × idleSlope / portTransmitRate负值下限

7.4.2 状态转换

State: NOT_TRANSFERRING (队列非空但 credit < 0，或被抢占)
    credit += idleSlope × delta_t
    if (credit >= 0 && queue not empty):
        transition to TRANSFERRING

State: TRANSFERRING (正在发送 SR 帧)
    credit += sendSlope × delta_t
    if (frame complete):
        if (queue empty):
            credit = max(0, credit)  // 上限截断到 0
            transition to NOT_TRANSFERRING
        else if (credit >= 0):
            continue TRANSFERRING (发送下一帧)
        else:
            transition to NOT_TRANSFERRING

Bounds: loCredit ≤ credit ≤ hiCredit (clamp 到边界)
CBS 与 Strict Priority 的交互：CBS 队列（通常 Traffic Class 0-7 中的部分队列）仅在 credit ≥ 0 时竞争发送权。若所有 CBS 队列 credit < 0，则非 CBS 队列（如 Strict Priority 队列）可获得发送机会。这保证了 SR 流量获得保证带宽的同时不饿死其他流量。

9.5 验证建议

  • FDB：测试学习、老化、移动、冲突处理、静态条目覆盖。
  • VLAN：测试 Ingress/Egress filtering、Tagged/Untagged 端口行为、VID translation。
  • Gate Control：测试周期精度、配置切换原子性、边界条件 (TimeInterval=0, GateState 全 0/全 1)。
  • CBS：测试 credit 边界 (hiCredit/loCredit)、不同 idleSlope 下的带宽保证、与非 SR 流量的共存。
  • ATS：测试 ProcessFrame 公式正确性、MaxResidenceTime 丢弃、BucketEmptyTime 更新。
  • Preemption：测试 Express 帧插入 Preemptable 帧中间、fragment 重组、错误恢复。
  • Stream Filter：测试 wildcard 匹配、优先级排序、SDU 过滤、gate 开关、计数器正确性。
总结：IEEE 802.1Q-2022 的数据平面包含 VLAN 转发、FDB 学习/查找、多级过滤（Ingress/Egress/Stream Filter）、多种调度算法（SP/CBS/ETS/ATS/Scheduled Traffic）以及帧抢占。RTL 实现建议采用模块化管线架构，每个子系统独立验证后再集成。
